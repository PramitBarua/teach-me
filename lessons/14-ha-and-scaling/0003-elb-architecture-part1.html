Elastic Load Balancer Architecture, Part 1

Lesson 03 of 12 · ~8 min

Source: Adrian Cantrill SAA-C03 · How Elastic Load Balancing Works

A load balancer's job: accept connections from customers, distribute them across registered back-end compute, and abstract customers away from that infrastructure entirely — so it can scale, fail, and heal without customers ever noticing.

What You Provision vs. What Actually Runs

When you create a load balancer, you pick one subnet in each of two or more Availability Zones. What looks like a single object is actually a set of load balancer nodes — one or more per AZ, living in the subnets you chose. A single DNS A record is created for the load balancer, and that record resolves to every node — so connections via the DNS name are distributed evenly across all of them.

Exam tip: this is why load balancers self-heal and self-scale
The nodes are managed entirely by AWS. If a node fails, it's replaced. If incoming load increases, more nodes are provisioned inside the chosen subnets automatically. You never manage this directly — you just pick the AZs (via subnets) up front.

Internet-Facing vs. Internal

This choice controls only IP addressing on the nodes — nothing else about the architecture changes:

TypeNode IP addressing
Internet-facingPublic and private IPs
InternalPrivate IPs only
Exam tip: the classic trap
An internet-facing load balancer can forward to both public and private EC2 instances — the back-end instances never need public IPs of their own. The only requirement is that load balancer nodes can reach the instances. If an exam question implies an internet-facing load balancer requires public back-end instances, that's the trap — it doesn't.

Subnet Sizing

Load balancers need at least 8 free IP addresses in each subnet they're deployed into. A /28 subnet technically provides this (16 addresses, minus 5 AWS reserves, leaves 11 free) — but AWS's own guidance recommends a /27 or larger so the load balancer has room to scale its node count as load increases.

Both answers can be "correct" depending on the question
Strictly, /28 meets the bare 8-free-IP minimum. AWS's documented recommendation is /27. If an exam question offers both a /27 and a /28 option, /27 is almost always the intended answer — but if /27 isn't offered and /28 is, treat /28 as valid too.

Multi-Tier Abstraction

Load balancers aren't only for the public-facing edge. An internal load balancer can sit between two internal tiers — e.g. a web tier talking to an application tier — abstracting each tier from the other's physical layout, and letting each tier scale independently without the other needing to know or care.

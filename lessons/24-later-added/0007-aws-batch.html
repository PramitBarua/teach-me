AWS Batch

Lesson 7 of 23 · ~6 min

Source: What is AWS Batch? · Components of AWS Batch

Some workloads aren't requests, they're jobs: render 10,000 video frames, run a genomics pipeline, reprocess last year's financial data. Each job runs for minutes or hours, starts, finishes and exits. Lambda's 15-minute limit rules it out, and building your own scheduler on EC2 is a lot of undifferentiated work. AWS Batch is a fully managed batch computing service. You submit containerized jobs, and Batch provisions the right amount of compute, queues the work, runs it and scales back down.

Four Components

Compute environment
The capacity that jobs run on: EC2 On-Demand, EC2 Spot or Fargate, orchestrated through ECS (or EKS). In a managed environment you set min, desired and max vCPUs, instance types, subnets and a Spot price threshold, and Batch scales the instances. In an unmanaged environment you run the instances yourself.
Job queue
Where submitted jobs wait. A queue has a priority and maps to one or more compute environments, for example a Spot environment first and On-Demand as a fallback.
Job definition
The blueprint for a job: container image, vCPU and memory, IAM role, environment variables, retry strategy.
Job
A unit of work submitted to a queue. Jobs can depend on other jobs, and can be array jobs that fan out into many parallel copies.

By default a queue schedules first in, first out. A fair-share scheduling policy can instead share capacity between users or workloads.

Spotting Batch
"Batch jobs", "jobs that run for hours", "hundreds of thousands of compute jobs", "scientific, financial or rendering workloads", or "the jobs can tolerate interruption, so minimize cost" all point to AWS Batch with a Spot managed compute environment. If a question insists on serverless batch with no instances at all, choose Batch on Fargate.

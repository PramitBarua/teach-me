AWS Resource Access Manager and VPC Sharing

Lesson 11 of 23 · ~6 min

Source: What is AWS RAM? · Share your VPC with other accounts

AWS RAM lets multiple AWS accounts deploy resources into the exact same VPC rather than connecting separate VPCs. This eliminates cross-VPC networking complexity and data transfer fees while maintaining strict account-level isolation

Multi-account setups solve isolation, billing and blast-radius problems, but they raise a new question: what if several accounts need the same resource? Duplicating a Transit Gateway, a set of subnets or a Route 53 Resolver rule in every account is wasteful and hard to keep consistent. AWS Resource Access Manager (RAM) lets one account share a resource with others instead.

How RAM Works

Resource share
The owner creates a resource share that lists the resources, the principals to share with, and the managed permissions that define what those principals can do.
Principals
Specific AWS accounts, organizational units, the entire Organization, or certain IAM roles and users. Once sharing with AWS Organizations is enabled, shares within the Organization need no invitation and take effect immediately.
Consumers
Shared resources appear in the consumer's account as if they were native. The owner still owns, manages and pays for the resource.
Cost
RAM itself is free.

Commonly shared resources include VPC subnets, Transit Gateways, Route 53 Resolver rules, License Manager configurations, prefix lists and more.

VPC Sharing: The Exam Favourite

With VPC sharing, a central owner account (often a networking account) creates the VPC and shares subnets with participant accounts in the same Organization.

  • Participants launch their own resources (EC2, RDS, Lambda in a VPC, load balancers) directly into the shared subnets.
  • Participants can't view, change or delete resources that belong to other participants or to the owner.
  • The owner keeps control of the network: route tables, NACLs, gateways. Participants control their own resources and security groups.
  • Everything sits in one VPC, so there's no peering to set up and no duplicated NAT gateways. That means fewer VPCs and fewer IP-range conflicts.
Spotting RAM
"Multiple accounts in an Organization must deploy into a centrally managed network, with the network team owning routing and each team owning its own instances": the answer is VPC sharing through AWS RAM. "Share one Transit Gateway with every account": also RAM. The usual distractors are VPC peering for each account (more VPCs and more connections) or giving teams IAM access to the networking account (they'd be able to touch each other's resources).

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. A networking team manages one VPC. Ten application accounts in the same Organization must launch their EC2 and RDS resources into it. The network team must keep control of routing, and teams must not affect each other's resources. What should be used?

2. In a shared VPC, account B (a participant) launches an EC2 instance into a shared subnet. What can account C, another participant, do with that instance?

3. A company has one Transit Gateway in a networking account. Every new account created in the Organization must be able to attach its VPCs to it, without anyone accepting invitations manually. What's the best approach?

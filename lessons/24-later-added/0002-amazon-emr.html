Amazon EMR

Lesson 2 of 23 · ~7 min

Source: Overview of Amazon EMR · Instance configuration best practices

Amazon EMR designed to analyze massive datasets stored directly in Amazon S3. Whenever an exam question mentions Hadoop, Spark, Hive, HBase or Presto, or "petabyte-scale processing with open-source big data frameworks", the service is Amazon EMR. EMR is a managed cluster platform. It launches and configures a fleet of EC2 instances that run these frameworks, so you don't build the Hadoop cluster yourself.

Three Node Types

Primary node
Manages the cluster: it coordinates how data and tasks are distributed and tracks their status. Every cluster has one. If it terminates, the cluster ends.
Core node
Runs tasks and stores data in HDFS on its local disks. Losing core nodes can mean losing HDFS data.
Task node
Runs tasks only and stores no HDFS data. That makes it safe to add and remove, and ideal for Spot Instances.

Where the Data Lives

HDFS on core nodes is fast but ephemeral: it disappears with the cluster. Most designs keep input and output in Amazon S3 (through EMRFS) instead. Separating storage from compute lets you terminate clusters freely without losing anything.

Long-running vs Transient Clusters

Work is submitted as steps, which run in sequence. By default, if a step fails, the remaining steps are cancelled. A long-running cluster stays up for interactive or continuous work. A transient cluster runs its steps and then auto-terminates, so you pay only while the job runs. Termination protection guards a long-running cluster against accidental shutdown.

You also choose once, at creation, between instance groups (one instance type per node type) and instance fleets (up to several instance types and purchase options per node type, which suits Spot diversification). The choice can't be changed later.

EMR vs Glue vs Athena
EMR fits existing Hadoop or Spark jobs, full control over frameworks, and very large or long-running processing. Glue fits serverless, managed ETL with no cluster to size. Athena fits ad-hoc SQL on S3 with no infrastructure at all. If a question says "minimize cost" for EMR, look for Spot task nodes, a transient cluster, and data in S3.

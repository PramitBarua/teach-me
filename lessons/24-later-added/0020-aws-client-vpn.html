AWS Client VPN

Lesson 20 of 23 · ~6 min

Source: What is AWS Client VPN?

The hybrid module covered Site-to-Site VPN, which connects a whole network (an office or data center) to a VPC through IPsec tunnels between routers. A different problem: individual employees on laptops, at home or traveling, need secure access to private resources in a VPC. That's AWS Client VPN, a managed, OpenVPN-based remote-access VPN service.

How It Fits Together

Client VPN endpoint
The managed resource that users connect to. It's highly available and scales automatically.
Target network associations
Associate the endpoint with subnets in a VPC (one per AZ for HA), or with a Transit Gateway. Once connected, users can reach that VPC, peered VPCs, on-premises networks over Direct Connect or VPN, and the internet, depending on routes.
Client CIDR
An IP range that connected users get addresses from. It must not overlap the VPC's CIDR.
Authentication
Active Directory (through Directory Service), federated SAML 2.0 (for example Okta or Entra ID), or mutual certificate authentication. These can be combined.
Authorization rules
Network access is denied by default. Rules grant groups access to specific destination CIDRs: engineering gets the app subnets, finance gets the ERP subnet.
Connection logging
Connection attempts and sessions can be logged to CloudWatch Logs.

Users connect with the AWS-provided client or any OpenVPN-compatible client. Billing is per subnet association hour plus per active connection hour.

Keywords
"Remote employees", "work from home", "laptops must securely reach private resources in the VPC", "authenticate with corporate SAML or AD": Client VPN. "Connect the office network or data center": Site-to-Site VPN or Direct Connect. A public bastion host is the classic distractor that breaks "secure, private access".

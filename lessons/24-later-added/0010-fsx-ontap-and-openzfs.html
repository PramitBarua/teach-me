FSx for NetApp ONTAP and FSx for OpenZFS

Lesson 10 of 23 · ~7 min

Source: What is FSx for ONTAP? · What is FSx for OpenZFS?

The course covered two of the four FSx file systems: FSx for Windows File Server and FSx for Lustre. Both are in scope, and so are the other two. All four follow one idea: a fully managed version of a file system you already know. That lets you move workloads to AWS without changing how applications access their files.

FSx for NetApp ONTAP: The Multi-Protocol Option

Protocols
NFS, SMB and iSCSI (plus NVMe over TCP). Linux, Windows and macOS clients can all use the same data. Block access through iSCSI is the distinctive feature.
NetApp features
Snapshots, instant zero-copy clones, SnapMirror replication (including from on-premises NetApp), FlexCache, compression and deduplication, and SnapLock for WORM compliance.
Cost and tiering
Data automatically tiers from SSD to a lower-cost capacity pool as it cools.
Resilience and identity
Single-AZ or Multi-AZ deployment, with Active Directory integration for SMB.

FSx for OpenZFS: The Linux NFS Option

Protocols
NFS (v3 and v4.x). Built for Linux workloads.
Performance
Up to about 2 million IOPS with latencies of a few hundred microseconds.
ZFS features
Snapshots, instant clones and compression.
Deployment types
Multi-AZ (HA), Single-AZ (HA) and Single-AZ (non-HA). Its main purpose is migrating ZFS or Linux NFS file servers without changing anything.

How to choose between ONTAP and OpenZFS
If the scenario mentions an existing NetApp appliance, both Windows and Linux clients sharing data, or iSCSI block storage, the answer is ONTAP. If it mentions ZFS, or a Linux NFS server that needs very high IOPS and point-in-time clones, the answer is OpenZFS. For a plain, elastic Linux NFS share with no particular file-system features, EFS is still usually the answer.

Observability: X-Ray, Managed Prometheus, Managed Grafana

Lesson 19 of 23 · ~7 min

Source: What is AWS X-Ray? · What is Amazon Managed Service for Prometheus? · What is Amazon Managed Grafana?

CloudWatch gives you metrics, logs and alarms. Observability has three classic signals: metrics, logs and traces. And many teams already standardize on open-source tools rather than CloudWatch. These three services fill the gaps: traces (X-Ray), open-source metrics (Prometheus), and open-source dashboards (Grafana).

AWS X-Ray: Distributed Tracing

In a microservice or serverless app, one user request might pass through API Gateway, three Lambda functions, SQS and DynamoDB. When it's slow or fails, which hop caused it? X-Ray follows each request end to end:

Trace and segments
A trace is one request's whole journey. Each service it passes through adds a segment (and subsegments, for example a downstream DynamoDB call) with timing and errors.
Trace map
A visual map of services showing latency and error rates, so bottlenecks are obvious at a glance.
Instrumentation
Use the X-Ray SDK or OpenTelemetry in your code. Enable tracing with a checkbox on Lambda, API Gateway and Elastic Beanstalk. On EC2 and ECS, a daemon or agent forwards trace data.

Amazon Managed Service for Prometheus

A serverless, Prometheus-compatible metrics service. You query with PromQL just as you would against self-hosted Prometheus, but AWS handles scaling, availability and storage. Data is replicated across three AZs, with a default retention of 150 days. It's typically used for container metrics from EKS, ECS or self-managed Kubernetes. Use it when a team already uses Prometheus and doesn't want to run Prometheus servers anymore.

Amazon Managed Grafana

Fully managed Grafana workspaces for dashboards and alerts over many data sources: CloudWatch, Managed Prometheus, X-Ray, OpenSearch, Timestream, Athena, Redshift and third-party tools. Users sign in through IAM Identity Center or SAML. Pricing is per active user, with no servers to patch.

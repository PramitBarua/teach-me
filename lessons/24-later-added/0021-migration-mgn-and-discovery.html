Application Migration Service and Application Discovery Service

Lesson 21 of 23 · ~6 min

Source: What is AWS Application Migration Service? · Application Discovery Service availability change

The hybrid module covered moving data: DataSync, Snowball, Storage Gateway and Transfer Family. Moving whole servers needs different tools. A large migration usually goes discover (what do we have, and what talks to what?), then plan, then migrate. The exam names a service for the first and last of those steps.

AWS Application Migration Service (MGN): Lift and Shift

MGN is AWS's primary service for rehosting ("lift and shift") physical, virtual or other-cloud servers to EC2, without changing the applications. The documentation now brands it as part of the AWS Transform family, and you'll see it as "MGN" either way.

  1. Install the replication agent on each source server.
  2. MGN performs continuous, block-level replication of the disks into a low-cost staging area subnet in your AWS account. The source keeps running normally.
  3. Launch test instances from the replicated data to validate, as often as you like, with no impact on the source.
  4. At cutover, launch the production instances. Because replication is continuous, the cutover window is minutes. Servers can be grouped into waves for large migrations.

AWS Application Discovery Service: Inventory and Dependencies

Discovery Service collected data about on-premises servers before a migration: configuration, utilization (for rightsizing) and network dependencies between servers. It used either an agentless collector (for VMware VMs) or an agent on each server (for deeper process and network data).

Closed to new customers
As of 7 November 2025, Application Discovery Service is no longer open to new customers. Existing customers can continue to use it, and AWS directs new discovery work to AWS Transform. It's still named in the exam guide, so know its purpose: discover servers and their dependencies to plan a migration.
NeedService
Inventory on-premises servers and map dependenciesApplication Discovery Service (or AWS Transform)

Migrate a database engine, or between enginesDatabase Migration Service (DMS)
Move files and objectsDataSync, Snow Family, Transfer Family
Keywords
"Lift and shift", "rehost", "migrate servers with minimal downtime and no application changes", "continuous replication then cutover": MGN. "Identify dependencies and utilization of on-premises servers before migrating": Application Discovery Service. If the question is about a database engine, the answer is DMS, not MGN.

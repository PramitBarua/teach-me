Amazon Managed Streaming for Apache Kafka (MSK)

Lesson 13 of 23 · ~6 min

Source: What is Amazon MSK? · Amazon MSK product page

Kinesis Data Streams is AWS's own streaming service. But many companies already run Apache Kafka, the open-source event streaming platform, with producers, consumers, connectors and tooling all built for Kafka APIs. Moving them to Kinesis would mean rewriting code. Amazon MSK runs Kafka as a managed service instead. It uses open-source Kafka versions, so existing applications and tools work without code changes.

What AWS Manages

  • Provisioning broker nodes spread across multiple Availability Zones in your VPC, at least one broker per AZ you choose.
  • Running the cluster metadata layer (ZooKeeper or, in newer versions, KRaft).
  • Detecting and automatically replacing failed brokers, plus patching and version upgrades.
  • Encryption in transit and at rest, IAM access control, and integration with CloudWatch.

Flavours

MSK Provisioned
You choose the broker count, instance size and storage. Standard brokers give the most control. Express brokers trade some of that control for higher throughput, faster scaling and less storage to manage.
MSK Serverless
No brokers to size. Capacity scales automatically and you pay for what you use.
MSK Connect
Runs Kafka Connect connectors as a managed service, for example to stream data into S3 or from a database.
MSK Replicator
Replicates data between MSK clusters, including across Regions.

The deciding word is "Kafka"
If a scenario mentions an existing Kafka cluster, Kafka clients, or "migrate a streaming platform with minimal code changes", the answer is MSK. If it says "reduce operational overhead" as well, prefer MSK Serverless. If nothing mentions Kafka, Kinesis Data Streams or Amazon Data Firehose is usually the expected answer.

Governance and Operations Round-up

Lesson 22 of 23 · ~8 min

Source: AWS Health · License Manager · AWS Artifact · Well-Architected Tool · The six pillars · AWS Auto Scaling plans

Five in-scope services that each fit in one paragraph. They rarely appear as the main topic of a question, but they often show up as the correct option for a narrowly worded requirement. Learn the one-line purpose and the trigger phrase for each.

AWS Health Dashboard

Shows account-specific AWS events: service issues affecting your resources, scheduled maintenance (for example, an EC2 instance retirement), and account notifications. The public service health page shows only general status. Health events can be sent to EventBridge (free) to automate responses. Organization-wide views and the AWS Health API need a Business-level Support plan or higher.

AWS License Manager

Manages software licenses (Microsoft, Oracle, SAP and others) for BYOL. You define license configurations with counting rules (vCPUs, cores, sockets or instances) and attach them to AMIs or launch templates. Hard limits block launches that would exceed your entitlement. Soft limits just alert. It works across accounts with Organizations and helps manage Dedicated Hosts for licenses tied to physical cores.

AWS Artifact

A self-service portal for AWS's own compliance reports (SOC 1/2/3, PCI DSS, ISO certifications and more) and for reviewing and accepting agreements such as the Business Associate Addendum (BAA) for HIPAA. Auditors ask "prove AWS is compliant"; Artifact is where you download the evidence. It's free.

AWS Well-Architected Tool

A console tool that reviews a workload against the Well-Architected Framework's six pillars: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization and Sustainability. You answer questions, it flags high-risk issues (HRIs) and produces an improvement plan. You save milestones to track progress, and you can apply lenses (for example Serverless, or your own custom lens).

AWS Auto Scaling (Scaling Plans)

"AWS Auto Scaling" is a separate service from EC2 Auto Scaling. It creates scaling plans that configure scaling for several resource types together: EC2 Auto Scaling groups, ECS services, DynamoDB tables and indexes, Aurora replicas and Spot Fleets. You pick a strategy that optimizes for availability, cost or a balance. It can use dynamic and predictive scaling. AWS now recommends configuring predictive scaling policies directly on Auto Scaling groups for EC2, but the scaling-plans service remains in scope.

Common traps
Artifact holds AWS's compliance evidence, not yours. Your own resource compliance is AWS Config or Security Hub. The Health Dashboard is about AWS events affecting you, not your application's health metrics, which belong to CloudWatch.

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. An external auditor asks for AWS's latest SOC 2 report to confirm that the underlying cloud infrastructure meets the standard. Where does the company get it?

2. A company owns 64 core licenses for a commercial database. It must make it impossible for teams to launch EC2 instances that would push usage past 64 cores. What should be used?

3. Operations wants an automatic ticket whenever AWS schedules maintenance (such as an instance retirement) that affects one of the company's own EC2 instances. What's the best approach?

4. A team wants to review its production workload against AWS best practices across all six pillars, get a prioritized list of high-risk issues, and track progress at each quarterly review. What fits?

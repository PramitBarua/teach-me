Systems Manager: Session Manager, Run Command, Patch Manager, Automation

Lesson 9 of 23 · ~8 min

Source: What is AWS Systems Manager? · Session Manager · Run Command · Patch Manager · Automation

The course used Systems Manager mostly for Parameter Store. But the exam leans on four other Systems Manager tools for operating fleets of servers securely. They all share one prerequisite. A machine becomes a managed node when it runs the SSM Agent and has permission to talk to Systems Manager (on EC2, through an instance profile role). Managed nodes can be EC2 instances, on-premises servers or VMs in other clouds.

Session Manager: Shell Access Without SSH

Session Manager gives an interactive shell (or PowerShell) on a managed node through the console or CLI. It needs no inbound ports, no bastion host and no SSH keys:

  • Who may start a session is controlled by IAM policies.
  • Session activity can be logged to S3 and CloudWatch Logs, and the API calls appear in CloudTrail.
  • Instances in private subnets with no internet access work too, using interface VPC endpoints (PrivateLink) for Systems Manager.
  • It also supports port forwarding, for example to reach a private database from a laptop.

Run Command: One Command, Thousands of Nodes

Run Command executes a Systems Manager document (a shell script, a PowerShell script, or an AWS-provided action) across many managed nodes at once. Nodes can be selected by tag. You control concurrency and error thresholds, again with no SSH. Output can go to S3 or CloudWatch Logs.

Patch Manager: Patching at Scale

Patch baseline
The rules for which patches are approved: auto-approval rules (for example, critical security patches 7 days after release), plus explicit approved and rejected lists.
Scan vs Scan and install
Report compliance only, or report and then apply the missing patches.
When it runs
Patch policies set up through Quick Setup, across accounts and Regions in an Organization (AWS's recommended approach). Or a maintenance window that you schedule, or an on-demand Patch now.

Patch Manager handles OS and application patches. It does not do major OS version upgrades.

Automation: Runbooks

Automation runs runbooks: multi-step documents for common maintenance and remediation tasks. Examples are restarting instances, creating a patched "golden" AMI, or remediating a non-compliant resource. A runbook can be triggered by an EventBridge rule or an AWS Config remediation, and can run across accounts and Regions with rate controls.

Pick the Systems Manager tool
"Secure shell access with no open port 22, no bastion, and every session logged": Session Manager. "Run a script on 500 instances by tag": Run Command. "Keep the fleet patched on a schedule and report compliance": Patch Manager (with maintenance windows or patch policies). "Automatically remediate or perform a multi-step operational task": Automation runbooks.

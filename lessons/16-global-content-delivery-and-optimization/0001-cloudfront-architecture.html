Global Content Delivery & Optimization

CloudFront Architecture

Lesson 01 of 10 · ~8 min

Source: Adrian Cantrill SAA-C03 · What Is Amazon CloudFront?

Serve content from a single Region and every distant customer pays for it in latency and transfer speed — data has to physically travel further, every single time it's requested. CloudFront is AWS's content delivery network (CDN): it fixes this by caching content on infrastructure physically close to customers, worldwide.

Core Vocabulary

Origin
Where your content actually lives — either an S3 bucket or a custom origin (anything else with a web server and a publicly routable IPv4 address). A single CloudFront configuration can use one or more origins.
Distribution
The unit of configuration in CloudFront. You configure a distribution, then deploy it out to the CloudFront network. Nearly everything is configured here, directly or indirectly.
Edge location
Small, numerous, globally-distributed points of presence — 200+ at last count — where content is actually cached. Mostly storage, with a little compute bolted on for specific features. You cannot deploy EC2 instances to an edge location.
Regional edge cache
Bigger and less numerous than edge locations. They cache less-frequently-accessed content that still benefits from being closer to customers than the origin, and sit architecturally between edge locations and the origin.

How a Request Actually Flows

A distribution gets a unique domain name ending in cloudfront.net (you can also attach your own custom domain). When a customer requests an object:

  1. Their request hits their nearest edge location.
  2. Cache hit — the object is already cached there → returned immediately. Best case: fast, low latency.
  3. Cache miss — not cached locally → the edge location checks its regional edge cache.
  4. Still missing → an origin fetch retrieves it from the origin, populating both the regional cache and the local edge location on the way back.
Exam tip: read-only caching
CloudFront is for download-style operations only — there is no write caching. Any upload goes directly to the origin, never through the CloudFront cache layer. This distinction shows up directly in exam questions testing whether you understand CloudFront's read/write scope.

Distributions Don't Directly Hold Configuration — Behaviors Do

It's tempting to assume origins attach directly to a distribution. They don't. A distribution contains one or more behaviors, and it's the behavior that points at an origin. Every distribution starts with one default behavior (a wildcard * pattern matching everything), but you can add more specific behaviors — e.g. a path pattern of img/* — which take priority over the default when matched.

Why this distinction matters
Nearly every setting you might assume lives "on the distribution" — TTL, origin selection, public vs. private access — actually lives on a behavior. Since a distribution can have many behaviors, different paths within the same distribution can have entirely different configurations. This architecture is the foundation for everything covered in the rest of this module.

CloudFront also integrates with ACM (AWS Certificate Manager) for SSL/TLS — covered in depth two lessons ahead.

CloudFront Behaviors: What Lives Where

Lesson 02 of 10 · ~7 min

Source: Adrian Cantrill SAA-C03 · Cache Behavior Settings

The previous lesson established that behaviors, not distributions, hold most of the real configuration. This lesson draws the exact line: what's set once, at the distribution level, versus what's set per-behavior and can differ across paths within the same distribution.

Set on the Distribution

SettingWhat it controls
Price classWhich edge locations the distribution deploys to — all of them (best performance), or a cheaper subset (e.g. US/Canada/Europe only)
WAF associationAttaching a Web Application Firewall Web ACL to the whole distribution
Alternate domain namesCustom domains beyond the default *.cloudfront.net name
SSL certificate type & security policyWhich certificate and TLS security policy the distribution uses
Supported HTTP versions, logging on/offDistribution-wide protocol and logging settings
Price class is a real trade-off
Restricting a distribution to fewer edge locations genuinely reduces cost, but at the cost of worse performance for customers outside those regions. It's a legitimate answer to "how do I reduce CloudFront cost" questions — just know it trades away global performance to do it.

Set on a Behavior (and Can Differ Per-Path)

SettingWhat it controls
Origin / origin groupWhich origin this path pattern is served from
Viewer protocol policyHTTP allowed, HTTP→HTTPS redirect, or HTTPS-only, between viewer and edge
Allowed HTTP methodsWhich methods (GET, POST, etc.) this path accepts
Cache settings (legacy or cache/origin-request policies)What's used as the cache key — headers, query strings, cookies
Min/Max/Default TTLCovered in full next lesson
Restrict viewer accessWhether this specific behavior requires signed URLs/cookies (private) — covered in Lessons 07–08
Field-level encryption, compression, Lambda@Edge associationsAll per-behavior
Exam tip: the two facts to memorize cold
All caching controls are behavior-level, and restrict viewer access (private content) is behavior-level — meaning one distribution can mix public and private paths freely. These two facts alone resolve a large share of CloudFront scenario questions about "can I have different X for different paths."

Trusted Key Groups vs. Trusted Signers

When restricting a behavior, you specify a trusted authorization source: trusted key groups (current, recommended) or trusted signers (legacy). Seeing either term in an exam question is a signal that a private/restricted behavior is involved — covered fully in Lesson 08.

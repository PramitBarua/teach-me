CloudFront Origin Types and Architecture

Lesson 06 of 10 · ~7 min

Source: Adrian Cantrill SAA-C03 · Origin Settings

CloudFront recognizes a few categories of origin: S3 buckets, AWS Elemental MediaPackage/MediaStore endpoints (out of scope here), and everything else — any ordinary web server, called a custom origin.

An S3 bucket can be either type
A plain S3 bucket used as an origin is an S3 origin. But enable static website hosting on that same bucket and point CloudFront at the website endpoint, and CloudFront now treats it as a custom origin — with a completely different, more limited feature set. The feature you get depends entirely on how you point at the bucket, not just that it's S3 underneath.

S3 Origins: Simplest to Integrate

ConfigurableDetail
Origin pathRestrict to a sub-path within the bucket instead of the top level
Origin accessRestrict the bucket to CloudFront-only access — via OAC (current) or OAI (legacy) — covered next lesson
Protocol matchingViewer protocol and origin protocol are always matched — no independent choice
Custom headersPass through to the origin, same as custom origins

Custom Origins: More Configuration, More Control

Anything that isn't a plain S3 origin gets a richer, more granular set of options:

ConfigurableDetail
Minimum origin SSL protocolThe floor TLS version CloudFront will use talking to your origin — pick the newest your origin supports for maximum security
Origin protocol policyHTTP-only, HTTPS-only, or match viewer (independently choosable, unlike S3)
HTTP/HTTPS portCustom origins can bind services to non-standard ports; S3 has no concept of configurable ports
Custom headersSame as S3 — also doubles as a security mechanism (next lesson)
Exam tip: custom ports/protocols → custom origin
Any exam question mentioning configurable ports, an independently-set origin protocol policy, or a minimum origin SSL protocol is describing a custom origin — S3 origins don't expose any of these, since S3 handles the underlying connection natively.

Origin Groups: Resilience Across Origins

With two or more origins configured on a distribution, you can combine them into an origin group and point a behavior at the group instead of a single origin — giving that behavior automatic resilience (failover) across multiple origins, all from within a single distribution.

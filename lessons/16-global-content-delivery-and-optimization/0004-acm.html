AWS Certificate Manager (ACM)

Lesson 04 of 10 · ~7 min

Source: Adrian Cantrill SAA-C03 · What Is AWS Certificate Manager?

ACM generates, imports, stores, and deploys SSL/TLS certificates — the mechanism behind HTTPS's server identity verification and in-transit encryption. It underpins nearly every AWS certification and shows up constantly in exam questions diagnosing "why can't this service use this certificate."

Public vs. Private, Generate vs. Import

ACM can act as a public certificate authority (issuing certificates trusted by public browsers/devices) or a private one (for internal use — clients must be explicitly configured to trust it).

Exam tip: who's responsible for renewal
If ACM generates a certificate for you, it handles automatic renewal — no ongoing action needed. If you import a certificate from an external source, you're responsible for renewing it (with that external source) and re-importing the new one. This distinction is tested directly and often.

Only Certain Services Can Use ACM

Certificates are stored encrypted and only ever deployed to ACM-integrated services — in practice, this mainly means CloudFront and load balancers.

EC2 is explicitly not supported
You cannot use ACM certificates directly with EC2. Since EC2 is self-managed compute (you have root access), AWS has no way to secure the certificate's transfer and storage the way it can for a fully-managed service. If you need a certificate on an EC2 instance, it has to be installed manually. This is one of the most reliably-tested ACM facts on the exam.

ACM Is Regional — With One Special Case

ACM is a regional service: a certificate generated or imported in one Region is locked to that Region and cannot be used cross-Region. To use a certificate on a load balancer in ap-southeast-2, that certificate must exist in ACM in ap-southeast-2 — no exceptions for regional services.

Exam tip: CloudFront's one exception
CloudFront is global, but from ACM's perspective, treat a CloudFront distribution as if it lives in us-east-1 (N. Virginia). Any certificate used by a CloudFront distribution must be requested or imported in us-east-1, regardless of where your other infrastructure or customers are. Generate it in any other Region, and CloudFront simply can't use it. This single fact — "CloudFront certificates: always us-east-1" — is worth memorizing verbatim; it comes up repeatedly.

Once deployed to a supported service, the certificate establishes trust between customers and that service — a load balancer in a Region, or a CloudFront distribution's edge locations worldwide (the distribution pushes the certificate out to every edge location it uses, regardless of their physical Region).

S3 doesn't use ACM at all
S3 handles its own certificate management when acting as a CloudFront origin — you never apply an ACM certificate to an S3 bucket, and you can't change the certificate S3 itself presents.

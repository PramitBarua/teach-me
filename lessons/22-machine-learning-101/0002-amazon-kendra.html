Amazon Kendra

Lesson 02 of 11 · ~5 min

Source: Adrian Cantrill SAA-C03 · What is Amazon Kendra? · Amazon Kendra availability change

Amazon Kendra is an intelligent enterprise search service. The design goal is that querying it should feel like talking to a human expert on the subject, rather than typing keywords into a search box and hoping for the best.

Current status: closing to new customers
The exam content here (and the underlying course video) treats Kendra as a standalone product you'd actively choose for a new enterprise search build. As of this writing, AWS has announced that Amazon Kendra will no longer be open to new customers starting July 30, 2026 — existing customers keep full support, but AWS now points new search workloads toward Amazon Bedrock Knowledge Bases instead. (Amazon Q Business, which is built on top of Kendra, is following the same path, closing to new customers July 31, 2026, with Amazon Quick as its recommended successor.) For the SAA-C03 exam, the concepts on this page — index, data source, query types — are still exactly what's tested; just be aware that "which service should a new customer pick today" and "what does the exam expect you to know" are now two different questions.

Three Kinds of Questions

Kendra is built to handle a spread of question styles:

  • Factoid questions — simple who/what/where questions, like "who wrote this book" or "where is this place."
  • Descriptive questions — open-ended questions where the answer is a sentence or passage, like "how do I get my cat to stop being a jerk?"
  • Keyword questions that are genuinely ambiguous — the classic example is "what time is the keynote address?" where "address" could mean a postal address or a speech. Kendra has to infer intent, not just match keywords.

Index and Data Source

Two concepts anchor how Kendra works:

Index
The searchable, organized block of data that Kendra actually queries against.
Data source
The original location where the data lives — an S3 bucket, Confluence, Google Workspace, RDS, OneDrive, a web crawler, WorkDocs, FSx, and many more. Kendra syncs a data source into the index on a schedule, keeping the index current.

Documents indexed this way can be structured (like FAQs) or unstructured (HTML, PDF, plain text).

Backend service, not an end-user tool
Kendra is a backend service: you build search into an application and consume Kendra through its API. It's not something end users open directly in the console. It integrates with IAM and IAM Identity Center (formerly AWS SSO) for security. If a question describes adding search within an application backed by varied enterprise data sources — not a general-purpose keyword search box — that's the Kendra signal.

Amazon Lex

Lesson 03 of 11 · ~5 min

Source: Adrian Cantrill SAA-C03 · What is Amazon Lex V2? · Slots — Amazon Lex

Amazon Lex is the product behind interactive chatbots and voice assistants — it's literally what powers Alexa's voice interactions. Like the other services in this module, it's a backend service: you don't use Lex directly as an end user, you build it into an application to add conversational capability.

Two Core Capabilities

Automatic Speech Recognition (ASR)
Speech-to-text. Sounds simple, but doing it well — reliably, in noisy or varied conditions — is genuinely hard.
Natural Language Understanding (NLU)
Working out what the user actually wants, their intent, from what they said or typed — and chaining related statements together. If someone says "I want to order a large pepperoni pizza" and then follows up with "make that an extra large," Lex has to recognize that the second statement modifies the first, rather than treating it as an unrelated new request.
The keyword heuristic
If an exam scenario mentions building a chatbot, a voice-interactive assistant, or an Alexa-style voice interface, default to Lex.

Key Concepts

  • Bot — the interactive conversational entity itself, capable of one or more languages.
  • Intent — the action a user wants to perform, such as "order pizza."
  • Utterances — different sample phrasings of the same intent, like "can I order," "I want to order," or "give me a."
  • Slots — parameters an intent needs to be fulfilled, such as pizza size or crust type.
  • Fulfillment — how the intent actually gets carried out once understood, typically via a Lambda function.

Lex scales automatically, uses pay-as-you-go pricing, and integrates well with Amazon Connect and event-driven or serverless architectures generally — Lambda fulfillment being the clearest example of that fit.

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. A team wants to build a voice-driven ordering assistant similar in style to Alexa, understanding spoken requests and follow-up clarifications. Which service is the fit?

2. A user tells a pizza-ordering bot "I want to order a pizza," then follows with "make that a large." What Lex capability lets it connect the second statement to the first?

3. A bot's "order pizza" intent needs to know the pizza size and crust type before it can be completed. What Lex concept represents these required pieces of information?

Amazon Textract

Lesson 06 of 11 · ~6 min

Source: Adrian Cantrill SAA-C03 · Analyzing Identity Documents — Amazon Textract · Analyzing Invoices and Receipts — Amazon Textract

Amazon Textract detects and analyzes text contained in documents. Input formats are JPEG, PNG, PDF, or TIFF. Output is the extracted text, the structure around that text, and analysis performed on it.

Synchronous vs. Asynchronous

For a normal-sized document, Textract runs synchronously — you get results back almost immediately. For a large document, think a hundred-page PDF, Textract processes it asynchronously: you submit a job and wait for it to complete. Pricing is pay-per-use, with custom pricing available at large volume.

More Than Just Text: Relationships and Tables

Textract doesn't just extract raw text — it understands the relationships between elements. On a receipt, it can connect a line item to its price and to the tax associated with it. It also extracts full table structure, not just the text sitting inside a table, so a complex, irregularly formatted table can still be reconstructed as rows and columns with its data intact.

Specialized Analysis Modes

Generic documents
Names, addresses, dates, and other general fields.
Expense analysis
Purpose-built for receipts and invoices — vendor information, line items, dates, and totals.
Identity document analysis
Extracts fields from documents like driver's licenses and passports, and abstracts equivalent fields into a common, normalized name. A driver's license number and a passport number are different fields on different documents, but Textract maps both into the same normalized Document ID field.
Why normalized identity fields matter
Because identity document analysis abstracts differently-named fields into one consistent schema, downstream systems can use a single data structure regardless of which document type a customer submitted. This is exactly what a know-your-customer (KYC) or anti-money-laundering (AML) identity-verification workflow needs. If an exam question describes verifying identity documents with a normalized field across document types, that's Textract's identity analysis feature specifically.

What the Console Demo Shows

The Textract console's sample walkthrough demonstrates the same underlying capability across several document types: a vaccination card (mixed structured fields and a handwritten table), a pay stub (dense key-value data), a loan application (large blocks of text), a receipt (via the expense analysis mode, extracting vendor info and line items), and both a driver's license and a passport (via identity document analysis, with both mapping to the same normalized Document ID field). The conceptual point across all of these: Textract extracts fields accurately even from slanted, differently sized, or messily formatted source data, and the same capability is available through the API for use inside an application — not just as an interactive console tool.

Console or API

Textract can be used from the console UI or from the API, and it integrates with applications you build as well as with other AWS products, including other machine learning services.

      Scenario 1

      An IAM role in Account B needs read access to a bucket in Account A. The role's identity policy in Account B already grants s3:GetObject on the bucket's ARN. Requests still fail with Access Denied. What else is required?

      • A. Nothing more — the identity policy alone is sufficient once it names the correct ARN
      • B. An ACL on every individual object granting the Account B role's canonical ID read rights
      • C. A bucket policy in Account A that also explicitly allows the Account B role
      • D. A CloudTrail data event rule in Account A permitting cross-account API calls

      Topic: S3 resource policies and ACLs

      Correct answer: C

      • A. Wrong — for cross-account access, the identity's own policy is necessary but not sufficient; the resource owner (Account A) must also explicitly allow the foreign principal via its bucket policy.
      • B. Wrong — per-object ACLs could technically work, but they're the legacy, unmanageable mechanism for this; a single bucket policy statement covering the whole bucket is the modern, recommended fix, not per-object ACL grants.
      • C. Correct — cross-account access needs both sides to allow: the requester's identity policy in Account B, and a bucket policy in Account A naming the Account B role as an allowed principal. Only the second piece is missing here.
      • D. Wrong — CloudTrail records API activity for auditing; it has no role in granting or denying access and cannot substitute for a bucket policy.

      Scenario 2

      A new bucket was created this year and a partner team tries to grant another AWS account read access by setting an object ACL, the same way it worked on an older bucket two years ago. The grant has no effect at all. Why?

      • A. ACLs were fully removed from S3 and no longer exist as an API operation
      • B. New buckets default to Bucket owner enforced, which disables ACLs entirely
      • C. ACL grants only apply to same-account principals, never to other AWS accounts
      • D. The object must be re-uploaded before any ACL change can take effect

      Topic: S3 resource policies and ACLs

      Correct answer: B

      • A. Wrong — ACLs still exist as an API concept and can still be enabled; they simply default to disabled for new buckets under the Bucket owner enforced setting.
      • B. Correct — since 2023, new buckets default to Object Ownership: Bucket owner enforced, which disables ACLs entirely. Every ACL grant is silently ignored in favor of bucket/identity policies. This is exactly the trap in this scenario.
      • C. Wrong — ACLs historically could grant access to other accounts (that's part of why they were used); the issue here isn't a same-account restriction, it's that ACLs are disabled on this bucket altogether.
      • D. Wrong — ACL changes on an existing object take effect immediately when ACLs are active; re-uploading the object is not required and wouldn't fix a disabled-ACL bucket anyway.

      Scenario 3

      A single IAM role needs read access to 40 different S3 buckets owned by the same team, all created going forward as well as already existing. What is the most maintainable way to grant this?

      • A. Add a matching statement to each of the 40 buckets' bucket policies
      • B. Attach one identity policy to the role using a wildcard bucket ARN pattern
      • C. Create 40 separate ACL grants, one per bucket, naming the role's account
      • D. Create a new IAM role per bucket, each scoped to just that one bucket

      Topic: S3 resource policies and ACLs

      Correct answer: B

      • A. Wrong — this technically works but means maintaining 40 separate policy edits, and any newly created bucket needs its own manual statement added; it's the wrong tool when one identity needs access to many resources.
      • B. Correct — when one identity needs access to many buckets, an identity policy is the efficient approach: attach it once to the role, and a wildcard ARN pattern automatically covers future buckets matching the pattern too.
      • C. Wrong — ACLs are the legacy, per-object/per-bucket mechanism; managing 40 individual ACL grants is even less scalable than bucket policies and doesn't automatically cover new buckets.
      • D. Wrong — creating 40 roles for one team's access need multiplies IAM management overhead for no benefit; a single role with one policy is far simpler.

      Scenario 4

      A platform team maintains one shared bucket used by finance, HR, and engineering. Each team needs different permissions, and the platform team wants all of this access control visible and managed in one artifact tied to the bucket itself, not scattered across dozens of IAM policies. What structure achieves this?

      • A. One bucket policy containing a separate statement per team, each scoped to that team's principals
      • B. Three separate bucket policies, one attached per team's access needs
      • C. One IAM policy per team attached to a shared cross-team IAM group
      • D. A default bucket ACL updated manually each time a team's access changes

      Topic: S3 resource policies and ACLs

      Correct answer: A

      • A. Correct — a bucket can have exactly one bucket policy, but that policy can contain multiple statements. Giving each team its own statement, scoped to its principals, keeps everything centralized in the single resource-based policy attached to the bucket.
      • B. Wrong — a bucket can only ever have one bucket policy at a time; a second policy attachment would simply overwrite the first, not add to it.
      • C. Wrong — this moves management into IAM rather than keeping it centralized on the bucket resource itself, which is the opposite of what the platform team wants.
      • D. Wrong — ACLs grant coarse read/write permissions per grantee and don't support the kind of fine-grained, per-team statement structure that a bucket policy's multiple statements provide.

      Scenario 5

      A public documentation bucket needs to allow anyone on the internet to download files with no AWS credentials at all. The account has S3 Block Public Access enabled at the account level, and the team adds a bucket policy with Principal: "*" and Allow GetObject. Downloads still fail for anonymous users. What's the missing piece?

      • A. Block Public Access settings must also be disabled for the relevant public-access checks to take effect
      • B. An identity policy must additionally be attached to a special "anonymous" IAM user
      • C. The bucket policy's Principal field must instead reference the AWS account's root ARN
      • D. A CloudFront distribution must be placed in front of the bucket before public policies apply

      Topic: S3 resource policies and ACLs

      Correct answer: A

      • A. Correct — Block Public Access acts as an account/bucket-level override that can block public bucket policies from taking effect regardless of what the policy says. The relevant BPA settings (blocking public bucket policies) must be turned off for a genuinely public policy to work.
      • B. Wrong — there is no "anonymous" IAM user concept in AWS; anonymous requests carry no identity, so no identity policy is ever relevant to them.
      • C. Wrong — the root ARN is a specific account principal, the opposite of public; a policy scoped to root would restrict access rather than open it to anonymous internet users.
      • D. Wrong — CloudFront is an optional caching/CDN layer, not a prerequisite for a bucket policy's public grant to function; a bucket policy alone can serve public objects directly once Block Public Access allows it.

      Scenario 6

      A visitor navigates to https://example-bucket.s3-website-us-east-1.amazonaws.com/docs/ on a bucket configured with static website hosting where the index document is set to index.html. An object exists at key docs/index.html. What is returned?

      • A. A 404 error, since S3 static hosting cannot serve documents under a sub-path
      • B. The configured error document, since no exact key named docs/ exists
      • C. The object at key docs/index.html, since the index document applies per directory-like prefix
      • D. An auto-generated listing of every object whose key begins with the docs/ prefix

      Topic: S3 static website hosting

      Correct answer: C

      • A. Wrong — static hosting works with any key prefix that looks like a folder path; sub-paths are fully supported, not rejected.
      • B. Wrong — the error document is only returned when no matching object can be resolved at all; here, the index document rule successfully resolves to docs/index.html, which does exist.
      • C. Correct — the index document setting applies to any request ending in /, appending the index filename to that prefix. A request for docs/ resolves to the object at key docs/index.html.
      • D. Wrong — S3 static website hosting does not generate directory listings; it always resolves to a specific index document object, never a listing page.

      Scenario 7

      A team hosts their entire marketing site on S3 static website hosting with a custom domain via Route 53 alias records. Legal now requires the site to be served exclusively over HTTPS. The team wants to keep the S3 static hosting endpoint as the actual content source. What must they add?

      • A. Nothing — the S3 website endpoint already serves HTTPS by default on all buckets
      • B. Enable versioning on the bucket, which upgrades the endpoint's protocol to HTTPS
      • C. A CloudFront distribution in front of the S3 website endpoint, serving HTTPS to visitors
      • D. Switch the bucket policy's Principal to require aws:SecureTransport only

      Topic: S3 static website hosting

      Correct answer: C

      • A. Wrong — the native S3 website hosting endpoint only serves plain HTTP; it has no built-in HTTPS support at all, which is the whole reason this requirement can't be met by the endpoint alone.
      • B. Wrong — versioning controls object history and has nothing to do with the protocol the website endpoint serves traffic over.
      • C. Correct — since the S3 website endpoint itself cannot terminate HTTPS, the standard pattern is to put CloudFront in front of it, letting CloudFront handle the TLS certificate and HTTPS termination while S3 remains the origin content source.
      • D. Wrong — a bucket policy condition can require secure transport for API calls, but the S3 website endpoint doesn't consult bucket policy conditions the same way, and this wouldn't add HTTPS capability to an endpoint that fundamentally doesn't support it.

      Scenario 8

      An application's EC2 fleet is under heavy load from serving product images, CSS, and JavaScript files directly to browsers alongside dynamic page rendering. The team wants to reduce EC2 load without changing any application logic. What is the standard fix?

      • A. Move static assets to an S3 bucket with static website hosting and update asset URLs
      • B. Enable MFA Delete on the EC2 instance's attached EBS volume for extra protection
      • C. Enable multipart upload on the EC2 fleet's outbound HTTP responses to browsers
      • D. Increase the EC2 instance type size to handle both static and dynamic load together

      Topic: S3 static website hosting

      Correct answer: A

      • A. Correct — this is the offloading use case: move static assets (images, CSS, JS) to S3 so browsers fetch them directly from S3 instead of the app servers, freeing EC2 capacity for dynamic rendering only.
      • B. Wrong — MFA Delete is an S3 versioning protection feature; it has no relationship to EBS volumes and does nothing to reduce EC2 request load.
      • C. Wrong — multipart upload is an S3 object-upload mechanism for large files; it isn't something EC2 applies to outbound HTTP responses and wouldn't reduce load in this scenario.
      • D. Wrong — this works, but it means paying for larger continuous compute capacity just to keep serving static files EC2 doesn't need to serve at all — an expensive workaround for a problem offloading solves architecturally.

      Scenario 9

      A visitor on an S3-hosted static site clicks a link to a page that was deleted last week. The bucket has static website hosting enabled with an error document configured. What does the visitor see?

      • A. A generic AWS XML error response, since S3 only returns custom pages for successful requests
      • B. The site's configured error document, returned because the requested key doesn't exist
      • C. The configured index document, since S3 falls back to the homepage on any missing key
      • D. A silent empty response with HTTP 204, since S3 does not surface 404s to browsers

      Topic: S3 static website hosting

      Correct answer: B

      • A. Wrong — that's the behavior of the raw S3 API/REST endpoint without website hosting enabled; the website hosting configuration specifically exists to replace that generic XML with a custom error document.
      • B. Correct — the error document is returned whenever a requested key doesn't exist or a server error occurs. A deleted page falls into exactly this case, so the visitor sees the custom error page instead of a raw XML error.
      • C. Wrong — S3 does not fall back to the index document for missing keys; the index document is only used for root/directory-style requests ending in /, not for arbitrary broken links.
      • D. Wrong — S3 does return an HTTP error status (typically 404) along with the error document body; it doesn't silently return an empty 204 response.

      Scenario 10

      A retailer wants to run a scheduled 4-hour deployment window during which their normal web servers will be completely torn down and rebuilt. During that window they want visitors redirected to a pre-built "under maintenance" experience with zero manual intervention required once the window starts, and no dependency on any compute resource. What should already be in place before the window begins?

      • A. An S3 bucket with static website hosting serving the maintenance page, plus a pre-planned DNS change to it
      • B. A Lambda function that generates the maintenance HTML on demand when servers become unreachable
      • C. An Auto Scaling group configured to scale to a single minimal instance during the deployment window
      • D. A CloudFront distribution caching the site's homepage with a very long TTL set in advance

      Topic: S3 static website hosting

      Correct answer: A

      • A. Correct — the out-of-band pattern calls for a static maintenance page hosted entirely in S3, completely independent of the compute being torn down, with DNS pre-planned to switch to it — matching "zero dependency on any compute resource" exactly.
      • B. Wrong — a Lambda function is still a compute resource that must run and could itself be affected by the deployment window's changes; it also adds needless complexity for serving a static page.
      • C. Wrong — keeping even one minimal EC2 instance running means the maintenance page still depends on compute, violating the "no dependency on any compute resource" requirement.
      • D. Wrong — a long CloudFront TTL caches the old homepage, not a custom maintenance message, and once the origin servers are torn down, some requests could still attempt origin revalidation and fail.

      Scenario 11

      A bucket owner wants to permanently turn off versioning on a bucket that currently has it enabled, planning to re-enable it later if ever needed. What is the correct action, and what happens to existing object versions?

      • A. Suspend versioning; existing versions remain in the bucket and no new versions are created going forward
      • B. Disable versioning directly; existing versions are automatically collapsed into a single current version
      • C. Suspend versioning; all existing non-current versions are immediately and permanently deleted
      • D. Delete the bucket and recreate it without versioning, then restore objects from a backup

      Topic: Object versioning and MFA Delete

      Correct answer: A

      • A. Correct — once enabled, versioning can only be suspended, never fully disabled. Suspension stops new versions from being created on future uploads, but every version already stored remains exactly as it was.
      • B. Wrong — there is no "disable" state reachable from "enabled"; and suspension never collapses or merges existing versions into one — they all remain distinct and stored.
      • C. Wrong — suspending versioning does not delete anything; all previously created versions stay in the bucket and continue to count toward storage costs until explicitly removed.
      • D. Wrong — this is a drastic, unnecessary, and risky approach that would require a full data migration; suspending versioning achieves the stated goal without touching any data.

      Scenario 12

      A bucket owner enables MFA Delete for the first time on a bucket that already had versioning enabled. Which credentials are required to perform this specific configuration change?

      • A. Any IAM user with s3:PutBucketVersioning attached, MFA not required for this step
      • B. The bucket owner's root account credentials, authenticated with an MFA device
      • C. Any assumed IAM role, as long as the role's session itself was established using MFA
      • D. A dedicated "security-admin" IAM group membership, no MFA device required

      Topic: Object versioning and MFA Delete

      Correct answer: B

      • A. Wrong — changing the versioning/MFA Delete state is exactly one of the two operations MFA Delete protects; a plain IAM permission without MFA authentication is not sufficient once this is being configured.
      • B. Correct — enabling or disabling MFA Delete requires the bucket owner's root account credentials combined with a valid MFA code from a registered device; this is one of the few operations still tied to root-level authentication.
      • C. Wrong — an IAM role's own session MFA doesn't satisfy this requirement; the specific operation to change versioning/MFA Delete state must come from the root user's credentials with MFA, not any generic role session.
      • D. Wrong — no IAM group membership, however named, substitutes for the root-credentials-plus-MFA requirement this specific configuration change enforces.

      Scenario 13

      A compliance officer needs to permanently and irreversibly remove one specific old version of a sensitive file from a versioned bucket, while leaving the current version and all other versions untouched. Which API call achieves this?

      • A. DELETE on the key with no version ID specified, which removes only the oldest version
      • B. DELETE on the key with the specific version ID of that one version included
      • C. Suspend versioning on the bucket, which purges every non-current version automatically
      • D. Apply a lifecycle rule that expires the current version after zero days

      Topic: Object versioning and MFA Delete

      Correct answer: B

      • A. Wrong — a delete without a version ID only ever adds a delete marker on top of the current version; it never permanently removes any version, oldest or otherwise.
      • B. Correct — specifying the exact version ID in the delete request permanently removes that specific version and only that version, leaving the current version and every other version fully intact — exactly the surgical removal requested.
      • C. Wrong — suspending versioning does not delete anything at all; it only stops future versions from being created, and existing versions (including the current one) remain untouched.
      • D. Wrong — a lifecycle expiration rule targets objects broadly by age criteria across the bucket, not one specific chosen version, and it would risk removing the current version too, violating the requirement.

      Scenario 14

      A bucket with versioning enabled stores a 2 GB file that gets re-uploaded daily for a year, creating 365 versions. The finance team notices storage costs are far higher than expected for what "should" be one 2 GB file. What is the most direct fix without disabling versioning?

      • A. Suspend versioning immediately, which retroactively removes all but the newest version
      • B. Enable MFA Delete, which automatically expires old versions after each new upload
      • C. Add a lifecycle rule that expires noncurrent versions after a defined retention window
      • D. Switch the bucket to One Zone-IA storage class, which does not retain old versions

      Topic: Object versioning and MFA Delete

      Correct answer: C

      • A. Wrong — suspending versioning only stops future versions from being created; it has no retroactive effect and does nothing to remove the 365 versions already stored and already costing money.
      • B. Wrong — MFA Delete is a security control on deletion operations; it does not automatically expire or clean up old versions on any schedule.
      • C. Correct — a lifecycle rule targeting noncurrent versions can automatically expire (permanently delete) versions older than a defined window, directly controlling the storage bloat from repeated uploads while keeping versioning itself enabled.
      • D. Wrong — storage class only changes the price tier and resilience characteristics of stored data; it has no effect on whether old versions are retained, and One Zone-IA still keeps every version just like Standard does.

      Scenario 15

      MFA Delete is enabled on a production bucket. A routine cleanup script runs nightly, calling plain DELETE on thousands of stale objects with no version IDs specified. What happens to the script's runs?

      • A. Every call is blocked with Access Denied, since MFA Delete requires MFA for any delete call at all
      • B. The calls succeed normally, adding delete markers, since MFA Delete only guards permanent version deletion and versioning-state changes
      • C. The calls succeed only if the script's IAM role session itself was established with MFA
      • D. The calls succeed but silently skip any object older than 90 days for compliance reasons

      Topic: Object versioning and MFA Delete

      Correct answer: B

      • A. Wrong — MFA Delete does not guard every delete call; it specifically protects permanent version deletion and versioning-state changes, not ordinary marker-adding deletes like this script performs.
      • B. Correct — a plain delete without a version ID only adds a delete marker, which is not one of the two operations MFA Delete protects. The script runs normally every night with no MFA prompt needed.
      • C. Wrong — MFA Delete's requirement is tied to the specific protected operations (version deletion, versioning state change), not to how the calling session itself was authenticated; a non-MFA session can still successfully add delete markers.
      • D. Wrong — there's no such automatic age-based skip behavior in S3 delete calls; nothing in MFA Delete or plain deletes filters by object age.

      Scenario 16

      A backend service uploads objects that are consistently 40 MB in size, and a flaky office connection drops mid-transfer often enough that engineers want per-chunk retry resilience instead of restarting failed uploads from zero. A teammate objects: "Multipart upload isn't worth using here — AWS requires an object to be at least 100 MB before multipart applies." Is the teammate right?

      • A. No — 100 MB is only AWS's guidance for when multipart starts paying off, not an enforced minimum; a 40 MB object can be split into parts of at least 5 MB each
      • B. Yes — the CreateMultipartUpload API itself rejects any object under 100 MB with a validation error
      • C. No, but only because enabling S3 Transfer Acceleration on the bucket overrides the 100 MB rule
      • D. Yes, and the only workaround is padding the object with filler bytes until it exceeds 100 MB before upload

      Topic: S3 performance optimization

      Correct answer: A

      • A. Correct — AWS recommends considering multipart upload once an object reaches around 100 MB, but that's a performance suggestion, not an enforced floor. The only real size constraints are on individual parts: at least 5 MB each, except the last part, up to 10,000 parts total. A 40 MB object can use multipart freely.
      • B. Wrong — this invents a specific API validation error that doesn't exist; CreateMultipartUpload has no object-size floor, only the per-part constraints noted above.
      • C. Wrong — Transfer Acceleration speeds up data transfer to the nearest edge location; it has no interaction with multipart eligibility or any "100 MB rule," which isn't a real constraint to begin with.
      • D. Wrong — this treats a nonexistent rule as real and proposes wasting bandwidth and storage to work around it; there's no minimum to pad toward in the first place.

      Scenario 17

      A team tries to enable S3 Transfer Acceleration on a bucket named reports.q3.2026 and the console rejects the request. What is the most likely reason?

      • A. Transfer Acceleration requires the bucket to already have versioning enabled first
      • B. Transfer Acceleration cannot be enabled on buckets smaller than 100 MB in total size
      • C. The bucket name contains dots, which Transfer Acceleration's DNS-compatibility requirement disallows
      • D. The bucket name contains numbers, which are not permitted in accelerated bucket names

      Topic: S3 performance optimization

      Correct answer: C

      • A. Wrong — Transfer Acceleration has no dependency on the bucket's versioning state; the two features are unrelated configuration settings.
      • B. Wrong — there is no minimum total bucket size requirement for enabling Transfer Acceleration; that's not a real constraint of the feature.
      • C. Correct — Transfer Acceleration requires a DNS-compatible bucket name with no dots (periods). reports.q3.2026 contains dots, which violates this requirement and blocks the feature from being enabled.
      • D. Wrong — lowercase letters, numbers, and hyphens are all permitted in a DNS-compatible bucket name; numbers themselves are not the problem here, the dots are.

      Scenario 18

      A video archive needs to upload a single 48 GB file to S3. The upload must be split into parts, and the team wants to minimize the number of parts used while staying within S3's hard limits. What part size should they choose?

      • A. 5 MB parts, since that is the only supported part size for multipart upload
      • B. Roughly 5 GB parts, close to the maximum per-part size, keeping the part count low
      • C. Exactly 10,000 equally sized parts regardless of the resulting per-part size
      • D. A single part covering the full 48 GB, since multipart has no per-part maximum

      Topic: S3 performance optimization

      Correct answer: B

      • A. Wrong — 5 MB is only the minimum part size, not the only allowed size; using it for a 48 GB file would require nearly 10,000 tiny parts, unnecessarily close to the maximum part count.
      • B. Correct — part sizes can range up to 5 GB. Choosing parts near that maximum for a 48 GB file keeps the total part count low (around 10 parts) while staying safely within both the size-per-part and 10,000-part limits.
      • C. Wrong — forcing exactly 10,000 parts for a 48 GB file would make each part only about 4.8 MB, needlessly maximizing part count and overhead for no benefit.
      • D. Wrong — each part has a hard maximum of 5 GB; a single 48 GB part is not permitted, and this defeats the purpose of splitting the upload at all.

      Scenario 19

      A company enables S3 Transfer Acceleration on a bucket in ap-southeast-2 to help a small team of users who are also based in the same region and metro area upload large files. After enabling it, upload speeds are essentially unchanged. Why?

      • A. Transfer Acceleration was configured incorrectly and needs a support ticket to activate properly
      • B. Transfer Acceleration helps most when there's real geographic distance between user and bucket, which isn't the case here
      • C. Transfer Acceleration only benefits downloads, never uploads, regardless of distance
      • D. Transfer Acceleration requires multipart upload to be enabled simultaneously to have any effect

      Topic: S3 performance optimization

      Correct answer: B

      • A. Wrong — enabling Transfer Acceleration is a straightforward bucket setting; it doesn't require any support ticket, and this isn't a plausible cause for the described lack of improvement.
      • B. Correct — Transfer Acceleration's benefit comes from routing over the AWS backbone instead of the public internet across distance; when users are already near the bucket's region, there's little distance-related latency to save, so the improvement is minimal.
      • C. Wrong — Transfer Acceleration benefits uploads (and can also help downloads); it's not upload-exclusive in reverse — the real issue here is the lack of distance, not upload vs. download direction.
      • D. Wrong — Transfer Acceleration and multipart upload are independent features; Transfer Acceleration works on its own without requiring multipart to be enabled at the same time.

      Scenario 20

      An engineer uploads a 4.5 GB file using default single-stream upload over an unstable connection. At 95% complete, the connection drops. What must happen next, and what would have prevented this cost?

      • A. The upload resumes automatically from 95%; single-stream uploads checkpoint progress natively
      • B. The entire upload must restart from zero; multipart upload would have limited the loss to the last failed part
      • C. Only the last 5% needs re-uploading; S3 always retains partially received single-stream data
      • D. The object is stored as a 95%-complete file; the engineer must manually complete it later

      Topic: S3 performance optimization

      Correct answer: B

      • A. Wrong — a single-stream upload has no checkpointing; if the stream fails at any point, the entire upload fails and must be started over from the very beginning.
      • B. Correct — single-stream uploads have no partial recovery, so a drop at 95% means restarting the whole 4.5 GB transfer. Multipart upload would have broken the file into independently retriable parts, so only the in-flight part would need to be redone.
      • C. Wrong — S3 does not retain partial data from a failed single-stream upload; the object is never created until the full stream completes successfully, so there's nothing partial to resume.
      • D. Wrong — S3 never stores an incomplete object; an upload that fails mid-stream results in no object at all, not a partially saved one waiting to be finished.

      Scenario 21

      An application needs to encrypt a 20 KB configuration file using a KMS key directly, without generating a separate data key. What happens when it calls Encrypt on the KMS key with this payload?

      • A. It succeeds, since KMS keys can directly encrypt any payload up to 1 MB in size
      • B. It fails, since direct KMS key encryption is capped at 4 KB and this payload exceeds that
      • C. It succeeds, but KMS automatically and transparently splits the payload into multiple 4 KB chunks
      • D. It succeeds only if the customer-managed key has "large payload mode" explicitly enabled first

      Topic: KMS introduction

      Correct answer: B

      • A. Wrong — the direct encryption limit for a KMS key is 4 KB, not 1 MB; a 20 KB payload is well over that limit.
      • B. Correct — KMS keys can only directly encrypt up to 4 KB of data. A 20 KB payload exceeds this, and the call fails; the application would need to generate a Data Encryption Key via GenerateDataKey and encrypt the payload with that instead.
      • C. Wrong — KMS does not automatically chunk or split oversized payloads for direct encryption; the caller must handle the DEK pattern themselves, KMS simply rejects requests over the limit.
      • D. Wrong — there is no "large payload mode" setting on a KMS key; the 4 KB direct-encryption limit is fixed and not configurable.

      Scenario 22

      A data ingestion role needs to encrypt incoming files using a customer-managed KMS key, but security policy states this role must never be able to read back any of the data it encrypts. What KMS configuration enforces this?

      • A. A key policy granting the role kms:GenerateDataKey and kms:Encrypt but withholding kms:Decrypt
      • B. A key policy granting the role full kms:* access, relying on CloudTrail to audit any decrypt calls after the fact
      • C. Switching to an AWS-owned key, since those keys never expose decrypt capability to any principal
      • D. Enabling automatic key rotation, which structurally prevents the same principal from both encrypting and decrypting

      Topic: KMS introduction

      Correct answer: A

      • A. Correct — KMS permissions are granular per action. Granting only the encrypt-side actions (GenerateDataKey, Encrypt) while withholding Decrypt enforces genuine role separation — the role can encrypt but structurally cannot read data back.
      • B. Wrong — granting full access and relying on audit logs is detective, not preventive; the role would still be technically capable of decrypting, violating the "must never be able to" requirement — CloudTrail only tells you after the fact.
      • C. Wrong — AWS-owned keys aren't about withholding decrypt from a specific role; they're keys the customer has no visibility or policy control over at all, which doesn't map to this scenario's need for a customer-defined, role-specific permission split.
      • D. Wrong — key rotation only changes which key material is actively used for new encryption operations over time; it has no bearing on which IAM actions a given principal is permitted to call.

      Scenario 23

      A customer-managed KMS key has automatic annual rotation enabled and has now rotated three times over three years. An application still needs to decrypt objects that were encrypted using the original key material from year one. What must the application do differently to decrypt these old objects?

      • A. Nothing — KMS retains all prior key material under the same key ID, so old ciphertext still decrypts correctly
      • B. Re-encrypt every historical object with the newest key material before any of them can be decrypted again
      • C. Manually specify the year-one key version ID on every decrypt call for those older objects
      • D. Restore the year-one key from AWS Backup before attempting to decrypt any of the older ciphertext

      Topic: KMS introduction

      Correct answer: A

      Correct answer: B

      • C. Wrong — Athena queries objects that are queryable in S3 (or via Glacier-aware connectors with restore steps); it isn't a substitute for Glacier Select's direct in-place filtering of a single archived object.

      Scenario 64

      An engineer wants to use S3 Select to pull a handful of matching JSON records out of a 10 GB object, and is deciding what happens to the object as a side effect. Which statement correctly describes the outcome?

      • B. The matching records are returned; the original object and its storage class are unchanged

      • D. A new filtered copy of the object is created alongside the original in the same bucket

      • A. Wrong — S3 Select never changes an object's storage class; storage class transitions only happen through lifecycle rules or explicit copy/put operations, not as a side effect of a query.

      Scenario 66

      Scenario 68

      Correct answer: B

      Scenario 70

      A team configures S3 Event Notifications on a bucket to trigger a Lambda function whenever any object is deleted, intending to log every deletion for audit purposes.       Correct answer: B

      • C. Wrong — delete events are available through native S3 Event Notifications directly to SNS, SQS, or Lambda; routing through EventBridge is not required to receive them.

      Scenario 71

      A security engineer enables logging on a production bucket, designating a separate, newly-created bucket (default settings, created this year) as the destination for log files.       • A. A destination bucket policy granting s3:PutObject to the logging.s3.amazonaws.com service principal
      • B. An ACL grant on the destination bucket for the S3 log delivery group
      • C. A pre-signed URL generated for the logging service's PUT requests
      • D. A CloudFront distribution placed in front of the destination bucket

      Topic: S3 access logs

      Correct answer: A

      • A. Correct — the current, recommended mechanism is a destination bucket policy granting s3:PutObject to the logging.s3.amazonaws.com service principal.       • C. Wrong — pre-signed URLs are time-limited and generated per request for a specific caller; they aren't how S3's system-level logging service is granted ongoing write access.

      Scenario 76

      A brokerage must retain trade records for 7 years under SEC Rule 17a-4, with an explicit requirement that absolutely no one — including the company's own root user — can delete or shorten the retention early, even under internal pressure. Which S3 Object Lock configuration satisfies this?

      • D. Versioning enabled with MFA Delete required for all deletions

      Topic: S3 Object Lock

      Correct answer: B

      • A. Wrong — even with restricted bypass permissions, Governance mode still has a bypass mechanism (s3:BypassGovernanceRetention) that could be granted, including to the root user, so it can't guarantee "absolutely no one."

      • B. Wrong — Legal Hold is a binary on/off flag with no retention period, and removing it requires only s3:PutObjectLegalHold; it doesn't provide the 5-year default protection window described.

      Scenario 78

      Scenario 79

      A team tries to enable Object Lock on an existing production bucket that has never had versioning turned on, and the operation fails. What is the most accurate explanation?

      Scenario 80

      An object under Governance mode retention still has 60 days left before its lock expires. An administrator with the s3:BypassGovernanceRetention permission wants to delete it early for a legitimate data-correction reason. What must they do to succeed?

      Scenario 81

      A single S3 bucket is shared by five business units. The bucket policy has grown to hundreds of lines mixing rules for every team, prefix, and use case, making changes risky and hard to review. What is the recommended way to simplify this without duplicating the underlying data?

      Correct answer: B

      Scenario 84

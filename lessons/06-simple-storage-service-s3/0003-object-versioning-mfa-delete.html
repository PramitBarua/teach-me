Bucket Versioning States

Every S3 bucket starts with versioning disabled. Once you enable it, you cannot go back to disabled — you can only suspend it. A suspended bucket can be re-enabled later.

StateCan transition to
Disabled (default)Enabled
EnabledSuspended only — never back to Disabled
SuspendedEnabled again

How Versioning Works

Each object is identified by its key (the object name). When versioning is disabled, the object's version ID is null. When versioning is enabled, every upload or modification gets a new unique version ID — the previous version is not overwritten; both co-exist in the bucket.

Deleting Versioned Objects

OperationWhat actually happens
Delete without specifying a version ID S3 adds a delete marker — the object appears deleted, but all versions are still in the bucket. Remove the delete marker to restore.
Delete with a specific version ID That version is permanently removed. Cannot be undone.
Cost note
All stored versions count towards your storage bill. A 1 GB file modified 10 times stores up to 10 GB worth of data. Use lifecycle rules to expire old versions.

MFA Delete

MFA Delete is an extra security layer enabled on the bucket configuration. Once on, two operations require MFA authentication (serial number + one-time code from the MFA device):

  1. Changing the versioning state of the bucket (enable ↔ suspend)
  2. Permanently deleting a specific object version
Exam tip
Once versioning is enabled it cannot be disabled — only suspended. This is a common distractor in exam questions. Also remember: a plain DELETE call adds a delete marker; you need to specify the exact version ID for a permanent deletion.

Retrieval Practice

1. A bucket currently has versioning enabled. An admin wants to turn versioning completely off. What can they do?

2. A user deletes an object from a versioning-enabled bucket without specifying a version ID. What is the result?

3. Which two actions require MFA authentication when MFA Delete is enabled on a bucket?

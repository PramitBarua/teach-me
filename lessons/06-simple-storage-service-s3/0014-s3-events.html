What are S3 Events?

S3 Event Notifications allow you to trigger automated reactions when something happens inside an S3 bucket — for example, when an object is created, deleted, or restored from Glacier.

Event Destinations

When an event fires, S3 delivers a notification to one of these targets:

  • SNS topic — fan-out to multiple subscribers (email, other queues, etc.)
  • SQS queue — buffer the event for asynchronous processing
  • Lambda function — run code in response to the event

S3 Events vs EventBridge

S3 Event NotificationsAmazon EventBridge
Setup locationBucket notification configurationEventBridge rule consuming S3 events
Event types supportedLimited S3 events onlyAll S3 events + many more AWS services
TargetsSNS, SQS, Lambda only50+ AWS service targets
Advanced filteringPrefix/suffix on key nameContent-based filtering, transformations
Recommended forSimple, single-destination S3 triggersComplex, multi-service event architectures
Exam tip
When a question involves reacting to S3 events with multiple downstream targets, cross-service routing, or advanced filtering, prefer EventBridge. For simple "upload triggers a Lambda" scenarios, S3 Event Notifications are sufficient.

Simple Storage Service (S3)

S3 Object Encryption: CSE & SSE

Lesson 06 of 16 · ~10 min

Source: Adrian Cantrill SAA-C03 · S3 Encryption Docs

Objects are Encrypted — Not Buckets

S3 encrypts individual objects, not buckets. Different objects in the same bucket can use different encryption settings. A bucket can have a default encryption configuration, but each object's effective encryption is what matters.

Since 2023 AWS mandates server-side encryption for all new S3 objects — unencrypted storage is no longer permitted.

Client-Side Encryption (CSE) vs Server-Side Encryption (SSE)

CSESSE
Where encryption happensClient, before uploadS3 servers, after arrival via HTTPS
Who holds the keysClient entirelyVaries by SSE type
AWS visibility of plaintextNever — AWS only sees ciphertextBriefly during the encryption step

The Three SSE Types

SSE-C — Customer-Provided Keys

You manage the key. You send the key + plaintext data over HTTPS to S3. S3 encrypts the object, stores a hash of the key alongside the object, then destroys the key. To decrypt, you must supply the same key again — S3 uses the hash to verify it matches.

Use when: you must own and manage keys but are happy to let S3 handle the cryptographic operation itself.

SSE-S3 — S3-Managed Keys (default)

AWS manages both the encryption and the keys. S3 uses a unique key per object (AES-256). You have no control over key rotation, key access, or who can use the key.

Problem: a full S3 administrator can decrypt all data — there is no role separation between S3 access and data access.

SSE-KMS — KMS-Managed Keys

Like SSE-S3 but the key is a customer-managed KMS key. S3 requests a DEK from KMS for each object, uses the plaintext DEK to encrypt the object, discards it, and stores the ciphertext DEK alongside the object.

Advantages over SSE-S3: key audit trail in CloudTrail, configurable rotation, and role separation — an S3 admin without KMS decrypt permission cannot read the data.

Exam tip
If a question asks about preventing S3 admins from reading data, or about controlling key rotation, the answer is SSE-KMS with a customer-managed key. SSE-S3 cannot provide role separation.

Retrieval Practice

1. With SSE-C, what does S3 store alongside the encrypted object to enable future decryption verification?

2. A company is legally required to prove that S3 data encryption keys are rotated annually and that access to the keys is audited. Which encryption type meets this requirement?

3. With SSE-S3, what can a user with full S3 administrator permissions do that would be prevented with SSE-KMS?

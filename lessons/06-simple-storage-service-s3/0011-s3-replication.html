Simple Storage Service (S3)

S3 Replication (CRR & SRR)

Lesson 11 of 16 · ~10 min

Source: Adrian Cantrill SAA-C03 · S3 Replication Docs

Two Types of Replication

TypeSource and destinationCommon use cases
CRR (Cross-Region Replication) Different AWS regions Global resilience, reduced latency for distant users
SRR (Same-Region Replication) Same AWS region Log aggregation, prod→test account sync, data sovereignty

How Replication is Configured

Replication configuration lives on the source bucket and specifies:

  1. Destination bucket — where objects are replicated to.
  2. IAM role — assumed by S3 to perform the replication. The trust policy allows S3 to assume the role; the permission policy grants read on the source and write on the destination.

Same vs Different AWS Accounts

ScenarioExtra requirement
Same AWS account None — the IAM role is trusted by both buckets automatically
Different AWS accounts A bucket policy on the destination bucket must explicitly allow the source account's IAM role to write into it

What Is and Isn't Replicated

FeatureBehaviour
Replication directionOne-way (source → destination) by default; bi-directional needs additional config
Retroactive replicationNot retroactive — only objects written after replication is enabled; use Batch Replication for existing objects
Versioning requirementBoth source and destination buckets must have versioning enabled
Delete markersNot replicated by default; must be explicitly enabled
Lifecycle actionsNot replicated — lifecycle rules on the source do not carry over
Glacier / Glacier Deep Archive objectsNot replicated
Objects not owned by source accountNot replicated unless the source bucket owner has permission on those objects

Replication Time Control (RTC)

An optional feature that adds a guaranteed 15-minute SLA for replication. Useful when predictability of replication lag is important for compliance or applications.

Exam tip
The most common exam traps: (1) replication is not retroactive — existing objects need Batch Replication; (2) delete markers are not replicated by default; (3) versioning must be enabled on both buckets.

Retrieval Practice

1. CRR is enabled on a bucket that already contains 10,000 objects. How many of those existing objects are replicated automatically?

2. A team deletes an object in the source bucket. Is the delete marker replicated to the destination bucket by default?

3. Replication is configured between two buckets in different AWS accounts. What extra configuration is required?

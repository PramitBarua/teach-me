Simple Storage Service (S3)

S3 Security: Resource Policies & ACLs

Lesson 01 of 16 · ~8 min

Source: Adrian Cantrill SAA-C03 · S3 Access Policy Guidelines

S3 is Private by Default

When an S3 bucket is created, only the AWS account root user and the identity that created the bucket have any access to it. Everything else — other IAM users, other AWS accounts, anonymous users — is implicitly denied until you explicitly grant access.

Bucket Policies (Resource Policies)

A bucket policy is a resource-based policy attached directly to the bucket. Like any resource policy, it contains a Principal field that specifies who the policy applies to. This is the key structural difference from an identity policy, which never has a Principal.

Quick tell: is this a resource policy?
If a policy document contains a "Principal" key, it is almost certainly a resource policy (bucket policy, KMS key policy, trust policy, etc.), not an identity policy.

One bucket can have one bucket policy, but that policy can contain multiple statements — granting different things to different principals.

How Policies Combine

Who is accessing?Which policies apply?
An IAM identity in the same AWS account The union of the identity's IAM policies and the bucket policy. Both must allow (or neither must deny).
An anonymous (unauthenticated) user Only the bucket policy — there is no identity policy to consult.
An IAM identity in a different AWS account Both the identity's policies in that account and the bucket policy in this account must allow.

Bucket Policy vs Identity Policy — When to Use Each

SituationPreferred approach
Many identities need access to one bucketBucket policy — one place to manage all access
One identity needs access to many bucketsIdentity policy — attach once to the user or role
Centralised IAM management is a requirementIdentity policy — everything lives in IAM
Anonymous (public) access is neededBucket policy — anonymous requests have no identity to attach a policy to
Exam tip
Anonymous access requires a resource policy because anonymous requests have no identity — there is nothing to attach an identity policy to.

S3 Lifecycle Configuration

Lesson 10 of 16 · ~8 min

Source: Adrian Cantrill SAA-C03 · S3 Lifecycle Management Docs

What is Lifecycle Configuration?

A lifecycle configuration is a set of rules that automatically perform actions on objects in a bucket based on age (not access frequency). Rules can target the whole bucket, a prefix, or specific object tags.

Action Types

TypeWhat it does
Transition actionMoves objects to a different (cheaper) storage class after N days
Expiration actionDeletes objects (or non-current versions) after N days
Not access-based
Lifecycle rules are time-based, not access-based. A rule that moves objects after 30 days will move them even if they are accessed daily. Use Intelligent-Tiering for access-based automation.

Transition Hierarchy

Objects can only move down this hierarchy — never back up:

  1. S3 Standard
  2. S3 Standard-IA
  3. S3 Intelligent-Tiering
  4. S3 One Zone-IA
  5. S3 Glacier Instant Retrieval
  6. S3 Glacier Flexible Retrieval
  7. S3 Glacier Deep Archive

Exception: One Zone-IA cannot transition directly to Glacier Instant Retrieval.

Key Constraints

  • Objects must remain in S3 Standard for at least 30 days before a lifecycle rule can transition them to Standard-IA or One Zone-IA. (This restriction does not apply if you place the object directly into those classes at upload time.)
  • Using a single lifecycle rule to go Standard → Standard-IA → Glacier requires waiting the full 30 days in Standard-IA. To bypass this with two rules, you can transition to Standard-IA and then to Glacier in less than 30 days total.
  • Watch small objects: transitioning many tiny objects can increase cost due to the minimum object-size billing of lower classes.
Exam tip
Lifecycle rules are a cost-optimisation tool. The 30-day wait for Standard → Standard-IA via lifecycle, and the one-way-only hierarchy, are the two most tested constraints.

Simple Storage Service (S3)

S3 Performance Optimization

Lesson 04 of 16 · ~7 min

Source: Adrian Cantrill SAA-C03 · S3 Performance Docs

Single-Stream Upload (Default)

By default an S3 upload is a single data stream. If the stream fails at any point the entire upload fails and you must restart from zero. The practical size limit for a single-stream upload is 5 GB, but AWS recommends avoiding single-stream for anything large — even well below 5 GB — because a mid-upload failure wastes all the bandwidth already used.

Multipart Upload

Multipart upload breaks a large object into independent chunks uploaded in parallel. Each chunk can be retried individually on failure.

ParameterValue
Minimum object size to use multipart100 MB
Maximum number of parts10,000
Size per part5 MB – 5 GB (last part can be smaller)
Why multipart?
Parallelism increases throughput. Resilience is improved because only the failed part needs to be re-uploaded, not the whole object.

S3 Transfer Acceleration

Transfer Acceleration routes upload traffic through the nearest AWS edge location, then across the fast AWS global backbone network to the destination bucket — instead of travelling the full public internet to the region.

Requirements to enable Transfer Acceleration:

  • The bucket name must be DNS-compatible (lowercase letters, numbers, hyphens only).
  • The bucket name must not contain any dots (periods).

When Transfer Acceleration helps most:

  • The user and the bucket are far apart geographically (long distance = high benefit).
  • The user's initial connection to the edge location is not a bottleneck (e.g. good local connectivity to the edge).
Exam tip
Transfer Acceleration is disabled by default; you enable it per bucket. It helps with distance and last-mile connectivity — if the user and bucket are in the same region, it offers little benefit.

Simple Storage Service (S3)

S3 Select & Glacier Select

Lesson 13 of 16 · ~5 min

Source: Adrian Cantrill SAA-C03 · S3 Select Docs

The Problem

Without S3 Select, to find anything inside a large object you must first retrieve the entire object. A CSV with 5 TB of data requires a 5 TB download just to read 10 rows. This wastes time, bandwidth, and money.

What S3 Select and Glacier Select Do

S3 Select and Glacier Select let you run SQL-like queries against the content of an object — filtering data server-side, inside S3 or Glacier, before the data is returned to you. Only the matching rows or fields are transferred.

Without SelectWith Select
Data transferredFull object sizeOnly the filtered subset
Processing locationClient (after full download)S3/Glacier (before transfer)
CostHigh egress + computeLower egress, some Select query cost
SpeedProportional to object sizeProportional to filtered result size
Exam tip
If a question mentions querying a subset of a very large S3 or Glacier object to reduce cost and time, the answer is S3 Select / Glacier Select. For running SQL across many objects in a bucket, the answer is Amazon Athena (a different service).

Retrieval Practice

1. What is the key advantage of S3 Select over downloading the full object and filtering client-side?

2. Which service should you use to run SQL queries across thousands of CSV files stored in an S3 bucket?

3. A 2 TB Glacier archive contains daily transaction logs. A query needs only transactions from one specific day. What does Glacier Select return?

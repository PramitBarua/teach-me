Simple Storage Service (S3)

S3 Access Points

Lesson 17 of 17 · ~7 min

Source: Adrian Cantrill SAA-C03 · S3 Access Points Docs

The Problem: One Bucket, Many Teams

When a single S3 bucket is shared by many teams or stores objects for different purposes, the bucket policy becomes complex and hard to manage. A single bucket policy must contain rules for every team's access, every prefix, and every use case — growing unwieldy over time.

What are Access Points?

An Access Point is a named network endpoint attached to a bucket. Think of it as a mini-bucket view with its own:

  • Unique DNS address — each access point has its own hostname
  • Access Point Policy — functionally equivalent to a bucket policy; controls what can be done via that access point
  • Optional VPC restriction — an access point can be locked to a specific VPC, so it can only be reached from within that VPC

You create as many access points as you need. Each team gets its own access point with its own scoped policy.

The Delegation Pattern

Access point permissions and bucket policy permissions are both evaluated. A permission defined in an access point policy must also be allowed in the bucket policy. The recommended pattern is delegation:

  1. On the bucket policy: grant broad (wildcard) access via any access point. This delegates the fine-grained control to the access points themselves.
  2. On each access point policy: define the specific, least-privilege permissions for that team or use case.
Creating an access point (CLI)
aws s3control create-access-point --name <name> --account-id <account> --bucket <bucket>
Exam tip
Access points are a management simplification tool, not a new access control mechanism. The bucket policy still applies; access points let you break one unwieldy bucket policy into smaller, team-scoped policies.

Retrieval Practice

1. What does each S3 Access Point provide that makes it distinct from another access point on the same bucket?

2. An access point policy allows a team to read objects in the /finance/ prefix. The bucket policy has no statement for that team. Can the team read those objects?

3. A financial application runs in a VPC and must only access S3 through a private network path, never the public internet. Which access point feature enables this?

Simple Storage Service (S3)

S3 Object Lock

Lesson 16 of 17 · ~8 min

Source: Adrian Cantrill SAA-C03 · S3 Object Lock Docs

What is S3 Object Lock?

Object Lock implements a WORM (Write Once, Read Many) model — preventing objects from being deleted or overwritten for a specified period. Object Lock requires versioning to be enabled; it applies to individual versions, not to objects as a whole.

A bucket can have a default Object Lock configuration that applies automatically to all new objects.

Retention Modes

Governance Mode

Objects are protected during the retention period, but users with the special IAM permission s3:BypassGovernanceRetention (and the header x-amz-bypass-governance-retention:true) can adjust or remove the lock. This permission is also available via the console UI.

Use for: most compliance and data protection scenarios where some trusted users need override capability.

Compliance Mode

The most restrictive mode. No one — not even the account root user — can delete or overwrite the object until the retention period expires. The retention period itself cannot be shortened.

Use for: strict regulatory requirements (e.g. SEC Rule 17a-4 for financial records).

Legal Hold

A binary on/off flag — no retention period involved. When legal hold is ON for an object version, it cannot be deleted or overwritten for any reason until the hold is removed. Requires the IAM permission s3:PutObjectLegalHold to set or remove.

Exam tip
Compliance mode is absolute — remember that even the root user cannot delete or shorten it. If a question mentions "regulator requires immutable records for X years that no one can alter", the answer is Compliance mode.

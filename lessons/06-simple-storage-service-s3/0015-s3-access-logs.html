Simple Storage Service (S3)

S3 Access Logs

Lesson 15 of 17 · ~6 min

Source: Adrian Cantrill SAA-C03 · S3 Server Access Logging Docs

What is S3 Access Logging?

S3 Access Logging records detailed information about every request made to a bucket. It is a primary tool for security auditing, understanding access patterns, and diagnosing unexpected S3 billing increases.

Source Bucket and Target Bucket

The setup involves two buckets:

  • Source bucket — the bucket you want visibility into. You enable access logging on this bucket.
  • Target bucket — where the log files are delivered. It can be a different bucket, or even the source bucket itself (though a separate bucket is cleaner).

How Logging Works

When you enable logging, S3 creates a log delivery group — a special system entity that reads the logging configuration on the source bucket and writes log files to the target bucket. The log delivery group needs write permission on the target bucket, which is granted via an ACL on the target bucket.

Best-effort delivery
Access logging is a best-effort process. Log records are usually delivered within a few hours, and changes to the logging configuration may take a few hours to take effect. Do not rely on it for real-time alerting — use S3 Events or CloudWatch for that.

Managing Multiple Source Buckets

A single target bucket can receive logs from many source buckets. To keep logs organised, set a key prefix in each source bucket's logging configuration. For example, a source bucket named prod-uploads could log to the prefix prod-uploads/ in the shared target bucket.

Log Lifecycle

S3 does not automatically expire or delete log files — they accumulate indefinitely. You are responsible for managing their lifecycle: apply lifecycle rules on the target bucket to transition old logs to a cheaper storage class or expire them after a retention period.

Exam tip
Three things to remember: (1) access is granted to the log delivery group via ACL on the target bucket; (2) logging is best-effort, not real-time; (3) you must manage log expiry yourself with lifecycle rules.

Retrieval Practice

1. What mechanism grants the S3 log delivery group permission to write to the target bucket?

2. Ten S3 buckets all log to the same target bucket. How should logs be separated to make auditing easy?

3. A target bucket has been receiving access logs for 2 years. No lifecycle rule is configured. What happens to the log files?

Key Management Service (KMS) — Introduction

Lesson 05 of 16 · ~10 min

Source: Adrian Cantrill SAA-C03 · AWS KMS Docs

What is KMS?

AWS Key Management Service (KMS) is a regional, public AWS service that creates, stores, and manages cryptographic keys. Keys created in KMS never leave KMS in plaintext — all encrypt/decrypt operations happen inside the service. KMS meets the US FIPS 140-2 (Level 2) security standard.

KMS Keys and the 4 KB Limit

KMS keys can directly encrypt or decrypt up to 4 KB of data. For anything larger you need Data Encryption Keys (DEKs).

Data Encryption Keys (DEKs)

Use the GenerateDataKey operation to create a DEK. KMS returns two versions of the DEK:

VersionWhat you do with it
Plaintext DEK Use immediately to encrypt the data. Discard it as soon as you're done.
Ciphertext DEK Store alongside the encrypted data. To decrypt later, pass this ciphertext DEK back to KMS to get the plaintext DEK again.
KMS does NOT store DEKs
KMS hands the DEK to you and forgets it. You are responsible for storing the ciphertext version alongside your data. KMS only stores its own master keys (KMS keys), not the derived DEKs.

KMS Key Types

TypeConfigurable?Rotation
AWS-owned keys No control AWS manages rotation fully
AWS-managed (customer account) Not configurable Managed by AWS; cannot be disabled
Customer-managed keys (CMK) Fully configurable Customer controls rotation (enabled by default)

When a key is rotated, AWS keeps the old key material so previously-encrypted data can still be decrypted. You do not need to re-encrypt existing data after rotation.

Exam tip
KMS enforces role separation through granular permissions: a user can have permission to GenerateDataKey but not to Decrypt. A full S3 admin doesn't automatically get decrypt access unless the key policy allows it. This is the primary reason to choose SSE-KMS over SSE-S3.

Retrieval Practice

2. After using GenerateDataKey, what should you do with the plaintext DEK once the data is encrypted?

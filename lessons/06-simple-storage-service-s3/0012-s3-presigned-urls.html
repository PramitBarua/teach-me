Simple Storage Service (S3)

S3 Pre-Signed URLs

Lesson 12 of 16 · ~6 min

Source: Adrian Cantrill SAA-C03 · S3 Pre-Signed URL Docs

What is a Pre-Signed URL?

A pre-signed URL encodes your AWS credentials and permissions into a time-limited URL. Anyone who receives the URL can access the S3 object — as if they were you — for the duration of the URL's validity.

This lets you share access to private objects without making them public and without creating IAM users for external parties.

How Permissions Work

The URL holder's effective permissions are those of the identity that generated the URL at the moment the URL is used, not at the moment it was created. Two important consequences:

  • If the generating identity loses access to the object (policy change, role revoked), the URL stops working — even if it hasn't expired.
  • You can generate a pre-signed URL for an object you don't currently have access to. The URL is technically valid but will return Access Denied when used.
Don't generate pre-signed URLs from IAM roles
IAM role temporary credentials have a maximum validity period that is typically shorter than the pre-signed URL's intended lifetime. If the role credentials expire before the URL does, the URL stops working. Use a long-lived IAM user identity instead.

Validity Period

Pre-signed URLs can have a much longer validity period than the temporary credentials of an IAM role — making them suitable for scenarios like sharing a large file download link that a user might not click immediately.

Exam tip
Pre-signed URL scenarios to recognise: (1) "share a private S3 object with an external user without making it public" → pre-signed URL; (2) "provide temporary, time-limited upload access to a bucket" → pre-signed URL with PUT permission.

Retrieval Practice

1. A pre-signed URL is generated for an object. The generating IAM user is then removed from the group that grants S3 access. What happens when the URL is used?

2. An application uses an IAM role to generate a pre-signed URL with a 7-day expiry. The role's temporary credentials expire after 1 hour. What happens after 1 hour?

3. A company needs to allow an external contractor to upload a single file to a private S3 bucket without granting them AWS credentials. What is the best approach?

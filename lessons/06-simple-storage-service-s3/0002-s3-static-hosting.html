S3 Static Website Hosting

What is S3 Static Hosting?

By default, S3 is accessed via the AWS API (HTTPS with AWS signing). Static website hosting enables an HTTP endpoint that any browser can reach — making S3 suitable for hosting static HTML, CSS, JavaScript, and media files.

When you enable static website hosting on a bucket you must specify two files:

  • Index document (e.g. index.html) — returned when a visitor navigates to the root URL or a directory without specifying a file.
  • Error document (e.g. error.html) — returned when a requested page does not exist or a server error occurs.

Two Practical Use Cases

Use caseHow it works
Offloading Serve static assets (images, JS, CSS) from S3 instead of your application servers. Reduces load on compute and takes advantage of S3's scaling.
Out-of-band pages Host a maintenance or status page in S3. When your primary servers go offline, update DNS to point visitors to the S3 static site instead. The maintenance page is hosted entirely outside your main infrastructure.

Cost Model

Cost componentDirectionNotes
StorageAlwaysPer GB per month; billed proportionally if stored for less than a full month
Data transferData in is free; data out charged per GBTransfers to the internet or other AWS regions incur egress fees
RequestsAlwaysCharged per 1,000 operations (GET, PUT, etc.); different operations have different per-1k rates
Exam tip
The out-of-band pattern is a favourite exam scenario: "your web servers are unavailable — how do you show users a maintenance page?" The answer is to pre-host a static page in S3 and redirect DNS to it.

Retrieval Practice

1. When a browser requests the root URL of an S3 static website and no path is specified, which file does S3 return?

2. A company's web servers are taken offline for emergency maintenance. Users need to see a "We'll be back soon" page. Which architecture achieves this with minimal infrastructure?

3. Which S3 data transfer scenario always incurs zero cost?

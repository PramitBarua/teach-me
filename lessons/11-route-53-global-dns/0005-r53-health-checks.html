Route 53 Health Checks

Lesson 05 of 13 · ~9 min

Source: Adrian Cantrill SAA-C03 · How Route 53 Checks the Health of Your Resources

Health checks underpin nearly every advanced Route 53 routing policy that follows in this module. They're created and configured separately from records — not inside a record — and then referenced by whichever records need them.

How a Check Runs

Checks run from a globally distributed fleet of health checkers — so if you're checking a public-internet endpoint, don't block their traffic as if it were a bot or an attack, or you'll get false failures. There are three check mechanisms, increasing in accuracy:

TypeWhat must succeed
TCPA TCP connection completes within 10 seconds
HTTP/HTTPSTCP connects within 4 seconds, and a 2xx or 3xx status is returned within 2 seconds of connecting
HTTP/HTTPS + string matchingSame as above, and the response body (received within a further 2 seconds) must contain a specified string within its first 5,120 bytes

Checks run every 30 seconds by default, or every 10 seconds ("fast") for an added cost. Checks aren't limited to AWS targets — anything reachable by IP address on the internet can be checked.

Three Kinds of Check

  • Endpoint checks — directly test a specified IP or domain name.
  • CloudWatch alarm checks — react to the state of a CloudWatch alarm, which can reflect deep in-OS or in-app metrics if the CloudWatch agent is involved.
  • Calculated checks — a check of other checks, letting you build one health signal that represents an entire application made of multiple components.
Exam tip: the 18% threshold
Route 53 aggregates results across every health checker assigned to a check. If more than 18% report an endpoint as healthy, Route 53 considers the overall check healthy — 18% or fewer, and it's unhealthy. In most configurations, records tied to an unhealthy check are simply not returned in query responses.

Other useful knobs: a failure threshold (how many consecutive checks must pass/fail before the status flips, giving you a buffer against one-off blips), the ability to invert a check's result, and the ability to temporarily disable a check (useful during planned maintenance — the resource is then always treated as healthy). Health check state changes can also trigger a CloudWatch alarm, which can notify an SNS topic.

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. Out of a health check's globally distributed checkers, exactly 18% report the endpoint as healthy. Is the overall health check status healthy or unhealthy?

2. You want a health check that reflects the status of an application made up of several sub-components, each already individually health-checked. What check type fits?

3. You need the most accurate health check possible — verifying not just that the server responds, but that the response body contains expected application content. Which check type do you use?

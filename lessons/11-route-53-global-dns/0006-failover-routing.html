Route 53 & Global DNS

Failover Routing

Lesson 06 of 13 · ~4 min

Source: Adrian Cantrill SAA-C03 · Creating Amazon Route 53 Health Checks (Failover)

Failover routing is the first routing policy this module covers that actually uses health checks. It implements classic active-passive failover: one primary resource, one secondary, and DNS switches between them based on health.

How It Works

A record name (e.g. www) gets two records of that same name — one marked primary, one marked secondary — each pointing at a different resource. A common pattern: primary = an EC2 instance running the live application, secondary = a static S3-hosted "sorry, we're down" page.

A health check attaches to the primary record. While the primary is healthy, every query for www resolves to the primary's value. The moment the primary fails its health check, Route 53 starts returning the secondary's value instead — automatically, with no other configuration needed.

Exam tip
Failover routing is for exactly one relationship: one primary, one secondary, active-passive. If you need many interchangeable resources all actively serving traffic, that's multivalue or weighted routing (next lessons) — not failover.

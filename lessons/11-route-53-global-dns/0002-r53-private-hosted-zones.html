Route 53 Private Hosted Zones

Lesson 02 of 13 · ~6 min

Source: Adrian Cantrill SAA-C03 · Working with Private Hosted Zones

A private hosted zone works exactly like a public one — same records, same resolver mechanics — except it's never reachable from the public internet. It's only accessible from the specific VPCs you associate with it, using the Route 53 resolver at each VPC's base +2 address.

Exam tip
Two things must both be true to resolve a private hosted zone: the service doing the query must be running inside a VPC, and that VPC must be associated with the zone. Miss either one and resolution simply fails — there's no partial access. Association can be done via console, CLI, or API within one account; cross-account association requires the CLI or API.

Why Use One

Private hosted zones are for records that are legitimate but shouldn't be exposed publicly — internal service discovery, sensitive configuration, systems that should only resolve inside your environment. A VPC that isn't associated with the zone is in exactly the same position as a random user on the public internet: no access at all.

Split-View (Split-Horizon) DNS

A powerful pattern combines both zone types under the same domain name: a private hosted zone for animalsforlife.org associated with an internal VPC, and a separate public hosted zone, also for animalsforlife.org, containing only a subset of records.

The result: internal users resolving animalsforlife.org from inside the associated VPC see the full private record set (e.g. an internal accounting system). External users on the public internet, walking the tree through the .org TLD servers, only ever reach the public zone — anything private-only, like that accounting record, is simply invisible to them.

Same name, different answers
Split-view DNS is exactly why a company can run its intranet and public website on the same domain name — the private zone answers for internal clients, the public zone answers for everyone else, and neither one knows the other exists.

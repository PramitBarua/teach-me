Route 53 & Global DNS

Geolocation Routing

Lesson 10 of 13 · ~6 min

Source: Adrian Cantrill SAA-C03 · Choosing a Routing Policy

The single most important thing to internalize about geolocation routing, repeated because it's tested so often: it is not about proximity. It's about matching a user's location to a record's tagged location — and if nothing matches, you can get no answer at all, even if a "closer" record exists elsewhere.

How Records Get Tagged

Records are tagged with one of:

  • Subdivision — a US state (the most specific level available)
  • Country — using ISO country codes
  • Continent — using ISO continent codes (e.g. SA for South America)
  • Default — a catch-all, optional

The Matching Order

When a query comes in, Route 53 determines the user's location (via IP lookup) and checks for a match in this strict order, stopping at the first match:

  1. Is there a record for the user's specific subdivision (state)? (US users only)
  2. If not, is there a record for the user's country?
  3. If not, is there a record for the user's continent?
  4. If none of those match, is there a default record?
  5. If nothing matches at all — no answer is returned.
The trap: no answer, not the nearest answer
A user in the UK with only a Canadian record available in the zone gets nothing — not the Canadian record, even though it might be the "closest" one geographically. Geolocation only returns records that are explicitly relevant to the user's actual tagged location, never a fallback based on proximity.

Use Cases

Geolocation is the right tool when you need to restrict or tailor content by location — serving content only to a specific market, presenting language-specific variants, or complying with data-residency-style requirements. It's about where the user legally/logically belongs, not about which server is fastest to reach.

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. A hosted zone has geolocation records tagged only for "Canada" and "Australia" (no default record). A user in the UK queries the record. What's returned?

2. Records exist for "California" (subdivision), "US" (country), and "North America" (continent). A user in Texas queries the record. Which is returned?

3. A media company wants to serve a specific licensed video only to users physically located in the US, and something else to everyone else. Which routing policy fits, and why?

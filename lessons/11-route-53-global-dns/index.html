Route 53 & Global DNS

Route 53 & Global DNS

13 lessons · ~80 min total

Source: Adrian Cantrill SAA-C03 · Amazon Route 53 Developer Guide

This module covers Route 53 end to end: how hosted zones work (public and private), the CNAME/alias distinction, every routing policy from simple through geoproximity, interoperability with third-party registrars, and DNSSEC. Routing policies are the highest-yield exam territory here — six distinct policies that are easy to confuse under time pressure.

# Lesson Key idea
01 Public Hosted Zones Four allocated name servers, globally resilient, walking the tree from DNS root to TLD to Route 53
02 Private Hosted Zones VPC-only resolution, association requirement, split-view (split-horizon) DNS
03 CNAME vs. Route 53 Alias CNAME can't be used at the zone apex; alias records can, and are free for AWS resource queries
04 Simple Routing Default policy, multiple values per name, the only policy with no health check support
05 Route 53 Health Checks TCP/HTTP/HTTP+string checks, endpoint/CloudWatch/calculated types, the 18% healthy threshold
06 Failover Routing Active-passive: primary + secondary, health check on the primary drives the switch
07 Multi-Value Routing Active-active: up to 8 healthy records returned at random, unhealthy ones excluded
08 Weighted Routing Record weight ÷ total weight; weight 0 = never returned; canary/A-B testing use case
09 Latency-Based Routing Routes to the Region with lowest estimated latency, using AWS's background latency database
10 Geolocation Routing Matches user location to tagged records (subdivision → country → continent → default); no match can mean no answer
11 Geoproximity Routing Pure distance-based routing, adjustable per-resource with a bias value
12 Route 53 Interoperability Registrar vs. hosting as two separable jobs; mixing Route 53 with third-party providers
13 Implementing DNSSEC KSK (KMS, us-east-1) vs. ZSK (Route 53-internal); DS record in the parent zone completes the chain of trust
Exam scope
The single highest-yield cluster is telling latency, geolocation, and geoproximity routing apart under scenario pressure — latency optimizes for estimated performance, geolocation matches by tagged location and can return no answer, geoproximity is pure distance with an adjustable bias. Also worth locking in: the CNAME-can't-be-used-at-the-apex rule (Lesson 03), and the 18% healthy-checker threshold (Lesson 05).

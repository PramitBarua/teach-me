Simple Routing

Lesson 04 of 13 · ~4 min

Source: Adrian Cantrill SAA-C03 · Choosing a Routing Policy

Route 53 supports several routing policies — different strategies for deciding what to return when a record is queried. Simple routing is the default and, as the name says, the simplest. The next several lessons cover each of the others in turn.

How It Works

With simple routing, one record name (e.g. www) can hold multiple values. A client query returns all of those values, in random order, and the client picks one itself to connect to.

The one thing simple routing can't do
Simple routing is the only Route 53 routing policy with no health check support. It has no idea whether the resource behind a returned value is actually up — every other routing policy covered in this module supports health checks in some form.

Use simple routing when you're pointing at a single service — one web server, one endpoint — and don't need intelligent routing or failure awareness. For anything where availability or performance-based routing matters, you'll want one of the other policies.

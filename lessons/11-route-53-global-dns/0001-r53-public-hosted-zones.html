Route 53 & Global DNS

Route 53 Public Hosted Zones

Lesson 01 of 13 · ~7 min

Source: Adrian Cantrill SAA-C03 · Working with Public Hosted Zones

A hosted zone is a DNS database for one section of the global DNS namespace — say, animalsforlife.org. Route 53 supports two kinds: public and private. This lesson covers public hosted zones; the next covers private.

Globally Resilient by Design

Route 53's name servers are distributed globally, all serving the same dataset — so an outage affecting a whole AWS Region doesn't stop Route 53 from functioning. Hosted zones are created automatically when you register a domain through Route 53, or you can create one separately to host a domain registered elsewhere. There's a monthly fee per hosted zone, plus a small per-query charge.

How a Public Hosted Zone Is Structured

Creating a public hosted zone allocates four Route 53 name servers, and it's on those servers that the zone file lives. Inside the zone, you create resource records — A/AAAA, MX, NS, TXT, and so on. The zone is accessible two ways:

  • From the public internet, via those four name servers.
  • From inside a VPC, via the Route 53 resolver at the VPC's base +2 address — as long as DNS resolution is enabled for that VPC.
Exam tip: walking the tree
A public query for animalsforlife.org doesn't go straight to Route 53. It starts at the DNS root servers, which point to the .org top-level-domain servers, which hold an entry for animalsforlife.org pointing at the four Route 53 name servers for that zone — only then does Route 53 actually answer. This delegation chain is called walking the tree, and it's how any public host resolves records inside your hosted zone.

To integrate an externally-registered domain with Route 53, you create the public hosted zone in Route 53 to get its four name servers, then update the name server (NS) records for that domain at your registrar (Hover, GoDaddy, etc.) to point at them — covered in more depth in the interoperability lesson later in this module.

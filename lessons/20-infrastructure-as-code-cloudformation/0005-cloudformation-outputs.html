CloudFormation Outputs

Lesson 05 of 17 · ~5 min

Source: Adrian Cantrill SAA-C03 · CloudFormation template Outputs syntax · Fn::Join

The Outputs section of a template is entirely optional — plenty of valid templates skip it. When you do include one, it lets you declare values that surface once a stack reaches create complete: visible in the CLI, visible in the console, and — this is the part that matters most — readable by a parent stack when this template is nested inside another. Outputs can also be exported for cross-stack references, a mechanism a later lesson covers in full; for now, keep this one simple.

Declaring an Output

An output has a logical name, and under it, two key fields you'll use constantly:

Description
A human-readable string. Visible from the CLI and console, and passed up to a parent stack when nesting is used. Always worth writing — it's what makes the output meaningful to someone who never saw the template.
Value
The actual thing being exposed. It can be a literal, a parameter reference, or — as in the example below — the result of an intrinsic function.

Here's a template provisioning an EC2 instance running WordPress, with an output that hands back a ready-to-click URL:

Outputs:
  WordPressURL:
    Description: URL for the WordPress installation
    Value: !Join ["", ["https://", !GetAtt WebServer.PublicDnsName]]

Fn::Join (shorthand !Join) concatenates the literal string https:// with the PublicDnsName attribute of the WebServer logical resource. Once the stack completes, the WordPressURL output resolves to something like https://ec2-1-2-3-4.compute-1.amazonaws.com — a working link straight to the service the stack just built, with no manual lookup required.

Why bother with outputs at all
Anything a user of the template would otherwise have to hunt for in the console — a load balancer's DNS name, a bucket name, an API endpoint — is a good candidate for an output. It turns "go find the thing this stack made" into "read the thing this stack made."
Stale vs. current: a newer way to read outputs across stacks
The transcript defers cross-stack referencing to a later lesson, and the classic mechanism — declaring an Export under an output, then reading it elsewhere with Fn::ImportValue — still works exactly as taught. Since recording, though, AWS added Fn::GetStackOutput, which lets a template read another stack's output directly, including across accounts and Regions, without that stack needing an explicit Export declaration at all. It's a genuinely newer option, not a replacement you need to worry about yet — the Export/ImportValue pattern remains the one this course teaches and the one you'll see most often.

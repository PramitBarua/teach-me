Change Sets

Lesson 16 of 17 · ~8 min

Source: Adrian Cantrill SAA-C03 · Updating stacks using change sets · Generate templates with the IaC generator

Updating a CloudFormation stack directly is a bit of a leap of faith — you apply a new template version and CloudFormation just does whatever it decides that implies. Change sets let you preview that decision first.

Three Ways an Update Can Land

When a stack update changes a logical resource, the resulting physical-resource impact is one of three things:

  • No interruption — the change applies with no effect on the running resource
  • Some interruption — for example, an EC2 instance reboots; disruptive but not destructive
  • Replacement — the physical resource is destroyed and a new one created in its place, which can mean real data loss

None of that is visible up front if you just update the stack directly and hope for the best.

The Direct-Update Risk

Picture a template that creates three S3 buckets: catpix, dogpix, and memes. You use it to create a stack — three buckets exist. Now you decide the memes bucket was a mistake, remove it from the template, and update the stack directly. CloudFormation removes the logical resource, and the physical bucket, along with it — immediately, no confirmation step.

What a Change Set Actually Is

Instead of updating the stack directly, you submit the new template as a change set — a distinct object representing the delta between the stack's current template and the proposed one. Creating a change set does not touch any physical resource; it's purely a comparison. You can create several change sets against the same stack, review each one, and discard whichever you don't want.

A change set lists every detected change: an Action like Remove, against a logical ID and its corresponding physical ID. You can inspect the template inside the change set, and view a JSON list of exactly what changed — one entry per affected resource. That's a genuinely reviewable artifact, the kind that fits into a formal change-management process.

When you're satisfied, you execute the chosen change set — this runs the same update-stack operation as a direct update, with the same underlying effect, but only after you've had full visibility into what's about to happen.

A change set isn't a guarantee
A change set shows you what CloudFormation intends to do — it doesn't guarantee the update will succeed. It won't catch things like breaching an account service limit, updating a property that doesn't actually support in-place updates, or an IAM permission gap. Those can still fail the update after execution.
Change sets show up again later in the course
Change sets aren't only for previewing edits to a stack you already manage. Importing existing, unmanaged resources into a stack is also implemented as a change set — created with ChangeSetType=IMPORT — and the newer IaC generator feature can scan your account's existing resources and auto-generate both a template and the import change set for you. Same underlying mechanism, a different use case.

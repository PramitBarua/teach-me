Infrastructure as Code (CloudFormation)

Infrastructure as Code (CloudFormation)

17 lessons · ~133 min total

Source: Adrian Cantrill SAA-C03 · AWS CloudFormation User Guide

This module covers CloudFormation end to end: the physical/logical resource model that underpins everything else, the portability toolkit (parameters, pseudo parameters, intrinsic functions, mappings), the template features that control what gets built and when (outputs, conditions, DependsOn, wait conditions/CreationPolicy), the two multi-stack architectures the exam loves to contrast (nested stacks vs. cross-stack references), account/region-scale deployment (StackSets), safety mechanisms for production use (deletion policies, stack roles, change sets), and the two ways to extend CloudFormation beyond its native reach (cfn-init/cfn-hup for EC2 configuration, custom resources for everything else).

# Lesson Key idea

03Intrinsic FunctionsRef/Fn::GetAtt, Fn::GetAZs/Fn::Select, Fn::Join/Fn::Split, Fn::Base64/Fn::Sub, Fn::Cidr — runtime data access that makes templates portable
04MappingsStatic key-value lookup tables (e.g. region → AMI ID) queried via Fn::FindInMap
05CloudFormation OutputsOptional, visible from CLI/console, returned to parent stacks when nested, and exportable for cross-stack references
06CloudFormation ConditionsEvaluated before resources; a resource with a false condition simply isn't created — the dev/prod and multi-AZ-count exam patterns
07DependsOnCloudFormation infers dependencies from references, but the Elastic IP ↔ Internet Gateway Attachment gap needs an explicit DependsOn
08Wait Conditions and cfn-signalBootstrapping finishing ≠ EC2 reporting complete; CreationPolicy (preferred, resource-attached) vs. WaitCondition (standalone, external-system-friendly)
09Nested StacksReuse the template, not the resource — every reuse creates a fresh physical copy; use when everything is lifecycle-linked
10Cross-Stack ReferencesReuse the actual resource via Export + Fn::ImportValue; use for shared services with independent lifecycles, same region/account only
11Stack SetsAdmin account → stack instances → stacks across many target accounts/regions; concurrent-accounts and failure-tolerance control the rollout
12Deletion PolicyDelete (default) / Retain / Snapshot (EBS, ElastiCache, Neptune, RDS, Redshift only) — applies to deletions only, never to replacement
13Stack RolesRole separation: an identity can create/update a stack via a passed role without ever holding the underlying resource permissions itself
14CloudFormation Init (cfn-init)Desired-state, idempotent, cross-platform alternative to procedural user data; config keys bundled into config sets

16Change SetsPreview no-interruption/interruption/replacement impacts before committing; execute only when the diff looks right

Exam scope
The single decision point the course diagrams themselves flag as exam-critical is nested stacks vs. cross-stack references (Lessons 09–10): nested stacks reuse a template (each use creates a brand-new physical resource, so only use this when everything is lifecycle-linked), while cross-stack references reuse an actual resource via Export/Fn::ImportValue (for shared services with independent, service-oriented lifecycles — same region and account only, no exceptions). Beyond that pairing, know DependsOn's classic Elastic-IP-needs-an-attached-Internet-Gateway trap (Lesson 07), that DeletionPolicy never applies to replacement (Lesson 12), and that CreationPolicy is AWS's recommended default over WaitCondition for EC2/ASG (Lesson 08).
Several features have grown since this course was recorded
Each lesson flags its own specifics inline, but at a glance: Fn::ForEach, Fn::Length, and Fn::ToJsonString are newer intrinsic functions under the AWS::LanguageExtensions transform (Lesson 03); CloudFormation can now reverse-generate a template from existing unmanaged resources via the IaC generator (Lesson 01, also behind Lesson 16's change-set-based resource import); StackSets gained a ConcurrencyMode switch decoupling concurrency from failure tolerance (Lesson 11); UpdateReplacePolicy now exists specifically to cover the replacement-triggered gap DeletionPolicy leaves open (Lesson 12); and CloudFormation Hooks (Lesson 17) offer proactive, pre-provisioning validation as a newer complement to custom resources' reactive extension model.

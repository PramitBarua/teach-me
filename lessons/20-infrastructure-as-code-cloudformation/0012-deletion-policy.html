Deletion Policy

Lesson 12 of 17 · ~7 min

Source: Adrian Cantrill SAA-C03 · DeletionPolicy attribute · UpdateReplacePolicy attribute

When a logical resource is removed from a template and the stack is updated — or when the whole stack is deleted — CloudFormation's default behavior is to delete the corresponding physical resource. For some resource types that's harmless. For an RDS database or an EBS volume, it means real data loss. DeletionPolicy is the per-resource attribute that controls what actually happens.

The Three Options

Delete (default)
CloudFormation removes the physical resource when the logical resource is deleted. This is what happens if you set no policy at all.
Retain
CloudFormation leaves the physical resource in place. Set every resource in a stack to Retain, and deleting the whole stack removes nothing — every resource survives in the account.
Snapshot
Only available for a smaller subset of resource types — EBS volumes, ElastiCache, Neptune, RDS, and Redshift. Before deleting the physical resource, CloudFormation takes a snapshot of it first.
Resources:
  AppDatabase:
    Type: AWS::RDS::DBInstance
    DeletionPolicy: Snapshot
    Properties:
      # ...
Snapshots outlive the stack — and cost money
A snapshot taken under a Snapshot deletion policy is not deleted when the stack is deleted, or ever cleaned up automatically. It's your responsibility to manage and eventually remove it, and until you do, it keeps incurring storage cost. Also remember: Snapshot is not supported for EC2 instances — only for the resource types listed above.

The Gap: Replacement Is Not Deletion

DeletionPolicy only fires on deletion-style operations — removing a logical resource and updating the stack, or deleting the stack outright. But some property changes cause CloudFormation to replace a resource: it creates a new physical resource, repoints dependents at it, and then deletes the old one — effectively a delete-and-recreate. DeletionPolicy does not apply to that old resource during a replacement, so a subtle template change can quietly destroy data that a DeletionPolicy of Retain or Snapshot would otherwise have protected.

Stale-vs-current: that gap now has a fix
AWS has since added UpdateReplacePolicy, an attribute that sits alongside DeletionPolicy on a resource and applies specifically to the old physical resource during a replacement update — the exact gap the transcript describes as unhandled. It accepts the same style of values (Retain, and Snapshot for resources that support it), letting you protect a resource from an update-triggered replacement the same way DeletionPolicy protects it from an outright deletion. For the exam, know both attributes exist and cover two distinct triggers: DeletionPolicy for delete operations, UpdateReplacePolicy for replacement operations.

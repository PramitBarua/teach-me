EC2 Dedicated Hosts

Lesson 07 of 08 · ~7 min

Source: Adrian Cantrill SAA-C03 · EC2 Dedicated Hosts

A Dedicated Host is a physical EC2 server allocated entirely to your account. You pay for the whole host — not per instance — and every instance you run on it after that is free of additional EC2 instance charges. The narrow but important reason this exists: software licensing.

Why Pay for the Whole Host

Some enterprise software licenses by physical socket or physical core, regardless of how much of that hardware any one instance actually uses. Run that software on a small standard instance and you could still be on the hook for licensing the entire underlying host's hardware — hardware you can't otherwise access. Dedicated Hosts make that visible and billable directly: you pay for the host (On-Demand, or 1/3-year reservations with the same upfront-payment options as Reserved Instances), and license against it, with no separate per-instance fees layered on top.

Fixed Sizing vs. Nitro Flexibility

A host is built for one specific instance family, with a fixed number of physical sockets and cores — and that determines how many instances of what size can run on it.

Host typeSizing flexibility
Older / non-Nitro (e.g. A1: 1 socket, 16 cores)Fixed at creation to one instance size — e.g. 16 × medium, or 8 × large, or 4 × xlarge — no mixing
Nitro-based (e.g. R5: 2 sockets, 48 cores)Mix instance sizes freely up to the core limit — e.g. 1×12xlarge + 2×2xlarge + 1×4xlarge on the same host
Exam tip
You just need to know Dedicated Hosts exist, the licensing rationale, and the fixed-size-vs-Nitro-flexible distinction. You won't need exact core counts or per-family pricing for the associate exam.

Limitations

  • AMI restrictions — RHEL, SUSE Linux, and Windows AMIs are not supported on Dedicated Hosts.
  • No Amazon RDS — RDS instances can't run on a Dedicated Host.
  • No placement groups — placement groups aren't supported in combination with Dedicated Hosts.

Sharing Within an Organization

A Dedicated Host can be shared with other accounts in your AWS Organization via AWS Resource Access Manager (RAM). The owning account sees every instance running on the host; each account the host is shared with can only see and control the instances it created — a clean visibility and control boundary even though the underlying hardware is shared.

Narrow use case
In most real-world situations, Dedicated Hosts are not the default choice for running EC2 — they trade away flexibility (fixed family, fixed or semi-fixed sizing) for something you only need if licensing constraints require visibility into physical sockets/cores.

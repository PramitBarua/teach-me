      Scenario 1

      A fleet of Linux EC2 instances spans 3 Availability Zones and all need to read and write the same set of files, with access continuing uninterrupted even if any single AZ fails. What should be configured?

      • A. A shared EBS volume attached to every instance across all 3 AZs
      • B. An EFS file system with one mount target in each of the 3 Availability Zones
      • C. An EFS file system with a single mount target placed in the AZ with the most instances
      • D. A single Region-wide EFS endpoint with no per-AZ configuration

      Topic: EFS Architecture

      Correct answer: B

      • A. Wrong — EBS volumes attach to a single instance in a single AZ; they can't be mounted by multiple instances across AZs the way EFS can.
      • B. Correct — mount targets are AZ-scoped ENIs, so one mount target per AZ (the same HA pattern as NAT Gateways) ensures instances in every AZ keep access if any single AZ fails.
      • C. Wrong — a single mount target in one AZ means instances in the other two AZs lose access if that AZ fails; this doesn't provide the required resilience.
      • D. Wrong — EFS mount targets are placed per-AZ inside the VPC; there's no single Region-wide endpoint that bypasses this architecture.

      Scenario 2

      A WordPress-style application currently stores user-uploaded media on each instance's local disk. The team wants instances to become disposable — replaceable without losing any uploaded media, with every instance in the fleet seeing the same files. What should replace local disk storage?

      • A. A larger EBS volume attached to each instance individually
      • B. Instance store volumes, since they offer the highest local throughput
      • C. An EFS file system mounted by every instance in the fleet
      • D. A snapshot schedule that backs up local disk every hour

      Topic: EFS Architecture

      Correct answer: C

      • A. Wrong — a larger EBS volume is still block storage tied to one instance; it doesn't let multiple instances share files or survive instance replacement.
      • B. Wrong — instance store is ephemeral and tied even more tightly to the instance's own lifecycle than EBS; it makes the disposability problem worse, not better.
      • C. Correct — moving media onto EFS makes instances closer to stateless: the file system lives outside any one instance, is mountable by many instances at once, and survives instance replacement.
      • D. Wrong — scheduled snapshots protect against data loss but don't let multiple instances share live files or make an individual instance disposable without a restore step.

      Scenario 3

      A big-data analytics workload runs highly parallel jobs across many EC2 instances simultaneously reading and writing to a shared EFS file system, prioritizing maximum aggregate throughput and tolerating some added per-operation latency. Which performance mode fits?

      • A. General Purpose, since it is the default and requires no configuration
      • B. Provisioned throughput mode, since it removes latency entirely
      • C. Bursting performance mode, since it is designed for parallel access
      • D. Max I/O, since it scales to higher aggregate throughput and operations-per-second for parallel workloads

      Topic: EFS Architecture

      Correct answer: D

      • A. Wrong — General Purpose is optimized for latency-sensitive workloads like web serving, not for maximizing aggregate throughput under heavy parallelism.
      • B. Wrong — Provisioned is a throughput mode (bandwidth independent of file system size), not a performance mode, and it doesn't eliminate latency.
      • C. Wrong — Bursting is a throughput mode, not a performance mode; EFS's two performance modes are General Purpose and Max I/O.
      • D. Correct — Max I/O scales to higher aggregate throughput and operations-per-second for highly parallel workloads, trading off some increased per-operation latency, exactly matching this scenario.

      Scenario 4

      An application's I/O needs are unpredictable — mostly idle, with occasional bursts — and the team wants throughput to scale automatically with file system size rather than provisioning a fixed rate. Which EFS throughput mode fits, and what's its EBS analog?

      • A. Provisioned, the same trade-off as EBS io1
      • B. Max I/O, the same trade-off as EBS st1
      • C. Bursting, the same trade-off as EBS gp2
      • D. General Purpose, the same trade-off as EBS sc1

      Topic: EFS Architecture

      Correct answer: C

      • A. Wrong — Provisioned throughput sets a rate independent of file system size, the opposite of the size-scaling, auto-bursting behavior this scenario wants.
      • B. Wrong — Max I/O is a performance mode, not a throughput mode, and st1 isn't the analog being drawn here.
      • C. Correct — Bursting throughput scales with file system size with a burst pool for spikes, the same trade-off as EBS gp2, matching this unpredictable, mostly-idle-with-bursts pattern.
      • D. Wrong — General Purpose is a performance mode, not a throughput mode; it doesn't describe how throughput scales with size.

      Scenario 5

      A team wants archival files on EFS to automatically move to a lower-cost storage tier as they age out of frequent use, without manually tracking and moving each file. What should they configure?

      • A. A lifecycle policy transitioning files to the Infrequent Access storage class based on access patterns
      • B. Max I/O performance mode, since it automatically archives cold data
      • C. Bursting throughput mode, since it reduces per-GB storage cost over time
      • D. The Standard storage class only, since it already minimizes cost for all access patterns

      Topic: EFS Architecture

      Correct answer: A

      • A. Correct — mirroring S3, EFS lifecycle policies automatically transition files between Standard and Infrequent Access based on access patterns, exactly this hands-off cost optimization.
      • B. Wrong — Max I/O is a performance mode for parallel throughput; it has no relationship to storage cost or automatic data movement.
      • C. Wrong — Bursting is a throughput mode governing bandwidth scaling; it doesn't affect per-GB storage cost or move data between classes.
      • D. Wrong — Standard is the default class for frequently accessed files and costs more than Infrequent Access; it doesn't minimize cost for rarely-touched archival data.

      Scenario 6

      A design calls for a shared file system mountable by a fleet of Windows EC2 instances. A junior engineer proposes EFS. Is this a valid choice?

      • A. No, EFS is officially supported for Linux instances only; FSx is the correct direction for Windows
      • B. Yes, EFS supports Windows and Linux instances equally
      • C. Yes, but only if the file system uses the Max I/O performance mode
      • D. No, because EFS only supports single-instance mounting regardless of OS

      Topic: EFS Architecture

      Correct answer: A

      • A. Correct — EFS explicitly targets Linux only; a scenario describing Windows instances needing shared file storage should point toward FSx instead.
      • B. Wrong — EFS is officially supported for Linux instances only; it isn't a cross-platform match for Windows workloads.
      • C. Wrong — performance mode selection has nothing to do with OS compatibility; EFS's Linux-only scope isn't affected by which performance mode is chosen.
      • D. Wrong — EFS explicitly supports simultaneous multi-instance mounting; the actual limitation here is OS support, not mount concurrency.

      Scenario 7

      An on-premises data center needs to mount the same EFS file system that EC2 instances inside a VPC already use, for a hybrid migration project. What must be in place, given that EFS is a private, VPC-scoped service by default?

      • A. Nothing extra; EFS is reachable from the public internet by default
      • B. A second, independent EFS file system replicated automatically to on-premises
      • C. Hybrid networking such as a VPN connection, AWS Direct Connect, or VPC peering into the VPC
      • D. Switching the file system's performance mode to Max I/O to enable external access

      Topic: EFS Architecture

      Correct answer: C

      • A. Wrong — EFS is VPC-scoped and not reachable from the public internet by default; some hybrid connectivity path is required.
      • B. Wrong — EFS doesn't offer an automatic on-premises replication feature; on-premises access works by reaching into the existing VPC-based file system, not by duplicating it.
      • C. Correct — because EFS is VPC-scoped, access from outside the VPC (like an on-premises data center) requires hybrid networking: VPC peering, a VPN connection, or Direct Connect.
      • D. Wrong — performance mode governs throughput/latency characteristics, not network reachability from outside the VPC.

      Scenario 8

      A team migrating a legacy Linux application to EFS needs the exact same file permission model (owners, groups, read/write/execute bits) their application already relies on. Does EFS support this out of the box?

      • A. No, EFS requires rewriting all permission logic using IAM policies instead
      • B. Yes, EFS file systems use POSIX permissions, the standard model every Linux distribution understands
      • C. No, EFS only supports read-only access with no per-user permission granularity
      • D. Yes, but only for files stored in the Infrequent Access storage class

      Topic: EFS Architecture

      Correct answer: B

      • A. Wrong — EFS doesn't require replacing file permissions with IAM policies; it natively uses the standard Linux permission model.
      • B. Correct — EFS file systems use POSIX permissions, the standard permission model every Linux distribution understands, so existing owner/group/mode-bit logic carries over directly.
      • C. Wrong — EFS supports normal read/write access with full POSIX-style per-user and per-group permissions, not just read-only.
      • D. Wrong — POSIX permission support isn't tied to a specific storage class; it applies to the file system regardless of Standard or Infrequent Access.

      Scenario 9

      A company runs RDS, DynamoDB, EFS, and EBS-backed EC2 instances, and currently manages backups for each with separate tools and manual scripts. What does AWS Backup offer that directly addresses this?

      • A. A requirement to migrate all databases onto self-managed EC2 instances first
      • B. Automatic migration of DynamoDB data into RDS to simplify backup handling
      • C. A managed VPN tunnel connecting all resources needing backup
      • D. Centralized management and storage of backups across all of these services in one place

      Topic: AWS Backup

      Correct answer: D

      • A. Wrong — AWS Backup works with existing managed services like RDS and DynamoDB directly; it doesn't require replacing them with self-managed EC2 instances.
      • B. Wrong — AWS Backup doesn't migrate data between service types; it centrally manages backups for each service as it already exists.
      • C. Wrong — AWS Backup is a data protection and backup consolidation service, not a network connectivity or VPN product.
      • D. Correct — AWS Backup's core value is consolidating backup storage and configuration for many AWS services into one central place, exactly resolving this fragmented-tooling problem.

      Scenario 10

      A financial services company must guarantee that backups cannot be deleted by anyone at all — not their own administrators, not even AWS — to satisfy a strict compliance requirement. What should they configure?

      • A. A default read/write vault, since backups are protected automatically once created
      • B. A shorter backup window, to reduce the time backups are exposed to deletion risk
      • C. Cross-Region copy alone, so a second copy of every backup always exists
      • D. AWS Backup Vault Lock, enabling WORM mode on the vault

      Topic: AWS Backup

      Correct answer: D

      • A. Wrong — vaults are read/write by default, meaning backups inside them can be deleted unless Vault Lock is specifically enabled.
      • B. Wrong — the backup window controls when a backup job starts and how long it runs; it has no effect on whether a stored backup can later be deleted.
      • C. Wrong — a cross-Region copy protects against Regional failure, but the copied backup in the destination vault remains deletable unless that vault also has Vault Lock enabled.
      • D. Correct — Vault Lock switches a vault to WORM mode; after the cool-off period, nobody, including AWS, can delete anything from it, which is exactly what this compliance requirement demands.

      Scenario 11

      An administrator enables AWS Backup Vault Lock on a vault at 9:00 AM Monday and immediately tries to delete an existing backup from it at 10:00 AM the same day. What happens?

      • A. The deletion succeeds, since Vault Lock is still within its 72-hour cool-off period and not yet fully active
      • B. The deletion is blocked immediately, since Vault Lock takes effect the instant it's enabled
      • C. The deletion fails only because the backup hasn't yet reached cold storage
      • D. The deletion is queued and automatically applied once the cool-off period ends

      Topic: AWS Backup

      Correct answer: A

      • A. Correct — there's a 72-hour cool-off period after enabling Vault Lock before it's fully active; a deletion attempted just one hour in would still succeed, since immutability hasn't taken hold yet.
      • B. Wrong — Vault Lock doesn't take effect the instant it's enabled; there's a 72-hour cool-off period before it becomes fully active.
      • C. Wrong — cold storage transition timing is unrelated to Vault Lock's cool-off period; the relevant blocker here is simply that the cool-off hasn't elapsed.
      • D. Wrong — AWS Backup doesn't queue a deletion request to auto-apply later; the deletion either succeeds now (pre-lock) or is permanently blocked once WORM mode is fully active.

      Scenario 12

      A backup plan transitions backups to cold storage after 20 days and is configured to expire (delete) them after 60 days total. Does this configuration satisfy AWS Backup's rules for cold storage retention?

      • A. Yes, since 60 days of total retention is well beyond any minimum AWS Backup enforces
      • B. No, because a backup must wait at least 30 days before transitioning to cold storage at all
      • C. No, because a backup must remain in cold storage at least 90 days before it can expire — 20+60 doesn't satisfy that
      • D. Yes, as long as Vault Lock is also enabled on the destination vault

      Topic: AWS Backup

      Correct answer: C

      • A. Wrong — total retention length alone isn't the rule; the constraint specifically governs how long a backup must stay in cold storage before expiring, which this plan violates (60 - 20 = 40 days in cold storage, short of 90).
      • B. Wrong — there's no 30-day minimum before transitioning to cold storage; the actual rule is a 90-day minimum stay once a backup is already in cold storage.
      • C. Correct — once a backup moves to cold storage, it must stay there at least 90 days before it can expire; this plan's 40 days in cold storage (20 to transition, 60 total) falls short of that minimum.
      • D. Wrong — Vault Lock governs whether backups can be deleted at all, not the cold-storage minimum-stay rule, and enabling it doesn't override that separate constraint.

      Scenario 13

      A compliance officer assumes that enabling AWS Backup Vault Lock on a backup vault also automatically enables S3 Object Lock on any S3 buckets the company owns. Is this assumption correct?

      • A. Yes, all AWS WORM features share a single account-wide toggle
      • B. No, AWS Backup Vault Lock, S3 Object Lock, and Glacier Vault Lock are distinct features on distinct services, despite sharing the same WORM idea
      • C. Yes, but only for buckets already referenced in an active backup plan
      • D. No, because S3 Object Lock was fully replaced by AWS Backup Vault Lock

      Topic: AWS Backup

      Correct answer: B

      • A. Wrong — there's no single account-wide WORM toggle; each of these features is configured independently on its own service.
      • B. Correct — all three implement the same WORM idea, but they are distinct features on distinct services; configuring one does not configure the others.
      • C. Wrong — being referenced in a backup plan doesn't cause S3 Object Lock to be enabled on a bucket; that's a separate, manually configured S3 feature.
      • D. Wrong — S3 Object Lock is still its own distinct, actively used feature; it hasn't been replaced by AWS Backup Vault Lock.

      Scenario 14

      An operations team needs backups to run every 12 hours on a fine-grained schedule that a simple daily/weekly/monthly picker can't express. What should they configure within a Backup Plan?

      • A. A cron expression, for finer scheduling control down to hourly frequency
      • B. Multiple overlapping backup vaults, one per desired time slot
      • C. An on-demand backup triggered manually every 12 hours by a script
      • D. A weekly plan configured to repeat twice within the same day

      Topic: AWS Backup

      Correct answer: A

      • A. Correct — Backup Plans support a cron expression for finer scheduling control, as frequently as hourly, covering exactly this 12-hour cadence need.
      • B. Wrong — vaults are storage destinations for backup data, not a scheduling mechanism; creating more of them doesn't control backup frequency.
      • C. Wrong — while on-demand backups exist for manual, outside-of-plan triggers, relying on a script to fire every 12 hours abandons the built-in scheduling a Backup Plan already provides via cron.
      • D. Wrong — a weekly plan lets you pick specific days, not sub-daily repetition; it can't natively express a 12-hour cadence the way a cron expression can.

      Scenario 15

      Before a risky maintenance change, an engineer wants to take a one-off backup of a resource right now, entirely outside of its normally scheduled Backup Plan cadence. Does AWS Backup support this?

      • A. No, all backups must originate from a configured Backup Plan on its defined schedule
      • B. Yes, on-demand backups can be triggered manually, outside of any scheduled plan
      • C. No, a new Backup Plan with a one-time schedule must be created and then deleted afterward
      • D. Yes, but only if Vault Lock is disabled first

      Topic: AWS Backup

      Correct answer: B

      • A. Wrong — Backup Plans aren't the only way to create a backup; a manual, outside-of-plan option exists specifically for cases like this.
      • B. Correct — AWS Backup supports on-demand backups triggered manually, outside of any scheduled plan, exactly fitting a one-off pre-maintenance backup need.
      • C. Wrong — creating and then deleting a throwaway Backup Plan is unnecessary overhead; on-demand backups exist precisely to avoid this.
      • D. Wrong — on-demand backups aren't gated behind disabling Vault Lock; Vault Lock only prevents deletion, it doesn't block creating new backups.

      Scenario 16

      A company wants to restore an RDS database to its exact state at 3:14 AM last Tuesday — a specific moment in time, not just the nearest daily snapshot. What capability does this require?

      • A. Cross-account backup, since only a second account's copy supports this level of precision
      • B. A shorter backup window, so snapshots are taken closer together
      • C. AWS Backup Vault Lock, since WORM mode enables timestamp-precise restores
      • D. Point-in-time recovery, supported by RDS (and S3) for restoring to any moment within the retention window

      Topic: AWS Backup

      Correct answer: D

      • A. Wrong — cross-account backup is about which account stores the backup copy, not about restoring to an arbitrary point in time; it doesn't provide timestamp-level restore precision.
      • B. Wrong — a shorter backup window changes how often full backups run, but doesn't provide restoration to an arbitrary moment between backups the way point-in-time recovery does.
      • C. Wrong — Vault Lock is about preventing deletion (WORM), not about the granularity of what moment in time you can restore to.
      • D. Correct — some services, including S3 and RDS, support point-in-time recovery: restoring to the resource's exact state at any moment within the retention window, not just to a specific snapshot.

Network Storage & Data Lifecycle

AWS Backup

Lesson 02 of 02 · ~7 min

Source: Adrian Cantrill SAA-C03 · AWS Backup Developer Guide

Without AWS Backup, protecting data means configuring backups separately for every service: RDS snapshots in one place, DynamoDB backups in another, a script somewhere taking EBS snapshots on a schedule. AWS Backup is a fully managed data protection service that consolidates the management and storage of backups across services — and across multiple accounts and Regions — in one place.

What It Covers

AWS Backup can centrally manage backups for a wide range of services: compute (EC2, VMware running on AWS), block storage (EBS), file storage (EFS, the FSx family), most of the database products (RDS, Aurora, DynamoDB, Neptune, DocumentDB), and even object storage (S3). For each, it centrally manages both where the backup is stored and how backup and retention behave.

Cross-account operation relies on AWS Organizations and Control Tower. Backups can also be copied between Regions for extra data protection.

Core Components

Backup Plans
Where you configure how often backups run — hourly, every 12 hours, daily, weekly, monthly, or via a cron expression for finer control (as frequently as hourly). Weekly plans let you pick specific days; monthly plans let you pick a specific day of the month. Plans also set the backup window (start time and duration), the lifecycle (when a backup transitions to cold storage and when it expires), which vault to use, and optional cross-Region copy.
Backup Resources
The logical thing being backed up — an S3 bucket, an RDS database, an EBS volume.
Vaults
The destination where backup data is stored. At least one vault is required. Vaults are read/write by default, meaning backups inside them can be deleted.
Exam tip
Cold storage transitions have a 90-day minimum — once a backup moves to cold storage, it must stay there at least 90 days before it can expire or be deleted.

Vault Lock: WORM Mode

By default, anyone with permission can delete a backup from a vault. Enabling AWS Backup Vault Lock switches a vault to Write Once Read Many (WORM) mode. There's a 72-hour cool-off period after enabling it, but once fully active, nobody — including AWS itself — can delete anything from the vault. This is designed for compliance scenarios where backups must be provably tamper-proof. Retention periods you've configured still apply, so backups still age out on schedule; Vault Lock just guarantees nothing can be deleted early.

Don't confuse this
AWS Backup Vault Lock is a separate product concept from S3 Object Lock and Glacier Vault Lock. All three implement the same WORM idea, but they are distinct features on distinct services — don't assume configuring one configures the others.

On-Demand Backups and Point-in-Time Recovery

Backup Plans aren't the only way to create a backup — AWS Backup also supports on-demand backups triggered manually, outside of any scheduled plan. Separately, some services (S3 and RDS among them) support point-in-time recovery: restoring a resource to its exact state at any moment within the retention window, not just to a specific snapshot.

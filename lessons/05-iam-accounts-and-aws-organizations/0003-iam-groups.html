IAM Groups

Lesson 03 of 11 · ~8 min

What is an IAM Group?

An IAM Group is a container for IAM users. It lets you attach policies to many users at once instead of managing policies user-by-user.

Important
A group itself has no access rights. Rights exist only on the members — the group is just a convenient attachment point for policies.

Key Rules

No built-in "all users" group
AWS does not create an all-users group automatically. If you want every user to share a policy, create the group and manage it yourself.
Policies on a group
A group can have both managed and inline policies attached. Both apply to every group member.
Policy merging
When a user belongs to multiple groups, AWS merges all policies — the user's own inline and managed policies plus every group's policies — then evaluates: Explicit Deny → Explicit Allow → Implicit Deny.
Groups cannot be nested
A group cannot contain another group. Only users can be group members.
Groups cannot be a principal
You cannot reference a group in a resource-based policy's Principal field. Only users, roles, and AWS services can be principals.

Exam tip
The 10-groups-per-user limit is a hard limit — you cannot increase it. The 300-groups-per-account limit is a soft limit. Expect scenario questions testing whether you know the difference.

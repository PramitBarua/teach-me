IAM, Accounts & Orgs

Service Control Policies (SCPs)

Lesson 08 of 11 · ~10 min

Source: Adrian Cantrill SAA-C03 · AWS SCPs Docs

What is an SCP?

A Service Control Policy (SCP) is a JSON policy document attached to nodes in the AWS Organizations hierarchy. It sets the maximum permissions boundary for every account in its scope — including the account's root user.

SCPs do not grant permissions
An SCP only restricts what identities in an account can do. It never grants access by itself. An identity still needs its own IAM permissions to act — the SCP just caps the ceiling.

Where you can attach an SCP

Attachment pointScope
Org RootApplies to all OUs and all member accounts in the organisation. Does not affect the management account.
Organizational Unit (OU)Applies to all accounts directly inside that OU and any nested OUs/accounts.
Individual AccountApplies to that one account only.
The management account exception
The management account is never affected by SCPs — not even by an SCP attached to the root. This is a deliberate AWS design decision. Never use the management account for production workloads precisely because it cannot be restricted.

Deny list vs Allow list

Deny list (default)
AWS attaches a default FullAWSAccess SCP to every account. You add explicit Deny statements to block specific services. Everything not denied is permitted (as far as SCPs go).
Allow list
Remove the FullAWSAccess SCP. Attach an SCP that explicitly allows only the services you permit. Nothing is allowed unless listed. Higher admin overhead, but tighter control.

How SCP and IAM policies interact

Access is granted only when it is permitted by both the SCP and the IAM identity policy. The effective permissions = intersection of what the SCP allows and what IAM allows.

Retrieval Practice

1. An SCP attached to the Org Root denies ec2:TerminateInstances. An IAM admin in the management account tries to terminate an EC2 instance. What happens?

2. An IAM user in a member account has AdministratorAccess IAM policy. The account's SCP only allows s3:*. What can the user do?

3. In an allow-list SCP strategy, AWS attaches a default FullAWSAccess SCP. What must you do first to implement a true allow-list?

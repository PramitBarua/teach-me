IAM Users & ARNs

Lesson 02 of 11 · ~10 min

Source: Adrian Cantrill SAA-C03 · AWS IAM Users Docs

What is an IAM User?

An IAM User is an identity for long-term AWS access. Use one whenever you can picture exactly one thing — one human, one application, one service account — that needs persistent credentials.

Decision rule
"Can I name exactly one thing that will use this identity?" If yes → IAM User. If no, or if more than 5 000 users are needed → consider an IAM Role instead.

Principals and Authentication

A principal is any entity trying to access an AWS account. At first it is unauthenticated. To act, it must authenticate:

  • Human – username + password (console)
  • Application – Access Key ID + Secret Access Key (API / CLI)

These are long-term credentials. After a successful authentication AWS resolves which policies are attached and enforces them for every subsequent request.

Amazon Resource Names (ARNs)

Every AWS resource is uniquely identified by an ARN. The general format is:

arn:partition:service:region:account-id:resource-id

Example ARNWhat it identifies
arn:aws:s3:::catgifsThe S3 bucket named catgifs
arn:aws:s3:::catgifs/*Every object inside that bucket
arn:aws:iam::123456789012:user/aliceIAM user alice in account 123456789012
Omitting a segment vs using *

Leaving a segment empty (::) means it is not required for that resource type. For S3 the region and account-id are left empty because bucket names are globally unique.

Using * is a wildcard meaning all values. These are different: arn:aws:s3:::catgifs (region not required) ≠ arn:aws:ec2:*:: (all regions).

IAM User Limits

  • Maximum 5 000 IAM users per AWS account (hard limit)
  • An IAM user can belong to a maximum of 10 groups

If you need more identities (e.g. an application serving thousands of customers), use IAM Roles with federation instead.

EC2 Instance Types (Part 2)

Lesson 04 of 21 · ~6 min

Source: Adrian Cantrill SAA-C03 · AWS EC2 Instance Types

Continuing directly from Part 1: this lesson walks through representative instance families in each category so you can start building intuition about which letter maps to which kind of workload. You are not expected to memorize every family and size — the goal is a working mental map, and to know where to look up specifics when you need them.

Exam tip
Because specific families and generations change over time, treat any exact family name here as illustrative rather than gospel — always confirm current offerings against the official EC2 Instance Types documentation before relying on it in production or in a fresh exam attempt.

General purpose

Family (illustrative)Notes
ARM-based (e.g. Graviton-powered)AWS-designed ARM processors; can offer strong price/performance if your OS and application support the architecture
Burstable (e.g. T-series)Assumes low baseline CPU with a credit-based allowance for occasional bursts — cheaper than steady-state types; good for a lightly-loaded domain controller or mail relay
Steady-state (e.g. M-series, and AMD variants)Consistent, predictable CPU load — good for something like a heavily used mail server running at a steady 60% CPU

Compute optimized

More CPU per dollar than general purpose, with network-optimized variants available. Good for media encoding, scientific modeling, gaming servers, and general machine learning workloads.

Memory optimized

Ranges from standard large-memory types, up through types offering some of the highest memory allocations AWS offers, to variants that pair large memory with fast local NVMe storage. Ideal for large in-memory applications, in-memory caching, and certain database workloads.

Accelerated computing

CapabilityBest for
GPU (parallel-processing oriented)Parallel processing and machine learning training
GPU (graphics oriented)Graphics-intensive work; usable but less ideal for ML than the parallel-processing type
FPGAGenomics, financial analysis, big data — anywhere you want to program the hardware itself
ML-inference optimizedRecommendation, forecasting, voice, and conversational ML workloads

Storage optimized

Large amounts of fast local storage, tuned either toward high sequential throughput or maximum IOPS (or a balance of both, depending on the specific type). Suited to data warehousing, search workloads like Elasticsearch, and demanding analytics.

Two tools worth bookmarking

  • The official Amazon EC2 Instance Types documentation — browse by category, drill into a specific family/generation, and see exact resource allocations and notes per size.
  • Third-party sites such as ec2instances.info provide a sortable, filterable comparison across instance types, including on-demand and reserved pricing, EBS optimization, and OS compatibility — useful for quickly narrowing down options during real design work.
Exam tip
For the exam, you don't need every family memorized — you need the family-letter associations (C = compute, R = RAM, I = I/O, D = dense storage, G = GPU, P = parallel processing) and the instinct for which of the five categories fits a described workload.

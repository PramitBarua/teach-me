EC2 Basics

EC2 Instance Types (Part 1)

Lesson 03 of 21 · ~8 min

Source: Adrian Cantrill SAA-C03 · AWS EC2 Instance Types

An EC2 instance is an OS plus an allocation of resources — and the instance type is how you control exactly what that allocation looks like. Choosing well matters: it affects raw resource amounts, the ratio between resources, network and storage bandwidth, underlying hardware architecture, price, and access to specialized capabilities like GPUs or FPGAs.

Exam tip
A recurring exam pattern: a performance problem is described, and one answer option is simply "change the instance type." Being able to judge whether a compute-optimized, memory-optimized, or storage-optimized type fits better is often enough to answer correctly.

What instance type selection actually controls

  • Raw resources — vCPU count, memory, local storage capacity and type.
  • Resource ratios — some families give more CPU per dollar, others prioritize memory per dollar.
  • Network and storage bandwidth — if you provision a high-performance EBS volume but pick an instance without enough network bandwidth, the instance becomes the bottleneck, not the storage.
  • Hardware architecture and vendor — ARM vs. x86, Intel vs. AMD CPUs.
  • Additional capabilities — GPUs for graphics, or FPGAs (field-programmable gate arrays) — reconfigurable hardware you can program for a specific task.

The five instance categories

CategoryOptimized forTypical use cases
General purposeBalanced CPU:memory ratioDefault starting point for steady-state workloads
Compute optimizedMore CPU per dollarMedia encoding, HPC, scientific modeling, gaming servers, ML
Memory optimizedMore memory per dollarLarge in-memory datasets, in-memory caching, some databases
Accelerated computingDedicated GPUs or FPGAsParallel processing, ML training, custom-programmed hardware
Storage optimizedLarge, fast local storageData warehousing, search, high sequential/random I/O workloads

General purpose is always your default. Only move to a specialized category once you have a specific, identified requirement that general purpose can't satisfy well.

Decoding an instance type name

Instance type names look cryptic — for example R5DN.8XLARGE — but they follow a consistent structure. Always use the full instance type when communicating a requirement; it's unambiguous.

SegmentExampleMeaning
FamilyRThe category/purpose code (see below) — memory optimized, in this case
Generation5Which iteration of that family — higher is newer, generally better price/performance
Additional capability lettersDNOptional flags — e.g. d = NVMe storage, n = network optimized, a = AMD CPU, e = extra RAM/storage
Size8XLARGEAmount of CPU/memory allocated within that family and generation

Sizes typically scale in a roughly linear sequence: nano, micro, small, medium, large, xlarge, 2xlarge, 4xlarge, 8xlarge, and so on — though the exact starting point varies by family. Larger sizes often carry a price premium, which matters when weighing "scale up" against "scale out" later in the course.

Exam tip
Default guidance is to always pick the latest generation available — it typically offers better price/performance. The only reasons to stay on an older generation are regional availability or an organization's internal testing/approval process. See the official EC2 Instance Types guide for the current, authoritative list of families, generations, and sizes.

Memory hooks for family letters

  • C — Compute
  • R — RAM (memory)
  • I — I/O
  • D — Dense storage
  • G — GPU
  • P — Parallel processing

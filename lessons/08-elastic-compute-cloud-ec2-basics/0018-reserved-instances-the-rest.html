EC2 Basics

Reserved Instances: The Rest

Lesson 18 of 21 · ~11 min

Source: Adrian Cantrill SAA-C03 · EC2 Reserved Instances · AWS Savings Plans

Standard Reserved Instances — a fixed one- or three-year commitment for constant, 24/7 usage — are only part of the reservation story. This lesson covers the more situational variants: Scheduled Reserved Instances, capacity reservations, the Reserved Instance Marketplace, and Savings Plans, a more flexible alternative to reserving a specific instance type outright.

Scheduled Reserved Instances

A standard reservation assumes 24/7/365 usage. Scheduled Reserved Instances solve for usage that's long-term and known but only needed on a recurring schedule — daily batch processing that runs five hours a night, a weekly analysis job every Friday, or a block of hours consumed each month. You specify the frequency, duration, and time window, and get a modest discount versus On-Demand for that window only.

Exam tip
Scheduled Reserved Instances still require a minimum one-year commitment and a minimum of roughly 1,200 hours per year of reserved time, and they don't support every instance type or region. Recognize the pattern — recurring, known, partial-time usage — rather than memorizing exact thresholds.

Capacity reservations

During a major regional or AZ failure, AWS satisfies capacity demand in priority order: Reserved commitments first, then On-Demand, then whatever's left for Spot. If a workload absolutely must be able to launch even during a capacity crunch, you need to reserve capacity, not just billing — and those are two separate, independently-usable components.

OptionReserves capacity?Billing discount?Term commitment
Regional RINo — any AZ in the region, no guaranteeYes, for matching instances anywhere in the region1 or 3 years
Zonal RIYes — locked to one specific AZYes, but only in that one AZ1 or 3 years
On-Demand Capacity ReservationYes — locked to one specific AZNoneNone — cancel anytime

A Zonal reservation gets you both the billing discount and a capacity guarantee, but only in the AZ it's pinned to. A Regional reservation is more flexible — the discount follows a matching instance into any AZ in the region — but it reserves no capacity anywhere; you launch with the same priority as On-Demand. An On-Demand Capacity Reservation is the odd one out: no term commitment and no discount, purely a guarantee that a specific amount of capacity in a specific AZ is available when you need it. You're billed for reserved capacity whether you consume it or not, so oversizing a capacity reservation wastes money exactly like an unused RI does.

Exam tip
"I need to guarantee I can launch instances during a capacity shortage, but I can't commit to a 1-3 year term" → On-Demand Capacity Reservation. "I need the cheapest possible price and a capacity guarantee, and I know exactly which AZ" → Zonal Reserved Instance.

Reserved Instance Marketplace

If your needs change and a reservation no longer fits — the wrong instance family, the wrong term length remaining — AWS provides the Reserved Instance Marketplace, where you can sell your unused Standard RIs to other AWS customers rather than let the commitment go to waste. It's a release valve for the biggest risk of reserving: getting locked into a commitment your business no longer needs.

Savings Plans

A Savings Plan works like a Reserved Instance in spirit — a one- or three-year commitment in exchange for a discount — but instead of committing to a specific instance type in a specific AZ or region, you commit to an hourly dollar spend (for example, $20/hour). Any usage up to that commitment is billed at the discounted Savings Plan rate; usage beyond it reverts to the normal On-Demand rate.

Plan typeApplies toFlexibilityTypical savings
Compute Savings PlansEC2, Fargate, and LambdaAny instance family, region, OS, or compute serviceUp to ~66% vs. On-Demand
EC2 Instance Savings PlansEC2 only, committed to one instance family in one regionFlexible across instance size, OS, and tenancy within that familyUp to ~72% vs. On-Demand

Compute Savings Plans are the better fit for an organization actively migrating between compute models — say, moving workloads from EC2 toward Fargate and eventually Lambda — because the same hourly commitment discounts all three as the mix shifts over time. If you know you'll only ever run EC2, an EC2 Instance Savings Plan unlocks a deeper discount in exchange for narrower flexibility. See AWS Savings Plans for the current mechanics and rates.

Exam tip
For the exam, you mainly need to recognize that Savings Plans exist and know the two-type split — Compute (broad, multi-service flexibility) vs. EC2 Instance (narrower, deeper discount). Don't confuse them with Reserved Instances, which commit to a specific instance type rather than a dollar amount.

      Scenario 1

      A hosting provider must run several unmodified legacy guest operating systems whose vendors forbid any source modification, on hardware that predates any CPU-level virtualization extensions. Which technique lets this work, at the cost of some performance overhead?

      • A. Emulated (software) virtualization, using binary translation on privileged calls
      • B. Hardware-assisted virtualization, since the CPU traps privileged calls directly
      • C. Para-virtualization, using hypercalls in place of privileged calls
      • D. SR-IOV, presenting virtual NICs directly to each guest

      Topic: Virtualization 101

      Correct answer: A

      • A. Correct — emulation needs no guest modification and no CPU virtualization extensions, using software binary translation instead, at a real performance cost.
      • B. Wrong — hardware-assisted virtualization requires CPU virtualization extensions, which this hardware doesn't have.
      • C. Wrong — para-virtualization requires modifying the guest OS source, which the vendor forbids here.
      • D. Wrong — SR-IOV virtualizes I/O devices, it doesn't address the general privileged-instruction problem described.

      Scenario 2

      A cloud vendor fully controls the source code of its guest operating systems, is willing to accept lock-in to one hypervisor vendor's driver stack, but its hardware predates any CPU virtualization extensions. Which approach are they well positioned to use for better-than-emulated performance?

      • A. Hardware-assisted virtualization, trapping privileged calls at the CPU
      • B. Emulated virtualization, translating privileged calls in software
      • C. Para-virtualization, issuing hypercalls from a modified guest OS
      • D. SR-IOV, presenting isolated virtual devices in hardware

      Topic: Virtualization 101

      Correct answer: C

      • A. Wrong — hardware-assisted virtualization needs CPU extensions this old hardware lacks.
      • B. Wrong — emulation works here too, but it's the slower option when guest modification is actually available to exploit.
      • C. Correct — with a modifiable guest OS and no CPU extensions, para-virtualization's hypercalls give meaningfully better performance than emulation, accepting hypervisor-vendor lock-in.
      • D. Wrong — SR-IOV is an I/O device technique, not a general solution to privileged CPU instructions.

      Scenario 3

      A hypervisor vendor advertises that guest operating systems require zero modification and that CPU performance is nearly indistinguishable from bare metal, achieved by the CPU itself trapping and redirecting privileged instructions to the hypervisor. Which technique are they describing?

      • A. Emulated (software) virtualization
      • B. Para-virtualization
      • C. SR-IOV
      • D. Hardware-assisted virtualization

      Topic: Virtualization 101

      Correct answer: D

      • A. Wrong — emulation also needs no guest modification, but it's slow software translation, not near-bare-metal CPU performance.
      • B. Wrong — para-virtualization explicitly requires modifying the guest OS, contradicting "zero modification."
      • C. Wrong — SR-IOV is about I/O devices, not general privileged CPU instruction handling.
      • D. Correct — hardware-assisted virtualization lets the CPU itself trap and redirect privileged instructions, needing no guest modification and reaching near-native CPU performance.

      Scenario 4

      An architect is troubleshooting high, inconsistent network latency on an EC2 instance under heavy load. The instance's guest OS is a vendor-supported image they are not permitted to modify in any way. They want the guest's NIC to get hardware-isolated, direct access with minimal hypervisor mediation. What should they use?

      • A. Para-virtualized network drivers, using hypercalls for I/O
      • B. SR-IOV, exposed in EC2 as enhanced networking
      • C. Emulated software virtualization for the network device
      • D. A dedicated host, to remove other tenants from the hardware

      Topic: Virtualization 101

      Correct answer: B

      • A. Wrong — para-virtualized drivers require modifying the guest OS, which is forbidden here.
      • B. Correct — SR-IOV lets the physical NIC present isolated virtual cards directly to the guest with no guest modification, which EC2 exposes as enhanced networking for higher throughput and lower, more consistent latency.
      • C. Wrong — emulation adds more hypervisor mediation and software translation, the opposite of what's needed for low, consistent latency.
      • D. Wrong — a dedicated host addresses noisy-neighbor hardware sharing, not the I/O virtualization path causing latency and throughput inconsistency.

      • B. Emulated → hardware-assisted → para-virtualized
      • C. Emulated → para-virtualized → hardware-assisted
      • D. Hardware-assisted → emulated → para-virtualized

      Scenario 6

      A company launches ten small EC2 instances for different internal teams. They want to pay only for the runtime and resources each instance actually uses, and they're fine with the underlying physical server also running other AWS customers' fully isolated workloads. Which host ownership model achieves this?

      • A. Shared hosts, the default per-instance billing model
      • B. Dedicated hosts, paying for the entire physical server
      • C. A host reserved exclusively for this company's own instances
      • D. A host that automatically migrates instances between AZs to spread cost

      Topic: EC2 Architecture and Resilience

      Correct answer: A

      • A. Correct — shared hosts are the default model: multiple customers' instances run isolated on the same host, and you pay per instance based on runtime and resources.
      • B. Wrong — dedicated hosts bill for the whole physical server, not per-instance runtime, and are never shared with other customers.
      • C. Wrong — exclusivity to one company's instances describes dedicated hosting, which violates the stated acceptance of sharing with other customers.
      • D. Wrong — instances never move between AZs automatically or otherwise; this isn't a real host ownership model.

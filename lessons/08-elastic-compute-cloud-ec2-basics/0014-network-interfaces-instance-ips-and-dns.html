EC2 Basics

Network Interfaces, Instance IPs & DNS

Lesson 14 of 21 · ~11 min

Source: Adrian Cantrill SAA-C03 · Elastic Network Interfaces · EC2 Instance IP Addressing

A lot of what the EC2 console UI presents as belonging to "the instance" — IP addresses, DNS names, security groups — actually belongs to something one layer down: the Elastic Network Interface (ENI). Understanding that distinction clears up most of the confusing edge cases around EC2 networking.

Every instance has at least one ENI

Every EC2 instance launches with a primary ENI, and can optionally have one or more secondary ENIs attached. All of an instance's ENIs — primary and secondary — must live in the same Availability Zone as the instance, though they can sit in different subnets within that AZ. The primary ENI cannot be detached from its instance; secondary ENIs can be detached and reattached to a different instance, as long as that instance is in the same AZ.

Exam tip
If a scenario needs different security group rules applied to different IP addresses on one instance, the answer is multiple ENIs, not multiple IPs on one ENI — security groups attach at the interface level, so separating IPs onto separate ENIs is the only way to give them separate rule sets.

Private and public DNS naming

Every instance's primary private IPv4 address gets a matching private DNS hostname in the form ip-10-16-0-10.ec2.internal — resolvable only inside the VPC, and always pointing at the private address.

If the instance also receives a public IPv4 address, it gets a public DNS hostname too, roughly in the form ec2-x-x-x-x.compute-1.amazonaws.com. This public DNS name behaves differently depending on where you resolve it from:

  • Inside the VPC — resolves to the instance's private IPv4 address, so instance-to-instance traffic using this name never has to leave the VPC via the internet gateway.
  • Outside the VPC — resolves to the public IPv4 address.

This dual-resolution behavior is a recurring theme later when designing hybrid networks — see the EC2 instance addressing guide for the full reference.

Public IPv4 is dynamic; Elastic IPs are not

A standard public IPv4 address is dynamic: it is deallocated when the instance stops, and a new, different one is allocated when it starts again. A simple reboot does not change it — only a stop/start (or a forced host migration) does.

An Elastic IP (EIP) is a static public IPv4 address allocated to your AWS account, which you then associate with a private IP on either the primary or a secondary ENI. Associating an EIP with the primary ENI's private IP immediately replaces whatever dynamic public IP the instance had. If you later remove the EIP, the instance is assigned a brand-new dynamic public IP — the original one is gone for good.

Exam tip
A favorite exam trap: "an instance had a dynamic public IP, an Elastic IP was assigned, then removed — can you recover the original dynamic IP?" No. Assigning an EIP permanently discards the original dynamic address; removing the EIP later just allocates a different new dynamic address.

The OS never sees the public IPv4 address

Inside the operating system, only the private IPv4 address is ever configured on the network interface. The public IPv4 address isn't attached to the instance at all — it's mapped in by NAT performed at the internet gateway. You will never configure a Windows or Linux network interface with a public IPv4 address in AWS. IPv6 is the exception, since IPv6 addresses are public by design with no NAT translation involved.

Two more practical uses of secondary ENIs worth remembering: MAC-based software licensing can be made portable by binding the license to a secondary ENI's MAC address, then detaching and reattaching that ENI to a new instance when needed; and multi-homed instances can use separate ENIs in separate subnets for management versus data traffic, each governed by its own security group.

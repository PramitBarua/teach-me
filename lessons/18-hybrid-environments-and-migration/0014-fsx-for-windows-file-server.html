FSx for Windows File Server

Lesson 14 of 16 · ~7 min

Source: Adrian Cantrill SAA-C03 · FSx for Windows File Server Performance

FSx for Windows File Server is a fully managed, native Windows file system — not an emulation of one. It's one of the core products AWS offers to properly support Windows workloads in the cloud.

You consume shares, not servers — same mental model as RDS
Just as RDS gives you a database endpoint while hiding the underlying database server, FSx for Windows File Server gives you file shares as your unit of consumption. The servers behind those shares are managed entirely by AWS and never exposed to you directly.

Active Directory Integration

FSx for Windows needs a directory as its user store, but critically, it is not tied to the Directory Service product. It can integrate with either:

  • AWS Managed Microsoft AD (via Directory Service), or
  • A self-managed Active Directory — running on-premises or inside AWS.

This matters for enterprises that already run their own AD: FSx can point straight at that existing, normal AD implementation without any Directory Service product being involved at all.

Deployment and Access

FSx for Windows can be deployed single-AZ or multi-AZ — the choice affects which network interfaces are used to reach it. Even in single-AZ mode, data is replicated within that AZ for resilience to hardware failure; multi-AZ adds full cross-AZ high availability. File systems are reachable from within a VPC, and also over VPC peering, VPN, and Direct Connect — useful for large enterprises with dedicated private links into their VPC.

Native Windows Features

Because it's a true native Windows file system, FSx for Windows carries capabilities you won't find on EFS:

  • Deduplication — reduces redundant data on disk.
  • DFS (Distributed File System) — natively groups and scales out file shares into a single enterprise-wide structure.
  • VSS (Volume Shadow Copy Service) — lets users right-click a file or folder, view previous versions, and restore themselves — no administrator involvement required.
  • Native NTFS-style Windows permissions — the same permission model Windows admins already know.
  • Encryption — at rest via KMS, plus optional encryption in transit.

Shares are accessed the familiar Windows way: \\filesystem-id.animalsforlife.org\catpix. Services that need Windows-native storage, such as WorkSpaces, can point directly at an FSx share.

Exam tip: SMB / Windows / AD → FSx; NFS / Linux → EFS
This is the single highest-yield fact for this topic. If a question mentions SMB, a native Windows file server, or Active Directory integration, the answer is FSx for Windows File Server. EFS uses NFS and is only accessible from Linux/Unix EC2 instances or Linux on-premises servers — it has no Windows story at all. If the scenario also frames it as avoiding the admin overhead of running a self-managed Windows Server EC2 instance, that reinforces FSx as the answer.

Performance

FSx for Windows delivers sub-millisecond latency, with per-file-system throughput capacity you select at creation and can scale later. Current AWS documentation puts the selectable range at roughly 32 MB/s up to 12 GB/s, paired with IOPS scaling up to the hundreds of thousands. The exact ceiling isn't something the exam expects you to memorize — what matters is that FSx scales to serious enterprise performance requirements, not that you can quote the exact top figure.

AWS Transfer Family

Lesson 16 of 16 · ~8 min

Source: Adrian Cantrill SAA-C03 · Create a Server in a Virtual Private Cloud — AWS Transfer Family

AWS Transfer Family is a managed file transfer service that lets you access S3 and EFS using legacy or non-native transfer protocols — without running any server infrastructure yourself. It's the answer whenever an existing workflow or client can't be changed to speak S3's or EFS's native APIs, but can speak FTP, FTPS, SFTP, or AS2.

The Four Protocols

ProtocolDescription
FTPFile Transfer Protocol — legacy, unencrypted. Niche usage today.
FTPSFTP with TLS encryption added on top.
SFTPFile transfer over SSH. The most commonly used of the four in practice.
AS2Applicability Statement 2 — a niche protocol for structured business-to-business data, common in supply chain / EDI / payment workflows with built-in compliance requirements.

Identity can be handled through built-in identities, AWS Directory Service, or a custom identity provider built with Lambda and API Gateway. A related feature, Managed File Transfer Workflows, is a serverless workflow engine that triggers actions — like notifications or tagging — automatically when a file is uploaded.

Endpoint Types: The Highest-Yield Content Here

Servers in Transfer Family expose one of three endpoint types, and the differences between them are the most exam-tested part of this whole topic.

Endpoint typeProtocolsIP addressAccess control
PublicSFTP onlyDynamic — use DNS, not the raw IPNone — no security group / NACL control
VPC, internet-facingSFTP, FTPS, AS2Static (Elastic IP)Security group / NACL controllable
VPC, internal onlySFTP, FTPS, FTP, AS2StaticSecurity group / NACL controllable

Both VPC endpoint types are reachable from the internet (if internet-facing) or the VPC, plus anything connected to that VPC over Direct Connect or VPN. The public endpoint is simplest to set up — nothing to configure in the way of networking — but comes with real trade-offs: SFTP only, a changing IP, and no way to restrict who connects with a security group or NACL.

Why plain FTP only works on the internal-only endpoint
FTP is unencrypted, so AWS restricts it to the VPC internal-only endpoint type — the one option that never touches the public internet. It makes no sense to expose an unencrypted protocol on a public or internet-facing endpoint, so AWS simply doesn't allow it there.
Exam heuristic: match the protocol requirement to the endpoint constraint
When a scenario names a required protocol, check it against endpoint capability: need plain FTP? Only VPC internal-only supports it. Need security-group-level access control? Rule out the public endpoint type — it offers none. Need the simplest possible setup with no VPC work and only SFTP is required? Public endpoint fits. Also remember: FTP and FTPS require Directory Service or a custom identity provider — built-in identities alone aren't enough for those two protocols.

Other Practical Details

  • Transfer Family servers are multi-AZ.
  • Billing is per provisioned-server-hour plus data transferred — no upfront cost.
  • Back-end access to S3 or EFS is granted to the Transfer Family server via IAM roles.

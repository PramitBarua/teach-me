Direct Connect: Public VIF + VPN Encryption

Lesson 06 of 16 · ~7 min

Source: Adrian Cantrill SAA-C03 · Direct Connect virtual interfaces and hosted virtual interfaces

A Site-to-Site VPN gives you an encrypted, authenticated tunnel — true whether it runs over the public internet or over Direct Connect. Running the VPN over Direct Connect adds low, consistent latency on top of that encryption, giving you great performance and great security together.

Why a "private" VPC needs a public VIF
Many students expect a private VIF here, since the target is a private VPC. But a private VIF only reaches private IP addresses. A VPN connects to public IP addresses owned by a virtual private gateway or transit gateway — AWS provisions VPN endpoints with public addressing in two Availability Zones. Because you're reaching public-zone IPs, you need a public VIF, regardless of what's logically behind that endpoint. Always ask what IP address you're actually connecting to, not what the traffic is ultimately destined for.

VPN Is Transit-Agnostic

The VPN configuration itself doesn't change based on transit — only how you reach the endpoint differs:

  • Over the public internet — many hops, variable latency.
  • Over a public VIF on Direct Connect — Direct Connect's low, consistent latency, same encrypted tunnel.

You can even reach VPN endpoints for virtual private gateways in other AWS Regions across the same public VIF, riding the AWS global network — a common way to deliver global encrypted transit between VPCs and a single business network connection.

VPN vs. MACsec: Different Problems, Not Competitors

VPN (IPSec)MACsec
Encryption scopeEnd-to-end: customer gateway → VGW/TGWSingle hop: DX router → customer router
TransitPublic internet or public VIFDirect Connect cross-connect only
ThroughputLimited by crypto overheadDesigned for terabit-class speeds
Vendor supportWide (most routers support IPSec)Narrower (fewer switches support it)

A VPN encrypts the full path from your on-premises customer gateway all the way to the AWS-side gateway. MACsec only encrypts the single local-area-network hop between your router and the AWS DX router at the cross-connect. Neither replaces the other — they solve different layers of the problem.

Exam tip: a common resilience pattern
A frequent real-world design: primary path is Direct Connect carrying an IPSec VPN (performance plus encryption), backup path is a completely separate internet connection also carrying its own IPSec VPN. Because a VPN can be stood up in minutes purely in software, teams often start with VPN-only connectivity and add Direct Connect later — either keeping the VPN in place for ongoing encryption, using it purely as a failover path, or both.

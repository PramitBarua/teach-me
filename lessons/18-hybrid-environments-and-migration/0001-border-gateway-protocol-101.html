Border Gateway Protocol (BGP) 101

Lesson 01 of 16 · ~7 min

Source: Adrian Cantrill SAA-C03 · Direct Connect routing policies and BGP communities

BGP (Border Gateway Protocol) is a routing protocol — a system for deciding how data flows from a source to a destination across a network of networks. BGP itself is a huge topic, far beyond exam scope, but you need the high-level shape of it because two AWS hybrid-networking products, Direct Connect and dynamic (BGP-based) VPNs, both rely on it. This lesson is a conceptual foundation for the lessons that follow — nothing more.

Autonomous Systems

BGP is built from autonomous systems (AS) — self-managed networks controlled by a single entity. An AS might be one router or an entire enterprise network with complex internal routing; from BGP's perspective, it's a black box. BGP doesn't care what happens inside an AS, only how traffic gets in and out of it.

Every AS is allocated an autonomous system number (ASN) by IANA. ASNs are generally 16 bits, ranging from 0–65,535. Most of that range is public and directly allocated by IANA; the range 64,512–65,534 is private, reserved for private peering arrangements without formal allocation.

Peering is manual, exchange is automatic
BGP runs over TCP port 179, and it's reliable — it includes error correction and flow control. But a BGP relationship between two autonomous systems is never automatic; someone has to configure that peering deliberately. Once peered, though, the two ASes automatically exchange what they know about network topology, and that knowledge propagates outward to each AS's other peers — which is how routing information spreads across the entire internet.

Path-Vector Behavior and the AS Path

BGP is a path-vector protocol: peers exchange the best known path to a destination, not every path they know. That path is called the AS path — the sequence of autonomous systems traffic must cross to reach a destination. Critically, BGP has no concept of link speed or link condition. It only compares path length. Given a choice between a fast link with a longer AS path and a slow link with a shorter AS path, default BGP behavior always prefers the shorter path, regardless of actual performance.

The Mental Model: Shortest AS Path Wins

Picture three sites in a ring, each its own autonomous system, each peered with the other two:

SiteASNLink to neighbor
Brisbane2001 Gbps fiber to Adelaide · 5 Mbps satellite to Alice Springs
Adelaide2011 Gbps fiber to Brisbane · 1 Gbps fiber to Alice Springs
Alice Springs2021 Gbps fiber to Adelaide · 5 Mbps satellite to Brisbane

Once all three peer with each other, each site learns two ways to reach every other site: a direct path and an indirect path through the third site. Brisbane can reach Alice Springs directly over the satellite link (AS path length: 1 hop) or indirectly via Adelaide over fiber (AS path length: 2 hops). By default, BGP prefers the shorter AS path — so Brisbane would route to Alice Springs over the slow, high-latency satellite link, purely because it's fewer AS hops, even though the fiber route via Adelaide is objectively better.

AS-path prepending: making a path look artificially worse
To fix this, an administrator can use AS-path prepending — repeating your own ASN multiple times in the advertised path to make it look artificially longer than it physically is. BGP still only compares path length, so a prepended satellite path (now "3 hops" instead of 1) loses to the genuinely shorter-looking fiber path via Adelaide, and traffic shifts onto the better link. This is a real, exam-relevant technique for de-prioritizing a backup or lower-quality link without touching the underlying physical topology.

This is also what gives ring-style BGP topologies their resilience: because every site learns both a direct and an indirect route to every other site, if one link or site fails, traffic automatically re-routes over the surviving path — no manual reconfiguration required.

Why this matters for AWS
You will not be asked to hand-trace AS paths on the exam. What matters is the mental model: autonomous systems peer, exchange the shortest known path, and BGP picks routes by path length alone — never by speed or latency. Keep this in mind going forward, because both Direct Connect and dynamic Site-to-Site VPNs (covered in upcoming lessons) use BGP to exchange routes between your on-premises network and AWS.

Elastic Container Registry (ECR)

Lesson 03 of 04 · ~6 min

Source: Adrian Cantrill SAA-C03 · Amazon ECR User Guide

You've already pushed a container image to Docker Hub. ECR (Elastic Container Registry) is AWS's own equivalent: a managed registry for container images, usable by ECS, EKS, or any other container tooling — and integrated with the rest of AWS the way you'd expect.

Structure

Every AWS account gets one public registry and one private registry. Inside a registry you can create many repositories (think of a repository like a repo in Git), and inside each repository you can store many container images, each identified by one or more tags that must be unique within that repository.

Registry typeRead accessWrite access
PublicAnyone — no permissions neededRequires IAM permissions
PrivateRequires IAM permissionsRequires IAM permissions
Exam tip
A public ECR registry means anyone can pull without credentials, but pushing always needs permission. A private registry requires permission for both directions. This asymmetry — free reads, gated writes — is the detail most likely to show up as a distractor.

Why Use ECR

  • IAM-integrated — every permission on the registry, repositories, or images is controlled through IAM, same as any other AWS resource.
  • Image scanning, in two tiers: basic scanning checks images against a CVE database on push or on demand; enhanced scanning uses Amazon Inspector for continuous, layer-by-layer scanning of both the OS and any language-level software packages inside the image.
  • Near real-time metrics delivered to CloudWatch — authentication, push, and pull operations.
  • CloudTrail logs every API action against the registry.
  • EventBridge events, so pushes/pulls can drive an event-driven workflow.
  • Replication, both cross-Region and cross-account, for distributing images closer to where they're consumed.
Basic vs. enhanced scanning
Basic scanning is billed through ECR itself and checks for known CVEs. Enhanced scanning is billed through Amazon Inspector and goes further — continuous rescans as new vulnerabilities are published, plus visibility into programming-language packages, not just the OS layer. See Scan images for vulnerabilities in Amazon ECR.

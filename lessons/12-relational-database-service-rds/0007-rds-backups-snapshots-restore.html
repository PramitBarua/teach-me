RDS Backups, Snapshots & Restore

Lesson 07 of 16 · ~9 min

Source: Adrian Cantrill SAA-C03 · Introduction to RDS backups

RDS gives you two backup-like mechanisms — automated backups and manual snapshots — plus continuous transaction logs that together make point-in-time recovery possible. Both store data in an AWS-managed S3 bucket, invisible in your own console, but regionally resilient because of it.

Snapshots vs Automated Backups

Manual snapshotAutomated backup
TriggerExplicit — you (or a script) run itAutomatic, once per day, in a defined backup window
First copyFull copy of the instanceFull copy of the instance
Subsequent copiesIncremental — only changed dataIncremental — only changed data
ScopeWhole instance (all databases on it)Whole instance
ExpiryNever — persists until you delete it, even past instance deletionCleared automatically per the retention period
Retention controlManual, indefinite0–35 days, configurable

Any snapshot — manual or automated — causes a brief I/O pause. On Single-AZ, this can affect application performance; on Multi-AZ, it's taken from the standby, so there's no impact.

Exam tip
Manual snapshots outlive the instance and never expire on their own — a classic exam trap. If you delete an RDS instance and want to retain data past the automated-backup retention window, you must explicitly create a final snapshot, which is then entirely under your control to delete.

Transaction Logs and Point-in-Time Recovery

Every 5 minutes, RDS writes database transaction logs to S3. Combined with the daily automated backup, this enables restoring to any point in time within the retention window, at roughly 5-minute RPO granularity.

  • Retention period: 0–35 days (0 disables automated backups entirely).
  • Backups (snapshots + transaction logs) can optionally be replicated to another Region — this is not the default; you must explicitly enable it, and cross-region copy + storage costs apply.

How Restore Actually Works

This is the part that trips people up: restoring always creates a brand-new RDS instance with a new endpoint. Your application needs to be updated to point at it — there's no in-place restore.

Restore typeBehaviourRPO impact
Manual snapshotRestores to the exact moment the snapshot was takenAs good as your last snapshot — potentially poor if it's stale
Automated backup (point-in-time)Nearest snapshot + transaction logs replayed to your chosen timestampMuch better — can restore to minutes before failure
Restore is slow
Restoring a large database is not fast — factor restore time into your RTO planning. Read replicas (next lesson) exist specifically to give you a much better RTO than a snapshot restore can.

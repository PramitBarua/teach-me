Aurora Global Database

Lesson 13 of 16 · ~6 min

Source: Adrian Cantrill SAA-C03 · Using Amazon Aurora Global Database

Aurora Global Database extends a single Aurora cluster's replication across AWS Regions — a primary Region plus multiple read-only secondary Regions, purpose-built for global read performance and cross-Region disaster recovery.

Architecture

  • One primary Region — behaves like a normal Aurora cluster: one writer, up to 15 read replicas.
  • Secondary Regions — entirely read-only during normal operation, with up to 16 replicas each.
  • Replication happens at the storage layer, one-way from primary to secondaries, typically completing in under one second.
  • Because replication is storage-layer, it adds no CPU load to the primary — performance is unaffected.
Secondary Region limit — check current figures
Cantrill's course states a limit of 5 secondary Regions. AWS's current documentation allows up to 10. As with Aurora's storage ceiling, AWS raises limits like this over time — verify the current Aurora Global Database docs if the exact number matters for your exam.

Why Use It

Use caseHow Global Database helps
Cross-Region disaster recovery If the primary Region fails entirely, a secondary can be promoted to read-write — sub-second replication keeps both RPO and RTO very low
Global read scaling Serve international users from a nearby secondary Region for low-latency reads, without touching the primary
Exam tip
Global Database replication is one-way, not bidirectional — secondaries never write back to the primary during normal operation. This distinguishes it from multi-master, where multiple instances can all accept writes.

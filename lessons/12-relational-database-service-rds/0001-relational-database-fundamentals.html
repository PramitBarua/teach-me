Relational Database Fundamentals

Lesson 01 of 16 · ~7 min

Source: Adrian Cantrill SAA-C03 · AWS RDS User Guide

Before RDS, Aurora, and any of the managed database products in this module make sense, you need the vocabulary of relational databases themselves. This lesson is the foundation everything else in this module builds on.

SQL, RDBMS — Same Thing, Different Names

Strictly speaking, SQL (Structured Query Language) is the language used to store, update, and retrieve data, while RDBMS (Relational Database Management System) is the platform itself. In practice — and on the exam — the two terms are used interchangeably to mean "relational database."

The defining trait of a relational database is structure: a fixed schema defined before any data goes in. The schema declares the names of things, valid values, data types, and — critically — the relationships between tables. All of this is rigid and hard to change once data exists.

Tables, Attributes, and Primary Keys

A relational database groups related data into tables. Each table has attributes (columns), and each row must supply a value for every attribute in that table.

ConceptWhat it means
TableStores data that relates together, e.g. all "humans" in one table, all "animals" in another
AttributeA column in a table (e.g. FNAME, AGE)
Attribute valueThe value a specific row holds for a specific attribute
Primary keyAn attribute that is unique for every row in a table — how a row is identified

Every row must have a unique primary key value. In a humans table, that might be a simple incrementing ID: row 1, row 2, row 3, each unique.

Relationships and Composite Keys

Relational databases formally link tables together using keys. Consider humans who own pets, where a human can have many pets and a pet can have many human "owners" — a many-to-many relationship. This is modelled with a join table, which references the primary keys of both other tables.

A join table's own primary key is usually a composite key — formed from two or more attributes that, together, must be unique. Two rows can share the same animal ID (the same pet has two owners) as long as the full combination of animal ID + human ID isn't repeated anywhere else in the table.

Exam tip
Relationships between tables are defined in advance, as part of the schema. This is precisely what makes relational databases a poor fit for data with rapidly changing relationships (like a social network) — a theme you'll see again when comparing to NoSQL models in the next lesson.

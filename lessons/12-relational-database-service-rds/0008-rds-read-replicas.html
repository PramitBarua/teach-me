RDS Read Replicas

Lesson 08 of 16 · ~8 min

Source: Adrian Cantrill SAA-C03 · Working with DB instance read replicas

Read replicas solve a different problem than Multi-AZ. Where Multi-AZ is about availability, read replicas are about read performance and recovery time — and unlike a Multi-AZ standby, they're genuinely usable.

Exam tip
For any RDS question (excluding Aurora): synchronous = Multi-AZ, asynchronous = read replicas. This single rule resolves a large share of RDS exam questions.

How Read Replicas Work

  • Read replicas are separate entities with their own endpoint — an application has zero awareness of them unless explicitly configured to use them.
  • Replication is asynchronous: a write is committed on the primary first, then replicated afterward — meaning there can be a small lag (seconds, depending on load and network conditions).
  • You can create up to 5 direct read replicas per source instance.
  • Read replicas can themselves have their own read replicas (multi-level), but replication lag compounds the deeper you go.
  • Read replicas can be created in the same Region or a different Region (cross-Region), with AWS handling the networking transparently and encrypting the link in transit.
  • A replica is read-only until promoted — after promotion, it behaves as a standalone, fully functional RDS instance.

Why Read Replicas Matter

BenefitWhy
Read scalingOffload read-heavy workloads to replicas, freeing capacity on the primary
Global read performanceCross-Region replicas let distant users read locally, without hitting the primary
Near-zero RTOA replica already has (nearly) current data, so promotion is fast — unlike a snapshot restore
Cross-Region resiliencePromote a cross-Region replica if an entire Region becomes unavailable
Only for failure, not corruption
Read replicas give you a great RTO — but only when recovering from failure. If your primary suffers data corruption, the replica almost certainly has that same corrupted data (it was just replicated). For corruption scenarios, you need point-in-time restore instead.

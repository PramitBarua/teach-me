RDS & Aurora

RDS Architecture

Lesson 05 of 16 · ~9 min

Source: Adrian Cantrill SAA-C03 · AWS RDS User Guide

RDS is often called "database as a service," but that's not quite accurate: you pay for and receive a database server, which can host multiple databases. A more precise name would be database server as a service.

Exam tip
Separate Amazon Aurora from "RDS" in your mind. Aurora is technically part of the RDS family but is a custom AWS-built engine with a fundamentally different architecture — covered in its own lessons later in this module.

RDS gives you database engines including MySQL, MariaDB, PostgreSQL, and commercial engines like Oracle and Microsoft SQL Server. It manages the hardware, OS, engine installation, and much of the ongoing maintenance. Critically: no SSH and no OS-level access (with one asterisk — RDS Custom, covered in Lesson 10).

RDS Lives Inside a VPC

Unlike S3 or DynamoDB, RDS is not a public service — it runs in subnets within a VPC, in a specific AWS Region. The key building block is a DB subnet group: a named list of subnets, spanning multiple AZs, that RDS is allowed to use for a given instance.

ConceptDetail
DB subnet groupList of subnets (ideally across ≥2 AZs) RDS can place instances into
Best practiceOne DB subnet group per RDS deployment, for maximum flexibility
Public vs private subnetsRDS instances in private subnets are reachable only from inside the VPC or connected networks; instances in public subnets can get public addressing — strongly discouraged for security

When you launch a Multi-AZ instance, RDS picks one subnet for the primary and a different subnet in a different AZ for the standby — at random, unless you specify a preference.

Storage, Replication, and Backups

  • Every RDS instance can host multiple databases.
  • Each instance has its own dedicated EBS-backed storage — this is a key contrast with Aurora, which uses shared cluster storage (see Lesson 11).
  • Multi-AZ primary → standby replication is synchronous — the standby always has the same data as the primary.
  • Read replicas use asynchronous replication and can live in the same Region or a different one (covered in Lesson 08).
  • Backups are stored in an AWS-managed S3 bucket — not visible in your own S3 console — and are automatically spread across multiple AZs. If Multi-AZ is enabled, backups are taken from the standby, so there's no primary-instance performance hit.

The Cost Model

RDS billing, like EC2, is based on resource allocation, not query volume:

Cost componentDetail
Instance size/typeHourly rate, billed per second — bigger/richer instance = more cost
Multi-AZExtra cost for the additional standby instance(s)
StoragePer-GB monthly fee; Provisioned IOPS storage costs more than General Purpose
Data transferPer-GB cost for traffic to/from the internet and other Regions
Backups/snapshotsFree up to the amount of provisioned storage; beyond that, a per-GB-month fee
Commercial enginesAdditional licensing costs for engines like Oracle or SQL Server

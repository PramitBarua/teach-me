ACID vs BASE

Lesson 03 of 16 · ~7 min

Source: Adrian Cantrill SAA-C03

Why do relational databases scale differently than NoSQL databases? The answer starts with a computer science theorem, and ends with two competing transaction models: ACID and BASE.

The CAP Theorem

The CAP theorem states that a distributed database can only guarantee two of these three properties at once:

PropertyGuarantee
ConsistencyEvery read receives the most recent write, or an error
AvailabilityEvery request receives a non-error response — but not necessarily the latest data
Partition toleranceThe system keeps working even if network messages are dropped between nodes

If nodes in a distributed database can't communicate, you face a choice: cancel the operation (favouring consistency) or proceed anyway (favouring availability). You cannot always have both. ACID and BASE are two different answers to that trade-off.

ACID: Consistency First

ACID governs most relational databases, including RDS. It stands for four guarantees on every transaction:

Atomic
All parts of a transaction succeed, or none do. A $10 transfer between two accounts either fully completes or fully rolls back — never half-done.
Consistent
Every transaction moves the database from one valid state to another — nothing in between is allowed.
Isolated
Concurrent transactions don't interfere with each other; the end result is as if they ran sequentially.
Durable
Once a transaction is committed, it survives even a system or power failure.

These are strong guarantees — which is exactly why financial systems favour ACID. But rigidly enforcing all four limits how far a database can scale horizontally.

BASE: Availability First

BASE is the trade-off many NoSQL databases make instead:

Basically available
Reads and writes are available as much as possible — but without a consistency guarantee.
Soft state
The database doesn't enforce its own consistency; that responsibility shifts to the application.
Eventually consistent
Given enough time, a read will eventually reflect the most recent write — but not necessarily immediately.

By relaxing consistency, BASE-modelled databases scale further and perform better under distributed load. DynamoDB defaults to BASE-style behaviour, offering both eventually-consistent and (on request) immediately-consistent reads.

Exam tip
Default exam mappings: ACID → RDS (relational). BASE → NoSQL. If a question mentions ACID together with DynamoDB, it's likely referring to DynamoDB transactions, a feature that layers ACID guarantees onto an otherwise BASE-style database.

3. An exam question describes a NoSQL database where reads might briefly return stale data after a write, but the system always responds and rarely errors. Which model does this describe?

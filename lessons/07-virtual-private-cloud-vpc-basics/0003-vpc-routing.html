VPC Routing & Route Tables

Lesson 03 of 09 · ~8 min

Source: Adrian Cantrill SAA-C03 · AWS Route Tables Docs

The VPC Router

Every VPC contains a VPC router — a highly available virtual device that runs across every AZ the VPC uses. You do not manage it directly; it is always present and active. The router is reachable from every subnet at the network + 1 address (e.g. 10.0.0.1 for a subnet starting at 10.0.0.0). Without any additional configuration the router handles all intra-VPC traffic automatically — subnets can talk to each other out of the box.

Route Tables

A route table is a set of rules that tells the VPC router what to do with traffic leaving a subnet. Each row in the table is a route with two fields:

FieldMeaningExample values
DestinationThe IP range the rule matches10.0.0.0/16 (entire VPC), 0.0.0.0/0 (default — everything else)
TargetWhere to send matching trafficlocal (keep inside VPC), an IGW ID, a NAT gateway ID

Route selection follows longest-prefix-match: the most specific route that matches the destination wins. A /32 beats a /24, which beats a /16, which beats the default 0.0.0.0/0. One exception: if two routes tie for specificity and one has target local, the local route always wins.

Main Route Table vs Custom Route Tables

A VPC is created with a single main route table. Any subnet that is not explicitly associated with a custom route table automatically uses the main route table. You can create additional custom route tables and associate them with specific subnets to override default routing behaviour.

Main route tableCustom route table
Created byAWS, at VPC creationYou
Default associationAll subnets not explicitly associatedSubnets you explicitly assign
Can be deleted?No (only replaced)Yes (if no subnets are associated)
Exam tip
A subnet can only be associated with one route table at a time — either the main or a custom one. To make a subnet public you create a custom route table with a 0.0.0.0/0 → IGW route and associate it with that subnet.

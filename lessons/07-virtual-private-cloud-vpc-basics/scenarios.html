      Scenario 1

      A finance team is creating a new VPC and, worried about noisy-neighbor performance issues, sets tenancy to Dedicated at creation time. Six months later they want to move back to shared hardware to cut costs. What should they expect?

      • A. Dedicated tenancy automatically reverts after ninety days pass
      • B. Tenancy only affects subnets, so the VPC setting never mattered
      • C. Reverting is difficult and costly, since Dedicated was hard to undo
      • D. Tenancy can be flipped back with a single API call at any time

      Topic: Custom VPCs

      Correct answer: C

      • A. Wrong — there is no automatic time-based reversion of tenancy described anywhere.
      • B. Wrong — tenancy is a VPC-creation-time choice, not a subnet-level setting.
      • C. Correct — Dedicated forces all resources onto dedicated hardware, and this choice is expensive and hard to undo once made.
      • D. Wrong — Dedicated tenancy is described as expensive and hard to undo, not a simple toggle.

      Scenario 2

      An architect is filling in the primary IPv4 CIDR block while creating a new VPC and wants the absolute largest address space AWS allows for a single VPC CIDR. Which block should they enter?

      • A. A /28 block, giving sixteen addresses total
      • B. A /16 block, giving 65,536 addresses total
      • C. A /8 block, giving over sixteen million addresses
      • D. A /24 block, giving two hundred fifty six addresses

      Topic: Custom VPCs

      Correct answer: B

      • A. Wrong — /28 is the smallest allowed VPC CIDR, the opposite end of the range from what was asked.
      • B. Correct — /16 is the largest allowed VPC CIDR, giving 65,536 IPs, the top of the allowed range.
      • C. Wrong — /8 is outside the allowed range entirely; AWS accepts nothing larger than /16 for a VPC.
      • D. Wrong — /24 is a valid size but is far from the largest; /16 is bigger and allowed.

      Scenario 3

      A VPC is created with primary CIDR 10.0.0.0/16. An engineer needs to know which address the internal DNS resolver lives at so they can reference it in a client configuration. What address should they use?

      • A. 10.0.0.2, the VPC base address plus two
      • B. 10.0.0.0, the network address of the block
      • C. 10.0.0.1, the address of the VPC router device
      • D. 10.0.0.4, reserved for future AWS use

      Topic: Custom VPCs

      Correct answer: A

      • A. Correct — the DNS resolver always lives at VPC base IP plus two, so for 10.0.0.0 that is 10.0.0.2.
      • B. Wrong — the base address itself is the network address, not a usable resolver endpoint.
      • C. Wrong — base plus one is the VPC router, a separate device from the DNS resolver.
      • D. Wrong — base plus three is reserved for future AWS use, not the resolver.

      Scenario 4

      A team launches EC2 instances with public IPv4 addresses into a new VPC but finds the instances receive no public DNS hostname. They confirm enableDnsSupport is true. What is most likely still wrong?

      • A. The VPC CIDR block is too large for hostname assignment
      • B. The instances were launched with Dedicated tenancy by mistake
      • C. enableDnsHostnames is false, since it defaults off and must be enabled
      • D. The subnet secondary CIDR has not yet been attached

      Topic: Custom VPCs

      Correct answer: C

      • A. Wrong — CIDR block size has no bearing on whether hostnames are assigned to instances.
      • B. Wrong — tenancy governs hardware placement, not DNS hostname behavior for instances.
      • C. Correct — enableDnsHostnames defaults to false and must be manually enabled; both settings must be true for public DNS hostnames.
      • D. Wrong — secondary CIDRs are optional address space additions, unrelated to hostname assignment.

      Scenario 5

      A company's VPC was created with a single /24 primary CIDR and is now running low on addresses as it grows. They want more IP space without recreating the VPC. What can they do?

      • A. Change the primary CIDR in place to a larger range
      • B. Switch the VPC tenancy to Dedicated to expand capacity
      • C. Enable enableDnsHostnames to unlock more address space
      • D. Add a secondary CIDR block to the existing VPC later on

      Topic: Custom VPCs

      Correct answer: D

      • A. Wrong — the primary CIDR is fixed at creation; it is not described as changeable in place afterward.
      • B. Wrong — tenancy governs hardware dedication, not the amount of address space available.
      • C. Wrong — this DNS setting controls hostname assignment, not IP address capacity.
      • D. Correct — a VPC has one mandatory primary CIDR, but optional secondary CIDRs can be added later to grow address space.

      Scenario 6

      A solutions architect wants a single subnet whose instances get spread automatically across two Availability Zones for resilience, to save on subnet count. Is this design achievable?

      • A. Yes, but only when the VPC uses Dedicated tenancy mode
      • B. No, since one subnet always maps to exactly one AZ only
      • C. Yes, subnets can span multiple AZs if you request it
      • D. No, because each AZ may only ever contain one subnet

      Topic: VPC Subnets

      Correct answer: B

      • A. Wrong — tenancy has no effect on how subnets map to Availability Zones.
      • B. Correct — a subnet lives in exactly one AZ; the relationship is one-directional, so spanning two AZs is not possible.
      • C. Wrong — subnets cannot span multiple AZs regardless of request; the mapping is always one subnet to one AZ.
      • D. Wrong — an AZ can hold many subnets; only the reverse direction is restricted.

      Scenario 7

      Two subnets, 10.0.1.0/24 and 10.0.2.0/24, sit inside the same VPC with no custom routes or security changes made yet. An instance in the first subnet tries to reach an instance in the second. What happens?

      • A. The connection succeeds, since same-VPC subnets reach each other by default
      • B. The connection fails until an internet gateway is attached
      • C. The connection fails until a NAT gateway is added
      • D. The connection succeeds only after DHCP options are replaced

      Topic: VPC Subnets

      Correct answer: A

      • A. Correct — subnets in the same VPC can reach each other by default with no routing configuration needed.
      • B. Wrong — an internet gateway is required for internet access, not for communication between subnets in one VPC.
      • C. Wrong — a NAT gateway is for outbound internet access from private subnets, not needed for intra-VPC traffic.
      • D. Wrong — DHCP options sets configure instance IP settings like DNS, not subnet-to-subnet reachability.

      Scenario 8

      A team provisions a new subnet using a /28 CIDR block, expecting to fit sixteen instances on it. How many addresses will actually be usable for instances in that subnet?

      • A. Eleven addresses, after five are reserved by AWS
      • B. Fourteen addresses, after two are reserved by AWS
      • C. Twelve addresses, after four are reserved by AWS
      • D. Sixteen addresses, matching the full block size exactly

      Topic: VPC Subnets

      Correct answer: A

      • A. Correct — a /28 has sixteen total addresses; subtracting the five AWS reservations leaves eleven usable.
      • B. Wrong — only two reserved understates the fixed five-address reservation AWS always applies.
      • C. Wrong — four reserved is close but not the actual fixed count; five addresses are always reserved.
      • D. Wrong — every subnet loses five IPs to AWS reservations regardless of size, so the full sixteen are never usable.

      Scenario 9

      An administrator needs to change the domain name and DNS server list that instances receive via a DHCP options set already attached to a production VPC. What is the correct way to do this?

      • A. Create a new options set and re-associate the VPC with it
      • B. Add a secondary CIDR block to force the settings to refresh
      • C. Edit the fields on the existing options set directly in place
      • D. Detach the VPC's internet gateway before editing the set

      Topic: VPC Subnets

      Correct answer: A

      • A. Correct — because sets are immutable, changing settings requires creating a new options set and re-associating the VPC with it.
      • B. Wrong — CIDR blocks control address space, not DHCP option propagation, and adding one does not refresh settings.
      • C. Wrong — DHCP options sets are immutable, so fields cannot be edited on an existing attached set.
      • D. Wrong — the internet gateway is unrelated to DHCP options sets and does not need to be touched.

      Scenario 10

      A subnet has no IPv6 CIDR associated with the VPC yet. An engineer tries to enable the auto-assign IPv6 setting on that subnet. What should they expect?

      • A. It silently falls back to assigning public IPv4 addresses instead
      • B. It works only if Dedicated tenancy is set on the VPC first
      • C. It works immediately, independent of any VPC-level IPv6 setup
      • D. It cannot work until the VPC has an IPv6 CIDR block attached

      Topic: VPC Subnets

      Correct answer: D

      • A. Wrong — auto-assign IPv6 and auto-assign public IPv4 are separate settings with no described fallback between them.
      • B. Wrong — tenancy governs hardware placement and has no relationship to IPv6 CIDR availability.
      • C. Wrong — auto-assign IPv6 is not independent; it explicitly requires the VPC to already have an IPv6 CIDR block.
      • D. Correct — auto-assign IPv6 requires the VPC to already have an IPv6 CIDR block before the subnet setting can function.

      Scenario 11

      A route table has two entries for a destination that falls inside both: one for 10.0.0.0/16 targeting a NAT gateway, and one for 10.0.0.0/24 targeting local. Traffic destined for 10.0.0.50 is being evaluated. Which route wins?

      • A. The /16 route wins, since it was likely created first
      • B. The /24 route wins, since it is the longer, more specific prefix
      • C. Neither route wins, so the packet is dropped as ambiguous
      • D. Both routes are used together by splitting the traffic evenly

      Topic: VPC Routing & Route Tables

      Correct answer: B

      • A. Wrong — route selection is based on prefix length, not creation order.
      • B. Correct — route selection uses longest-prefix-match, so the more specific /24 route beats the /16 route.
      • C. Wrong — overlapping routes are resolved deterministically by prefix length, not dropped as ambiguous.
      • D. Wrong — route tables do not split traffic between overlapping routes; one route is selected.

      Scenario 12

      A new subnet is created in a VPC and no one explicitly associates it with any route table. Which route table governs its traffic, and can that table be deleted later?

      • A. The main route table applies automatically, and it cannot be deleted
      • B. A custom table is auto-created for it, and it can be deleted anytime
      • C. The main route table applies, but it can be deleted once unused
      • D. No route table applies until one is manually attached by an admin

      Topic: VPC Routing & Route Tables

      Correct answer: A

      • A. Correct — any subnet not explicitly associated with a custom table automatically uses the main route table, which cannot be deleted, only replaced.
      • B. Wrong — no custom table is auto-created; unassociated subnets fall back to the existing main table.
      • C. Wrong — the main route table specifically cannot be deleted; only custom tables can be, and only when unassociated.
      • D. Wrong — every VPC has exactly one main route table that applies by default, so a subnet is never routeless.

      Scenario 13

      An engineer created a custom route table with a route to an internet gateway and associated it with two subnets. She now tries to delete that custom route table while the two subnets are still associated with it. What happens?

      • A. Deletion is blocked while any subnet remains associated with it
      • B. Deletion converts the table into the new main route table instead
      • C. Deletion succeeds only for the subnet with fewer IP addresses
      • D. Deletion succeeds and both subnets fall back to the main table

      Topic: VPC Routing & Route Tables

      Correct answer: A

      • A. Correct — custom route tables can be deleted, but only when no subnets are still associated with them, so deletion is blocked here.
      • B. Wrong — a custom table never becomes the main table through deletion; the main table can only be replaced, not created this way.
      • C. Wrong — deletion eligibility depends on association state, not on subnet size or IP count.
      • D. Wrong — custom tables can only be deleted if no subnets are still associated with them; it does not auto-detach first.

      Scenario 14

      A route table contains a local route for 10.0.0.0/16 and, after a peering setup, an added route for 10.0.0.0/16 targeting the peering connection, both with identical prefix length. Which route is used for traffic within that block?

      • A. The local route wins, since local always wins a tied prefix length
      • B. The route table becomes invalid and traffic in that range is dropped
      • C. The peering connection route wins because it was added more recently
      • D. Traffic alternates between the two routes on a round-robin basis

      Topic: VPC Routing & Route Tables

      Correct answer: A

      • A. Correct — when two routes tie in prefix length and one target is local, local always wins the tie.
      • B. Wrong — a tie is explicitly resolved by the local-wins rule, so the table remains valid and functional.
      • C. Wrong — recency of creation does not decide ties; only the local-target exception applies.
      • D. Wrong — route tables select a single deterministic route, not round-robin between duplicates.

      Scenario 15

      Instances in Subnet-A can reach instances in Subnet-B within the same VPC, but Subnet-A instances cannot reach the internet, while Subnet-B instances can. Both subnets use custom route tables. What is the most likely explanation?

      • A. Subnet-A and Subnet-B must be in different, unrelated VPCs
      • B. The VPC router has failed for Subnet-A but not for Subnet-B
      • C. Subnet-A's DHCP options set was never associated with the VPC
      • D. Subnet-A's route table is missing a route to an internet gateway

      Topic: VPC Routing & Route Tables

      Correct answer: D

      • A. Wrong — the two subnets are clearly communicating directly, which is only possible within the same VPC.
      • B. Wrong — the VPC router is a single highly-available device serving the whole VPC, not per-subnet, so it cannot fail for just one subnet.
      • C. Wrong — DHCP options sets configure IP settings like DNS, not internet routing reachability.
      • D. Correct — local intra-VPC routing works automatically, but internet access needs an explicit route in that subnet's table to an internet gateway target.

      Scenario 16

      An EC2 instance in a public subnet sends a request to an internet host. The instance's own OS-level network configuration shows only a private IPv4 address, yet the response arrives correctly from the internet. Where does the mapping between the instance's private IP and its public IP actually live?

      • A. Inside the subnet's route table entries
      • B. Inside the EC2 instance's own OS network stack
      • C. Inside the security group attached to the instance
      • D. Inside the internet gateway attached to the VPC

      Topic: Internet Gateway (IGW)

      Correct answer: D

      • A. Wrong — the route table only directs traffic toward the IGW, it does not store any IP address mapping.
      • B. Wrong — the OS never sees its own public IP; the instance only knows its private IP.
      • C. Wrong — a security group filters traffic by rule, it plays no role in address translation.
      • D. Correct — the IGW performs static NAT and holds the private-to-public IP mapping itself, translating traffic as it passes through.

      Scenario 17

      A solutions architect wants to give a VPC two separate internet gateways so that traffic can exit through either one for redundancy. When they attempt to attach a second IGW to the same VPC, the console blocks the action. What does this confirm about IGW-to-VPC relationships?

      • A. A VPC may attach two IGWs if in different regions
      • B. A VPC may attach one IGW per AZ it uses
      • C. A VPC may attach at most one IGW at any time
      • D. A VPC may attach unlimited IGWs for redundancy

      Topic: Internet Gateway (IGW)

      Correct answer: C

      • A. Wrong — a VPC lives in one region, and the one-IGW limit applies regardless of region framing.
      • B. Wrong — a single IGW is already region-resilient and covers every AZ in the region, so per-AZ attachment isn't how it works.
      • C. Correct — a VPC can have zero or one IGW attached, never more than one at a time.
      • D. Wrong — this directly contradicts the strict zero-or-one limit on IGW attachment per VPC.

      Scenario 18

      A subnet has an IGW attached to its VPC, a route table associated with it that sends 0.0.0.0/0 to the IGW, and instances launched in it still cannot be reached from the internet even though they boot successfully. Auto-assign public IPv4 was never enabled on the subnet. What is missing from the required setup?

      • A. The IGW needs a second route table binding
      • B. A NAT gateway must be created in the subnet
      • C. Instances need a public IPv4 address assigned
      • D. The VPC needs a second IGW for inbound traffic

      Topic: Internet Gateway (IGW)

      Correct answer: C

      • A. Wrong — a route table is associated with a subnet, not bound a second time to the IGW itself.
      • B. Wrong — a NAT gateway is for private subnet outbound access, not for making a public subnet reachable inbound.
      • C. Correct — without auto-assign public IPv4 enabled, instances launch with only private IPs, skipping the final step of the six-step public-subnet process.
      • D. Wrong — a VPC can never have more than one IGW, so this option is impossible regardless.

      Scenario 19

      A dual-stack VPC has instances configured with both IPv4 and IPv6 addresses. An administrator inspects an instance's OS network configuration and notices the IPv6 address shown matches exactly what external hosts see, while the IPv4 address shown is only the private one. Why does the IGW behave differently for IPv6?

      • A. IPv6 addresses are private by default so no translation is needed
      • B. IPv6 traffic is translated by the route table instead of the IGW
      • C. IPv6 uses a second hidden IGW dedicated to translation
      • D. IPv6 addresses are globally routable so the IGW passes them through unchanged

      Topic: Internet Gateway (IGW)

      Correct answer: D

      • A. Wrong — IPv6 addresses assigned in this scenario are globally routable, not private, which is exactly why no translation occurs.
      • B. Wrong — route tables direct traffic paths, they do not perform any address translation for either protocol.
      • C. Wrong — there is only ever one IGW per VPC, and it handles both address families without a second dedicated device.
      • D. Correct — IPv6 addresses are globally routable and visible directly to the OS, so the IGW does not translate them at all, unlike its static NAT behavior for IPv4.

      Scenario 20

      A newly created VPC has subnets, route tables, and EC2 instances, but no internet gateway has ever been created or attached to it. A team member asks whether any instance in this VPC could still be reachable from or reach the public internet. What is the correct assessment?

      • A. Yes, if the subnet enables auto-assign public IPv4
      • B. No, the VPC is entirely private with no IGW attached
      • C. Yes, as long as the security group allows all traffic
      • D. Yes, if the route table has a 0.0.0.0/0 route entry

      Topic: Internet Gateway (IGW)

      Correct answer: B

      • A. Wrong — auto-assign public IPv4 only assigns an address, it cannot create internet reachability without an IGW to translate and route the traffic.
      • B. Correct — a VPC with no IGW attached is entirely private; there is no path in or out to the public internet regardless of other configuration.
      • C. Wrong — a permissive security group only controls what traffic is allowed, it cannot substitute for the missing physical path an IGW provides.
      • D. Wrong — a default route to an IGW that does not exist has nowhere to send traffic, so this route alone changes nothing.

      Scenario 21

      A company needs administrators to manage EC2 instances that sit in private subnets with no internet exposure. They deploy a single hardened EC2 instance in a public subnet configured for SSH access, and admins connect to that instance first before hopping to the private instances. What is this architecture pattern called?

      • A. An internet gateway with SSH routing
      • B. A bastion host acting as a jump box
      • C. A NAT gateway forwarding admin sessions
      • D. A load balancer terminating SSH traffic

      Topic: Bastion Hosts

      Correct answer: B

      • A. Wrong — an IGW simply connects a VPC to the internet, it has no concept of routing SSH sessions between hosts.
      • B. Correct — a bastion host is a single EC2 instance in a public subnet used as a hardened, auditable jump box into private-subnet instances.
      • C. Wrong — a NAT gateway handles outbound traffic from private instances to the internet, not inbound admin access into the VPC.
      • D. Wrong — a load balancer distributes application traffic across targets, it is not designed as an administrative entry point.

      Scenario 22

      A security review finds that a bastion host's security group allows inbound SSH from 0.0.0.0/0, and the private instances' security groups allow inbound SSH from the entire VPC CIDR range rather than from the bastion specifically. What change correctly hardens this setup according to bastion best practice?

      • A. Restrict bastion inbound to admin IPs, leave private instances open to the VPC
      • B. Restrict bastion inbound to admin IPs, restrict private instances to the bastion
      • C. Leave bastion inbound open, restrict private instances to the bastion only
      • D. Move the bastion into the private subnet for extra isolation

      Topic: Bastion Hosts

      Correct answer: B

      • A. Wrong — this violates the requirement that private instances only trust the bastion specifically, leaving them open to any host in the VPC.
      • B. Correct — the bastion's security group should allow only known admin IPs, and private instances should allow only the bastion's IP or security group, not the whole VPC.
      • C. Wrong — this violates the requirement that the bastion itself only accept traffic from known admin IPs rather than the whole internet.
      • D. Wrong — a bastion must sit in a public subnet with a reachable public IP; it cannot function placed in a private subnet.

      Scenario 23

      A junior engineer proposes replacing the company's bastion host with a NAT gateway, arguing both let traffic cross between public and private subnets so they must be interchangeable. Why is this reasoning incorrect?

      • A. A NAT gateway handles outbound access, a bastion handles inbound admin access
      • B. A NAT gateway sits in a private subnet, a bastion sits in a public one
      • C. A NAT gateway is stateful, a bastion host is stateless by design
      • D. A NAT gateway requires key-based authentication, a bastion does not

      Topic: Bastion Hosts

      Correct answer: A

      • A. Correct — a NAT gateway lets private instances reach out to the internet, while a bastion lets admins reach in to private instances; the directions of access solve opposite problems.
      • B. Wrong — this reverses the facts; a NAT gateway is placed in a public subnet and a bastion must also be in a public subnet, not a private one.
      • C. Wrong — statefulness is a firewall/connection-tracking concept unrelated to what distinguishes these two services from each other.
      • D. Wrong — key-based authentication is a bastion hardening practice, not something meaningfully attributed to a NAT gateway at all.

      Scenario 24

      An architect is deciding where to place a bastion host that administrators will use to reach private EC2 instances over SSH. Which subnet placement is required for the bastion to function at all?

      • A. A dedicated subnet with no route table attached
      • B. Either subnet, as long as a NAT gateway also exists
      • C. A public subnet, since it needs a reachable public IP
      • D. A private subnet, since it must stay hidden from attackers

      Topic: Bastion Hosts

      Correct answer: C

      • A. Wrong — a subnet with no route table cannot route traffic anywhere, which would isolate the bastion entirely.
      • B. Wrong — a NAT gateway provides outbound internet access for private instances, it does not give the bastion the inbound reachability it needs.
      • C. Correct — a bastion must be in a public subnet because it needs a public IP that admins can reach from the internet.
      • D. Wrong — hiding it in a private subnet would make it unreachable from the internet, defeating its purpose as an entry point.

      Scenario 25

      During an audit, a security team wants confidence that if the bastion host is ever compromised, the blast radius and forensic trail are minimized. Which combination of practices best reflects proper bastion hardening?

      • A. Full admin toolset installed, password auth only, no logging enabled
      • B. Full admin toolset installed, key-based auth, logging disabled
      • C. Minimal installed software, key-based auth only, sessions logged
      • D. Minimal installed software, shared password auth, sessions not logged

      Topic: Bastion Hosts

      Correct answer: C

      • A. Wrong — this violates every hardening practice: extra software widens attack surface, passwords are disallowed, and unlogged sessions prevent auditing.
      • B. Wrong — installing a full admin toolset and disabling logging both violate hardening practice despite correct key-based authentication.
      • C. Correct — hardening practice calls for no unnecessary software, key-based authentication only, and logged sessions for audit purposes.
      • D. Wrong — shared passwords and no session logging both violate the stated hardening requirements even though the software footprint is minimal.

      Scenario 26

      A client opens a TCP connection to a web server on port 443. The client's OS chooses port 51422 to receive the response. A network engineer is asked to explain, in general terms, what determines that response port number. What is the correct explanation?

      • A. The firewall assigns a fixed response port per protocol
      • B. The client OS picks a random ephemeral port for that connection
      • C. The response always reuses port 80 regardless of request port
      • D. The server always echoes back its own listening port 443

      Topic: Stateful vs Stateless Firewalls

      Correct answer: B

      • A. Wrong — firewalls do not assign ephemeral ports, that selection is made by the client operating system.
      • B. Correct — the response phase returns to whichever ephemeral port, typically randomly chosen in the 1024-65535 range, the client OS selected for that connection.
      • C. Wrong — port 80 has no special role here, the response port depends on the client's ephemeral choice, not a fixed reused value.
      • D. Wrong — the well-known port 443 is the server's listening port for the request, the response goes to the client's chosen port, not back to 443.

      Scenario 27

      A firewall evaluates every packet in isolation, with no memory of any packet that came before it, and therefore cannot recognize that a returning packet belongs to an already-approved outbound request. Which type of firewall behavior does this describe?

      • A. Stateless firewall behavior
      • B. Stateful firewall behavior
      • C. Application-layer firewall behavior
      • D. Connection-tracking firewall behavior

      Topic: Stateful vs Stateless Firewalls

      Correct answer: A

      • A. Correct — a stateless firewall evaluates every packet in isolation with no memory of prior packets, so it cannot tell a response belongs to an approved request.
      • B. Wrong — a stateful firewall tracks connections and automatically allows the matching response, which is the opposite of what's described.
      • C. Wrong — this scenario describes packet-level state tracking, not application-layer inspection, which is a different concept entirely.
      • D. Wrong — connection tracking is exactly the capability being described as absent, so this label contradicts the scenario.

      Scenario 28

      A team configures a stateless firewall to allow a web server to receive HTTPS requests and successfully send back responses. They only add one inbound rule permitting TCP port 443 from any client. What is missing given the requirement that responses must also reach clients?

      • A. A stateful inspection module bolted onto the same rule set
      • B. An inbound rule allowing traffic on port 80 as a fallback
      • C. A second inbound rule duplicating port 443 for redundancy
      • D. An outbound rule allowing the full ephemeral port range back to clients

      Topic: Stateful vs Stateless Firewalls

      Correct answer: D

      • A. Wrong — adding stateful inspection would change the firewall's fundamental behavior rather than fixing the rule set within a stateless design.
      • B. Wrong — port 80 is unrelated to this HTTPS scenario and does not address the missing outbound response rule.
      • C. Wrong — duplicating the same inbound rule does nothing for the outbound response leg of the connection, which is what's actually missing.
      • D. Correct — stateless firewalls need a separate outbound rule for the response, covering the full 1024-65535 ephemeral range since the exact client port can't be predicted.

      Scenario 29

      Comparing two firewall designs for the same request/response traffic pattern, one requires exactly two explicit rules per connection direction while the other requires only one rule for the initial request and automatically permits the matching response. What distinguishes the second design's ability to do this with just one rule?

      • A. It tracks approved connections and auto-allows their matching responses
      • B. It opens every ephemeral port permanently for all clients
      • C. It relies on the client to re-request access for each response
      • D. It disables port filtering entirely for return traffic

      Topic: Stateful vs Stateless Firewalls

      Correct answer: A

      • A. Correct — a stateful firewall tracks connections, so once a request is approved the matching response, even on a random ephemeral port, is automatically allowed without a separate rule.
      • B. Wrong — permanently opening every ephemeral port would remove filtering rather than intelligently matching responses to approved requests.
      • C. Wrong — responses are server-to-client traffic and are not re-requested by the client, so this describes no real mechanism.
      • D. Wrong — the firewall is not disabling filtering, it is using connection state to selectively permit only the legitimate response.

      Scenario 30

      A network designer notes that with a stateless firewall, because the exact ephemeral port a client will use cannot be predicted in advance, the outbound rule permitting responses must cover the entire 1024-65535 range rather than a single port. What is the direct consequence of this for the network's security posture?

      • A. It eliminates the need for any outbound rule at all
      • B. It narrows exposure since only the request port needs opening
      • C. It has no security consequence since ports are irrelevant to exposure
      • D. It creates wider exposure since a broad port range must stay open

      Topic: Stateful vs Stateless Firewalls

      Correct answer: D

      • A. Wrong — a stateless firewall still requires an explicit outbound rule for responses, it does not eliminate that requirement.
      • B. Wrong — this reverses the fact; the request port alone is not enough, the wide response range is what actually must stay open.
      • C. Wrong — open port ranges directly affect attack surface, so claiming no consequence ignores the stated exposure tradeoff.
      • D. Correct — having to open the full ephemeral range for responses creates wider exposure, since the specific port a client will use can't be predicted ahead of time.

      Scenario 31

      Two EC2 instances, A and B, sit in the same subnet and communicate directly with each other. The subnet's NACL has a rule at position 100 that denies all traffic. Does this NACL rule block the traffic between A and B?

      • A. No, but only if both instances share a security group
      • B. No, NACLs only filter traffic crossing the subnet boundary
      • C. Yes, unless an explicit allow rule is numbered lower
      • D. Yes, NACL rules apply to all traffic inside the subnet

      Topic: Network ACLs (NACLs)

      Correct answer: B

      • A. Wrong — security group membership is irrelevant to whether a NACL applies; NACLs attach to subnets, not instances or SGs.
      • B. Correct — a NACL is applied at the subnet boundary and filters traffic entering or leaving the subnet; traffic between two instances in the same subnet never crosses that boundary, so it is unaffected.
      • C. Wrong — rule ordering only matters for traffic the NACL actually evaluates, and boundary-crossing traffic is a prerequisite that isn't met here.
      • D. Wrong — this misunderstands where a NACL filters; it never inspects intra-subnet traffic between instances, regardless of the rule.

      Scenario 32

      A subnet's NACL has rule 50 allowing inbound TCP 443 from 0.0.0.0/0, and rule 40 denying inbound TCP 443 from 0.0.0.0/0. A client attempts to reach an instance in the subnet over HTTPS. What happens?

      • A. Traffic is allowed, since allow always wins over deny
      • B. Traffic is denied by the implicit asterisk rule instead
      • C. Traffic is allowed, since higher numbers take priority
      • D. Traffic is denied, since rule 40 is evaluated first

      Topic: Network ACLs (NACLs)

      Correct answer: D

      • A. Wrong — NACLs have no concept of "allow always wins"; only rule order (lowest number first) determines the outcome.
      • B. Wrong — the implicit deny (*) is only used when nothing else matches; rule 40 matches first, so the asterisk rule is never reached.
      • C. Wrong — this reverses the actual evaluation order; lower-numbered rules are checked first, not higher-numbered ones.
      • D. Correct — NACL rules are evaluated in ascending numeric order and processing stops at the first match; rule 40 is lower than rule 50, so the deny is hit first and wins even though an allow exists later.

      Scenario 33

      A team creates a brand-new custom NACL in their VPC and does not add any rules to it yet. Before associating it with any subnet, what is its effective behavior if it were applied?

      • A. It allows all traffic in both directions by default
      • B. It allows inbound only, blocking all outbound traffic
      • C. It blocks all traffic in both directions by default
      • D. It copies the rules from the VPC's default NACL

      Topic: Network ACLs (NACLs)

      Correct answer: C

      • A. Wrong — allow-all-by-default is the behavior of the default NACL (which starts with rule 100 allow-all), not a newly created custom NACL.
      • B. Wrong — a custom NACL blocks both inbound and outbound by default; it does not selectively allow inbound.
      • C. Correct — a custom NACL starts with only the implicit deny rule in both directions, so the net effect is that all traffic is blocked until rules are explicitly added.
      • D. Wrong — a custom NACL is created empty (aside from the implicit deny); it does not inherit or copy rules from the default NACL.

      Scenario 34

      An administrator adds an inbound NACL rule allowing TCP 443 from 0.0.0.0/0 on a subnet, but web clients still cannot complete HTTPS requests to instances in that subnet. What is the most likely missing piece?

      • A. A security group rule allowing TCP 443 inbound as well
      • B. Renumbering the inbound rule to a lower rule number
      • C. An outbound rule allowing the ephemeral port range back to clients
      • D. Associating the same NACL with the client's own subnet

      Topic: Network ACLs (NACLs)

      Correct answer: C

      • A. Wrong — this is plausible in general but the scenario already establishes the inbound path is allowed; it doesn't explain a stateless-return-traffic failure the way a missing ephemeral outbound rule does.
      • B. Wrong — rule numbering only matters when multiple rules conflict; there's no indication of a conflicting rule here, so renumbering wouldn't fix a missing return-path rule.
      • C. Correct — NACLs are stateless, so return traffic is not automatically permitted; an outbound rule allowing the ephemeral port range is needed for the response to reach the client.
      • D. Wrong — NACLs apply per subnet based on where the resource sits, not the client's subnet; associating the NACL with the client's subnet is not how return traffic is enabled.

      Scenario 35

      A security team wants to explicitly block a single malicious IP address, 203.0.113.55, from reaching any resource in a subnet, while still allowing all other traffic. Which approach works, and why?

      • A. Removing the default NACL from the subnet entirely
      • B. A security group rule, since SGs filter by source IP too
      • C. A security group rule referencing the malicious IP's SG
      • D. A NACL rule, since NACLs can explicitly deny by IP/CIDR

      Topic: Network ACLs (NACLs)

      Correct answer: D

      • A. Wrong — removing a NACL association doesn't block anything; the subnet would simply fall back to another NACL, and this does nothing to target the specific IP.
      • B. Wrong — security groups can only allow traffic; there is no explicit deny rule, so you cannot use an SG to block one IP while allowing the rest.
      • C. Wrong — an SG source can reference another SG, but that only creates allow rules for resources with that SG attached, not a deny for an external malicious IP.
      • D. Correct — NACLs are the only AWS firewall that can explicitly deny traffic by IP/CIDR, making them the right tool to block one specific address while allowing everything else.

      Scenario 36

      An EC2 instance receives an inbound SSH connection that is permitted by its security group's inbound rule. No outbound rule was ever added for the response traffic. Does the SSH response reach the client?

      • A. No, because SGs only track state for HTTP and HTTPS traffic
      • B. Yes, because security groups are stateful and auto-allow returns
      • C. Yes, but only if the instance sits in a public subnet
      • D. No, an outbound rule must be manually added for the response

      Topic: Security Groups

      Correct answer: B

      • A. Wrong — SG statefulness applies to all allowed traffic and protocols, not a special case limited to HTTP/HTTPS.
      • B. Correct — security groups are stateful, so an allowed inbound connection automatically permits its matching outbound response with no extra rule required.
      • C. Wrong — statefulness is an inherent property of the security group itself, unrelated to whether the subnet is public or private.
      • D. Wrong — this describes stateless behavior, which applies to NACLs, not security groups; SGs never require a separate return-traffic rule.

      Scenario 37

      An architect wants to allow all traffic except from one specific known-bad IP range, while allowing everything else through to an instance. They only have security groups available. What is the outcome of trying to do this with a security group alone?

      • A. It works automatically since SGs deny unlisted CIDRs
      • B. It works by lowering the deny rule's priority number
      • C. It cannot be done — SGs have no explicit deny rule at all
      • D. It works by adding a deny rule above the allow-all rule

      Topic: Security Groups

      Correct answer: C

      • A. Wrong — SGs don't compare listed vs. unlisted CIDRs to infer denies; anything not explicitly allowed is implicitly denied, but that's not the same as being able to carve out an exception for one bad range while allowing all others.
      • B. Wrong — security group rules don't have a priority-number system like NACLs, and there is no deny rule to prioritize in the first place.
      • C. Correct — security groups can only allow traffic; there is no explicit deny rule mechanism, so blocking one specific range while allowing the rest is impossible with an SG alone (a NACL is needed instead).
      • D. Wrong — SGs have no deny rule concept at all, so there is no "deny rule" to place above anything, regardless of ordering.

      Scenario 38

      A cluster of application servers needs to let any member communicate with any other member on port 7000, and the cluster will scale up and down frequently as demand changes. What SG configuration avoids needing rule updates every time an instance is added or removed?

      • A. A rule allowing the entire VPC CIDR range on port 7000
      • B. A NACL rule permitting the subnet's own CIDR block
      • C. A self-referencing rule allowing traffic from the same SG
      • D. A rule listing each instance's private IP individually

      Topic: Security Groups

      Correct answer: C

      • A. Wrong — this is broader than needed and would allow any resource in the whole VPC on that port, not just cluster members, weakening the security posture.
      • B. Wrong — NACLs cannot reference logical groupings like "instances with this SG," and they operate at the subnet boundary, not between instances in the same subnet.
      • C. Correct — a self-referencing rule lets any two resources sharing that SG talk to each other, and it stays correct automatically as instances are added or removed with no rule updates needed.
      • D. Wrong — this violates the scaling requirement, since listing individual IPs would require manual updates every time an instance is added or removed.

      Scenario 39

      An EC2 instance's network interface needs to satisfy two separate requirements: one rule set for general SSH management access, and a completely different rule set for application traffic from a load balancer. How many security groups can be attached to the single ENI to achieve this?

      • A. Multiple security groups can be attached at the same time
      • B. Two, but only if both are attached to the instance itself
      • C. Only one security group can ever attach to an ENI
      • D. None — rules must be merged into a single rule set first

      Topic: Security Groups

      Correct answer: A

      • A. Correct — a single ENI can have multiple security groups attached simultaneously, letting the SSH rule set and the application rule set coexist as separate SGs on the same interface.
      • B. Wrong — security groups attach to the ENI, not to the instance itself, so framing it as "attached to the instance" misstates the attachment point even though the numeric answer happens to be plausible.
      • C. Wrong — this contradicts how SGs work; ENIs support multiple attached security groups, not just one.
      • D. Wrong — there's no need to merge rules into one SG; AWS explicitly supports attaching several SGs to cover distinct rule sets.

      Scenario 40

      A database tier's security group needs to accept connections on port 3306 only from the web tier's instances, and the web tier's instance count changes often. Which source configuration is most maintainable for the database SG's inbound rule?

      • A. List the current private IPs of all web tier instances
      • B. Allow the full VPC CIDR block as the source
      • C. Reference the web tier's security group as the source
      • D. Reference the web tier's Auto Scaling group name directly

      Topic: Security Groups

      Correct answer: C

      • A. Wrong — this violates the maintainability requirement, since IPs would need constant manual updates as the web tier's instance count changes.
      • B. Wrong — this is broader than intended, allowing any resource in the VPC to reach the database on 3306, not just the web tier.
      • C. Correct — SG rules can reference another security group as the source, meaning any ENI with the web tier's SG attached is allowed, which stays accurate as instances scale without tracking raw IPs.
      • D. Wrong — security group rules reference other security groups (or IPs/CIDRs), not Auto Scaling group names directly; that isn't a valid source type for an SG rule.

      Scenario 41

      Instances in a private subnet need outbound-only internet access to download OS updates, without being reachable from the internet. A NAT Gateway is deployed in a public subnet with an Elastic IP attached. What must the private subnet's route table contain for this to work?

      • A. A route to the NAT Gateway's private subnet CIDR only
      • B. A default route 0.0.0.0/0 pointing to the IGW directly
      • C. No route needed, since NAT works without routing changes
      • D. A default route 0.0.0.0/0 pointing to the NAT Gateway

      Topic: NAT & NAT Gateway

      Correct answer: D

      • A. Wrong — a route limited to the NAT Gateway's own subnet CIDR wouldn't send general internet-bound traffic (0.0.0.0/0) to the NAT Gateway at all.
      • B. Wrong — routing directly to the IGW would make instances need public IPs and be reachable inbound, violating the outbound-only, non-reachable requirement.
      • C. Wrong — NAT Gateway functionality depends entirely on the route table directing traffic to it; without that route, private instances have no path out.
      • D. Correct — the private subnet's route table needs a default route 0.0.0.0/0 targeting the NAT Gateway so outbound traffic is directed there before reaching the internet via the IGW.

      Scenario 42

      A company deploys a single NAT Gateway in AZ-A and routes the private subnets of AZ-A, AZ-B, and AZ-C all to it. AZ-A later suffers a complete outage. What happens to outbound internet access for private instances in AZ-B and AZ-C?

      • A. They keep outbound access, since NAT Gateways are regionally resilient
      • B. They lose outbound access too, since all AZs route to AZ-A's NAT
      • C. They lose only inbound access, outbound is unaffected entirely
      • D. They keep outbound access, since each AZ has its own hidden NAT

      Topic: NAT & NAT Gateway

      Correct answer: B

      • A. Wrong — a NAT Gateway is only AZ-resilient, not regionally resilient; it survives hardware failure within its AZ but goes down if the whole AZ fails.
      • B. Correct — routing all AZs to a single NAT Gateway in one AZ is a single point of failure; if that AZ fails, every private subnet routed to it loses outbound internet, even subnets in otherwise healthy AZs. This is the classic "zonal" NAT Gateway (the default kind, and the one this exam scope tests) — AWS has since also introduced a "regional" NAT Gateway mode that automatically expands across AZs and removes the need to deploy one per AZ, but zonal NAT Gateways still work exactly as described here and remain a common deployment.
      • C. Wrong — NAT Gateways only ever provided outbound-only access in the first place, and that outbound path is exactly what's lost when the NAT Gateway's AZ fails.
      • D. Wrong — there is no automatic hidden NAT Gateway per AZ; achieving per-AZ resilience with a zonal NAT Gateway requires deliberately deploying one per AZ (AWS's newer regional NAT Gateway mode automates this, but that's a distinct, opt-in resource type).

      Scenario 43

      An engineer wants an outbound internet gateway solution for private instances that also supports attaching a security group directly to the gateway resource itself and can double as a bastion host. Which NAT option fits, and why?

      • A. A NAT Gateway, since it is the AWS-recommended default
      • B. A NAT Instance, since it supports SGs and bastion use
      • C. A NAT Gateway, since it accepts SGs for inbound filtering
      • D. An Egress-Only Internet Gateway, since it supports SGs

      Topic: NAT & NAT Gateway

      Correct answer: B

      • A. Wrong — while NAT Gateway is generally preferred for its managed scaling, it explicitly does not support security groups (NACLs only) and cannot serve as a bastion host, so it fails these specific requirements.
      • B. Correct — a NAT Instance is EC2-based, self-managed, does support security groups, and can double as a bastion host, matching both stated requirements.
      • C. Wrong — this violates a stated fact directly: NAT Gateway does not support security groups at all, relying on NACLs instead.
      • D. Wrong — an Egress-Only IGW is for IPv6 outbound-only traffic, not for SG attachment or bastion functionality, and it isn't a NAT mechanism for IPv4.

      Scenario 44

      A workload in a dual-stack subnet needs to reach other IPv6 hosts on the internet directly over IPv6, with no inbound connections permitted and no translation of its traffic to IPv4 along the way. Which service fits, and why can't a NAT Gateway be used for this specific need?

      • A. A standard NAT Gateway configured for IPv6 addressing
      • B. A NAT Instance with an IPv6 Elastic IP attached to it
      • C. A regular Internet Gateway with a restrictive NACL rule
      • D. An Egress-Only Internet Gateway for IPv6 outbound traffic

      Topic: NAT & NAT Gateway

      Correct answer: D

      • A. Wrong — a NAT Gateway's IPv6 capability (NAT64) only translates traffic from IPv6-only resources to IPv4 destinations; it has no mode for native IPv6-to-IPv6 pass-through, so it can't serve this specific need even though it isn't IPv6-blind anymore.
      • B. Wrong — Elastic IPs are IPv4 addresses used for NAT's many-to-one IPv4 translation; NAT (Gateway or Instance) is not the outbound-only IPv6-to-IPv6 mechanism this scenario needs.
      • C. Wrong — a regular IGW provides two-way reachability for IPv6 (addresses are globally routable and public by default), which would leave the workload reachable inbound, violating the outbound-only requirement.
      • D. Correct — an Egress-Only Internet Gateway is purpose-built for outbound-only IPv6-to-IPv6 connectivity with no inbound reachability, which is exactly what's needed when native (non-translated) IPv6 traffic must leave the VPC one-way.

      Scenario 45

      A private instance sends a request to the internet through a NAT Gateway. Trace the source IP as the packet travels: private instance to VPC router, to NAT Gateway, to IGW, to the internet. What does the NAT Gateway do to the packet's source IP as it passes through?

      • A. Swaps the source IP to the NAT Gateway's own private IP
      • B. Leaves the source IP unchanged for the IGW to modify later
      • C. Swaps the source IP directly to the Elastic IP itself
      • D. Swaps the source IP to a randomly chosen public IP

      Topic: NAT & NAT Gateway

      Correct answer: A

      • A. Correct — the NAT Gateway records the connection and swaps the source IP to its own private IP; the IGW then swaps that to the Elastic IP as the packet continues outward.
      • B. Wrong — the source IP is not left unchanged at the NAT Gateway; the whole point of NAT translation is that the NAT Gateway actively rewrites the source IP as traffic passes through it.
      • C. Wrong — this skips a step; the NAT Gateway itself swaps to its private IP first, and it is the IGW that performs the subsequent swap to the Elastic IP, not the NAT Gateway directly.
      • D. Wrong — the replacement IP isn't random; it follows a defined path (NAT Gateway's private IP, then the IGW rewrites to the fixed Elastic IP), not an arbitrary public address.

Subnets and Availability Zones

A subnet is a subdivision of a VPC's IP address space that lives inside a single Availability Zone. Subnets are AZ-resilient: if the AZ hosting a subnet fails, that subnet and the resources in it become unavailable. This is why production architectures spread resources across subnets in multiple AZs.

The relationship is one-directional: one subnet belongs to exactly one AZ, but an AZ can contain zero or many subnets. All subnets inside the same VPC can communicate with each other by default — no routing configuration is required for intra-VPC traffic.

Exam tip
Subnets start entirely private. Making a subnet public requires additional steps (Internet Gateway + route table + auto-assign public IP). The presence of a subnet does not automatically mean internet access.

The Five Reserved IP Addresses

Every subnet loses 5 IP addresses to AWS reservations — these cannot be assigned to instances. Using the example subnet 10.16.16.0/20 (range 10.16.16.0 → 10.16.31.255):

AddressOffsetReserved for
10.16.16.0+0Network address (identifies the subnet itself)
10.16.16.1+1VPC router (default gateway for the subnet)
10.16.16.2+2DNS resolver (Route 53 resolver for the VPC)
10.16.16.3+3Reserved by AWS for future use
10.16.31.255lastBroadcast address (not used in AWS, but still reserved)

A /28 subnet has 16 raw addresses; after reservations only 11 are usable. Factor this in when sizing subnets.

DHCP Options Sets and Auto-Assign

Instances in a VPC receive their IP configuration automatically through a DHCP options set. One options set is attached to a VPC at a time, and that configuration flows down to every subnet. You can create a new options set to change settings (e.g. custom DNS servers or domain names), but you cannot edit an existing options set — you must create a new one and then reassign the VPC to it.

At the subnet level, two optional settings extend this behaviour:

SettingEffect
Auto-assign public IPv4Every instance launched into the subnet automatically receives a public IPv4 address in addition to its private IP
Auto-assign IPv6Every instance launched into the subnet automatically receives an IPv6 address (requires the VPC to have an IPv6 CIDR block)

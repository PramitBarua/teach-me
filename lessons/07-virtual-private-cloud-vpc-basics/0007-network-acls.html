Network Access Control Lists (NACLs)

Lesson 07 of 09 · ~9 min

Source: Adrian Cantrill SAA-C03 · AWS NACLs Docs

What NACLs Do and Where They Sit

A Network Access Control List (NACL) is a stateless firewall applied at the subnet boundary. It filters traffic as it crosses into or out of the subnet — not traffic that stays within the subnet. EC2 instances communicating with each other inside the same subnet are unaffected by NACLs.

Each NACL has two independent rule sets:

  • Inbound rules — evaluated when traffic enters the subnet from outside.
  • Outbound rules — evaluated when traffic exits the subnet to outside.

Because NACLs are stateless, you must create matching rules in both directions for any connection to work — including allowing the ephemeral port range for responses.

Rule Numbering and Evaluation

NACL rules are numbered and evaluated in ascending order. The first rule that matches the traffic is applied and processing stops — lower numbers win.

The asterisk (*) rule is the implicit deny — it always sits at the bottom and cannot be removed. If no numbered rule matches, this rule denies the traffic.

Exam tip
NACLs are the only AWS firewall that can explicitly deny traffic by IP or CIDR range. Security Groups have no explicit deny — they only allow or implicitly deny. Use a NACL to block a specific bad IP address.

What NACLs Cannot See

NACLs work only with IP addresses, CIDR ranges, ports, and protocols. They have no awareness of AWS logical resources — you cannot write a NACL rule that references an EC2 instance, a Security Group, or an S3 bucket by name. NACLs can only be associated with subnets, not with individual resources. Each subnet can have exactly one NACL; one NACL can be associated with many subnets.

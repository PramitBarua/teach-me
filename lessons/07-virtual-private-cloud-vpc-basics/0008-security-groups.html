Security Groups

Lesson 08 of 09 · ~9 min

Source: Adrian Cantrill SAA-C03 · AWS Security Groups Docs

Where Security Groups Are Attached

A Security Group (SG) is attached to an Elastic Network Interface (ENI) — not to an EC2 instance, not to a subnet. Because an instance has an ENI, the effect is the same in practice, but the distinction matters: the SG filters traffic at the network card level, and a single ENI can have multiple security groups applied simultaneously.

An SG is stateful. When an inbound connection is allowed, the corresponding outbound response is automatically permitted — and vice versa — with no additional rule needed.

Allow Only — No Explicit Deny

Security Groups can only allow traffic. There is no explicit deny rule. Everything that is not explicitly allowed is implicitly denied. This means:

  • You cannot use an SG to block a specific IP while allowing everything else.
  • To block a specific source, you must use a NACL.
Exam tip
SG = stateful, no explicit deny. NACL = stateless, can explicitly deny. When a question asks how to block a specific IP, the answer is always NACL.

Referencing Logical Resources

Unlike NACLs, Security Groups can reference AWS logical resources as the source or destination of a rule — not just IP addresses and CIDR ranges. You can write a rule like "allow inbound TCP 3306 from sg-webserver", meaning: allow traffic from any ENI that has the webserver Security Group attached. This is far more maintainable than tracking IP addresses as instances scale up or down.

Self-Referencing

A Security Group can reference itself in a rule. A self-referencing rule means: allow all traffic from any resource that is also a member of this Security Group. This is the canonical way to allow intra-tier communication in a multi-instance cluster:

ScenarioRule to addEffect
10 app servers in the same SG need to communicate with each other Inbound: All TCP from this SG (self-reference) All 10 can talk to each other; adding or removing instances needs no rule update
Database tier allows access from web tier only Inbound TCP 3306 from web-tier SG Any instance in the web SG can reach the DB; IP changes are irrelevant

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. An EC2 instance has a Security Group that allows inbound TCP 443. The SG has no outbound rules (only the default allow-all). A client connects on port 443. Will the server's response reach the client?

2. You want to block all traffic from the IP range 198.51.100.0/24 from reaching instances in a security group. You add a deny rule in the SG. What happens?

3. You have a cluster of 20 EC2 instances, all in the same Security Group, that must communicate freely with each other. As instances are added and removed, IP addresses change. What is the most maintainable SG rule to enable this?

Internet Gateway (IGW)

Lesson 04 of 09 · ~10 min

Source: Adrian Cantrill SAA-C03 · AWS IGW Docs

What is an Internet Gateway?

An Internet Gateway (IGW) is the component that connects a VPC to the public internet and to AWS public-zone services (S3, SQS, SNS, etc.). It is region-resilient — a single IGW covers all AZs in the region, so you do not need one per AZ.

Key constraints:

  • A VPC can have zero or one IGW — never more than one.
  • An IGW can exist without being attached to a VPC (it is created first, then attached).
  • A VPC with no IGW is entirely private — no internet access in or out.

Six Steps to Make a Subnet Public

Making instances in a subnet reachable from the internet requires six configuration steps:

#StepWhat it does
1Create the IGWAllocates the gateway resource in your account
2Attach the IGW to the VPCLinks the gateway to the VPC (one-to-one)
3Create a custom route tableWill hold the public-facing routes
4Associate the route table with the public subnetOverrides the main route table for that subnet
5Add a default route: 0.0.0.0/0 → IGWSends all non-VPC traffic toward the internet
6Enable auto-assign public IPv4 on the subnetInstances launched here receive a public IP

How the IGW Translates Addresses (Static NAT)

The operating system of an EC2 instance never sees its public IP. The public IPv4 address exists only in a mapping table maintained by the IGW. Here is how a packet travels:

DirectionWhat happens at the IGW
Outbound (instance → internet) Instance sends packet with private IP as source. IGW replaces the source address with the instance's public IP before forwarding to the internet.
Inbound (internet → instance) Packet arrives at the public IP. IGW looks up the mapping and replaces the destination address with the private IP, then forwards into the VPC.
Exam tip
IPv6 is different: all IPv6 addresses are globally routable and publicly visible to the OS. The IGW does no address translation for IPv6 — packets pass through with their original addresses intact.

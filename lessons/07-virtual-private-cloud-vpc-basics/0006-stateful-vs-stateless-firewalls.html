Stateful vs Stateless Firewalls

Lesson 06 of 09 · ~8 min

Source: Adrian Cantrill SAA-C03 · AWS Security Groups & NACLs

Request–Response and Ephemeral Ports

Every network connection has two phases: a request (client → server) and a response (server → client). The request uses a well-known destination port — HTTP is TCP 80, HTTPS is TCP 443. The response returns to whichever ephemeral port the client's OS chose for that connection, typically a random port in the range 1024–65535.

Traffic directionDestination portWho chooses it
Client request → serverWell-known (e.g. 443)Protocol specification
Server response → clientEphemeral (e.g. 49,152)Client OS, randomly assigned per connection

Stateless Firewalls

A stateless firewall evaluates every packet in isolation. It has no memory of previous packets, so it cannot tell whether a response packet belongs to an already-approved request. This means you need two separate rules per connection:

  • An inbound rule allowing the request on the well-known port (e.g. TCP 443 from 0.0.0.0/0).
  • An outbound rule allowing the response on the full ephemeral range (TCP 1024–65535 to the client IP).

Because the response can come back on any ephemeral port, stateless firewalls typically need a wide outbound rule, which creates more exposure than a stateful firewall would require.

Exam tip
AWS NACLs are stateless. When writing NACL rules you must explicitly allow both the request direction and the response direction, including the ephemeral port range. Forgetting the outbound ephemeral rule is the most common NACL mistake on the exam.

Stateful Firewalls

A stateful firewall tracks connections. Once it approves a request, it automatically allows the corresponding response — even on an ephemeral port — without requiring a separate explicit rule. You allow the request, and the response is automatically permitted.

StatelessStateful
Memory of connectionsNone — each packet evaluated aloneYes — tracks request/response pairs
Rules needed per connectionTwo (request + response)One (request only)
Ephemeral port rulesMust be explicitly openedHandled automatically
AWS implementationNetwork ACLs (NACLs)Security Groups

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. A NACL allows inbound HTTPS (TCP 443) but blocks all outbound traffic. A user tries to load a website hosted on an EC2 instance. What happens?

2. Why must a stateless firewall typically allow the entire ephemeral port range (1024–65535) in the outbound direction?

3. A Security Group allows inbound TCP 443 from 0.0.0.0/0. No outbound rules explicitly allow the ephemeral response port. Will HTTPS responses reach clients?

Bastion Hosts

Lesson 05 of 09 · ~6 min

Source: Adrian Cantrill SAA-C03 · AWS VPC Security Best Practices

What is a Bastion Host?

A bastion host (also called a jump box) is a single EC2 instance placed in a public subnet whose sole purpose is to provide a hardened, auditable entry point into a VPC. Administrators SSH or RDP into the bastion from the internet, then connect from the bastion to instances in private subnets that have no direct internet exposure.

The pattern solves a common problem: you need to manage private resources (databases, application servers) but you do not want to expose them directly to the internet. The bastion host is the single controlled door.

Architecture and Security Rules

ComponentPlacementAccess rule
Bastion host Public subnet (has public IP) Inbound SSH/RDP allowed only from known admin IPs; all other inbound blocked
Private instances Private subnet (no public IP) Inbound SSH/RDP allowed only from the bastion's private IP or security group

Security hardening for a bastion host typically includes:

  • No unnecessary software installed — its only job is SSH/RDP forwarding.
  • Security group restricted to specific source IPs (your office CIDR, VPN egress IP).
  • Key-based authentication only — password login disabled.
  • All sessions logged (CloudTrail, OS-level logging) for audit purposes.
Exam tip
On the exam, a bastion host is the go-to answer when you need to provide administrative (SSH/RDP) access to private instances without making those instances publicly reachable. Do not confuse it with a NAT gateway — a NAT gateway lets private instances reach the internet outbound; a bastion lets admins reach private instances inbound.

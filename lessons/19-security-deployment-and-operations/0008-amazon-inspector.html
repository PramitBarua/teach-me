Amazon Inspector

Lesson 08 of 9 · ~9 min

Source: Adrian Cantrill SAA-C03 · What is Amazon Inspector? · CIS scans for Amazon EC2 instance operating systems

The source material describes a retired product generation
The original course narration describes what the industry now calls Inspector Classic: manually-run assessments over a fixed duration (15 minutes, 1, 8, 12 hours, or a day), a choice between agent-based and agentless network assessments, and rule packages you select yourself. Inspector Classic reached end of support on May 20, 2026 — its console and resources are no longer reachable at all as of this lesson. AWS relaunched Inspector in December 2021 around a completely different, continuous model, and has kept extending it since. This lesson teaches the current architecture, verified against AWS's current documentation, while still flagging the legacy concepts in case an exam question was written against the older framing.

Current Inspector: Continuous, Not Scheduled

Modern Amazon Inspector automatically discovers eligible resources and continually scans them — no duration to pick, no assessment template to run manually. It covers three resource types:

  • EC2 instances — operating system and installed software
  • Container images in Amazon ECR
  • Lambda functions

Newly launched instances, functions, and eligible container images pushed to ECR are detected and scanned automatically. Inspector also rescans automatically in response to events that could introduce a new vulnerability — installing a new package, applying a patch, or a new CVE being published that affects an already-scanned resource. You never have to trigger this yourself.

CVE Matching Is Still Core — and Still a Strong Keyword

Package vulnerability scanning against the Common Vulnerabilities and Exposures (CVE) database remains central to the product. Findings reference specific CVE IDs, and Inspector calculates a risk score (in CVSS format) that adjusts the underlying National Vulnerability Database score for your actual environment — for example, lowering the severity of a finding if the vulnerable instance has no open network path to the internet.

Exam heuristics that still hold
CVE mentioned → Inspector. Vulnerability scanning of container images in ECR or of Lambda functions → Inspector. These associations survive the product's architectural relaunch untouched — they're the safest keywords to anchor on regardless of which generation a question was written against.

EC2 Scanning: SSM Agent, With an Agentless Fallback

Current Inspector uses the AWS Systems Manager (SSM) Agent already running on an instance to collect its software inventory for agent-based scanning — there is no separate, Inspector-specific agent to install as there was in Classic. Where an instance doesn't have the SSM Agent deployed, Inspector can fall back to an agentless scan mode instead, so coverage doesn't strictly depend on agent installation.

Network Reachability: Now Built Into Continuous EC2 Scanning

The transcript's network reachability concept — assessing end-to-end exposure of an instance to public networks by examining route tables, security groups, NACLs, gateways, peering, and more — is still very much alive, but it's no longer a separate rules package you opt into with or without an agent, the way Classic worked. In current Inspector, network reachability analysis runs as part of the same continuous, automatic EC2 scanning, requiring no agent, and its results are correlated directly into the CVE risk score rather than reported as a standalone finding type.

CIS Benchmarks: Back, but Structured Differently

The transcript cuts off mid-definition of CIS (Center for Internet Security) Benchmarks — a set of host-hardening configuration best practices. In current Inspector, CIS Benchmark scanning returned in January 2024 as CIS scans: you target EC2 instances by tag, choose a benchmark level (Level 1 or Level 2), and run the scan on a schedule you define.

The one real trap here
Unlike CVE and network-reachability scanning, which are continuous and automatic, CIS scans are configured and scheduled by you — closer in spirit to how Classic's assessments worked. If a question asks whether Inspector's vulnerability scanning is "always on," the answer is yes for CVE and network exposure; CIS Benchmark scanning is the one area that still asks you to define a scan configuration.

Findings and Integration

Findings publish to EventBridge for near-real-time automation, and if Security Hub CSPM is active, Inspector also publishes findings there for a broader security-posture view alongside other services like Macie and GuardDuty. Multi-account environments can designate a delegated administrator through AWS Organizations, the same administrator/member pattern used by Macie and GuardDuty.

AWS Secrets Manager

Lesson 01 of 9 · ~7 min

Source: Adrian Cantrill SAA-C03 · Rotate AWS Secrets Manager secrets · Replicate secrets across Regions

Secrets Manager is a product that gets confused with something you've already met: the SSM Parameter Store, whose SecureString parameter type also stores encrypted values like passwords. The two products genuinely overlap — for plenty of scenarios either one gets the job done — so the exam skill here isn't learning new mechanics from scratch, it's learning the specific keywords that tell you which product a question actually wants.

The keyword heuristic
If a question mentions secrets, API keys, or passwords, default to Secrets Manager. If it mentions rotation — and especially rotation paired with RDS — that's an even stronger, more specific signal for Secrets Manager, because automatic rotation with direct in-sync product integration is the one thing Parameter Store cannot do at all. If the scenario is really just hierarchical configuration that isn't sensitive — say, settings for the CloudWatch agent — that points back to Parameter Store instead.

What Secrets Manager Actually Stores

At its core, Secrets Manager stores and protects secrets: it keeps them encrypted at rest with KMS, integrates with IAM so permissions control who can read which secret, and lets client applications retrieve secrets programmatically — console, CLI, API, and SDKs are all supported, though SDK-based retrieval from inside an application is the dominant real-world pattern.

Picture Catagram, a web app for sharing pictures of happy cats. Catagram's backend uses the Secrets Manager SDK to fetch its database credentials at runtime. The SDK authenticates using IAM — typically a role attached to the compute, though access keys are technically possible and less ideal — and that IAM identity is what's authorized to read the secret. Once retrieved, the application uses those credentials to connect to its database. Nothing described so far is beyond what Parameter Store's SecureString could also do.

Where Secrets Manager Pulls Ahead: Rotation

The differentiator is automatic rotation. Secrets Manager can periodically invoke a Lambda function that generates a new secret value and writes it back into Secrets Manager. That Lambda function runs under an execution role, which grants it the permissions it needs — both to update the secret in Secrets Manager, and, for certain supported products, to update the credential inside the product itself.

RDS is the flagship example of that deeper integration: when rotation fires, the Lambda function can change both the secret in Secrets Manager and the actual database password inside RDS, keeping the two permanently in sync. This direct, managed integration is only available for a limited set of supported products — it isn't something you get generically for any credential you store.

Encryption and Role Separation

Every secret is protected using KMS, which guarantees role separation: reading and decrypting a secret requires permissions to both Secrets Manager and the KMS key protecting it. Holding one without the other isn't enough — a deliberate design choice that prevents a single over-broad IAM policy from exposing secrets on its own.

Multi-Region secrets now exist too
Secrets Manager also supports replicating a secret to other AWS Regions, keeping encrypted secret data and metadata like tags in sync across them. If rotation is enabled on the primary secret, the new value propagates automatically to every replica — you don't manage rotation separately per Region. It's a natural extension of the same "keep it in sync automatically" theme that makes RDS rotation useful, this time solving for multi-Region applications that need low-latency, local access to the same secret.
Rare to have to choose
Most exam questions won't force a direct pick between Secrets Manager and Parameter Store — usually only one of them fits the scenario at all. When both seem plausible, fall back to the keywords: secrets, rotation, and named product integration (RDS above all) mean Secrets Manager; plain hierarchical configuration means Parameter Store.

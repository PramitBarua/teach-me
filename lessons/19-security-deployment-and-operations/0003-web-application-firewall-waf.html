Web Application Firewall (WAF)

Lesson 03 of 9 · ~9 min

Source: Adrian Cantrill SAA-C03 · Web ACL capacity units (WCUs) in AWS WAF · AWS WAF Pricing

WAF is AWS's concrete implementation of the layer 7 firewall concept from the last lesson — a firewall that understands application protocols like HTTP and HTTPS. WAF protects CloudFront (a global service) as well as Application Load Balancers, AppSync, and API Gateway (regional resources). That global-versus-regional split matters immediately: a Web ACL built for a regional resource must be created in the same region as that resource, whereas a CloudFront Web ACL is global.

The Web ACL: WAF's Core Unit

The Web Access Control List (Web ACL) is the actual unit of configuration in WAF — it's what you associate with a protected resource, and association is what turns WAF protection on for that resource. A Web ACL starts with a default action — allow or block — applied to any traffic that no rule matches. Which default you choose depends on your posture: block everything by default and explicitly allow known-good traffic, or allow everything by default and explicitly block known-bad traffic.

The resource-to-Web-ACL relationship is asymmetric: one resource has exactly one Web ACL, but one Web ACL can be associated with many resources. A CloudFront Web ACL can't be attached to a regional resource, or vice versa, and Web ACLs currently aren't usable with AWS Outposts. Associating a Web ACL with a resource can take a while — CloudFront in particular has to push the change out to edge locations — but adjusting a Web ACL that's already associated is much quicker.

WCU is not DynamoDB WCU
Web ACL Capacity Units (WCU) measure the compute complexity of the rules inside a Web ACL — nothing to do with DynamoDB's Write Capacity Units, which happen to share the same acronym. Every rule and rule group consumes some number of WCUs based on its complexity — a simple size check costs less than a regex match. Historically the exam framed this as a default cap of 1,500 WCU per Web ACL, raisable via a support ticket; current AWS documentation shows this has moved on — see the note below.
Fact check: the WCU ceiling has moved
Current AWS documentation confirms the maximum capacity for a Web ACL is now 5,000 WCU, available without a support ticket. The figure of 1,500 WCU still matters, though — it's now the pricing threshold: usage up to 1,500 WCU is included in the base Web ACL price, and usage beyond that incurs additional tiered charges. So "1,500" survives in the current docs, just with a different meaning than a hard ceiling.

Rule Groups vs. Rules

Rule groups are containers of rules, added into Web ACLs to allow grouped administration — they carry no default action of their own; that still comes from the Web ACL. Rule groups can be AWS-managed, marketplace-provided, customer-owned (yours), or service-owned (created on your behalf by services like Shield or Firewall Manager). AWS-managed rule groups are mostly free, with notable exceptions: Bot Control and Fraud Control carry their own extra fees. Marketplace rule groups generally carry a subscription cost too. A rule group's WCU capacity is fixed at creation and reused by every Web ACL that references it.

A rule itself has three parts: type, statement, and action.

PartMeaning
TypeRegular (matches if something occurs) or rate-based (matches if something occurs at a certain rate — e.g. 5,000 requests in 5 minutes)
StatementThe match criteria — country, IP, label, headers, cookies, query parameters, URI path, query string, HTTP method, or request body
ActionWhat WAF does on a match
The body-inspection limit
When a statement matches against the request body, WAF only ever inspects the first 8,192 bytes of it — a specific, quotable exam fact.

Match types on a statement include exact match, starts-with, ends-with, contains, and regular expressions. Multiple statements can be combined with AND/OR/NOT logic for more complex conditions.

Rate-based rules have no "allow" — and it's logical
Regular rules can act with allow, block, count, or CAPTCHA. Rate-based rules only offer block, count, or CAPTCHA — there is no allow. This makes sense once you think about intent: a rate-based rule exists specifically to react when traffic crosses a threshold, and "allow" is never a meaningful reaction to that condition.

Optional custom responses can accompany block (a custom body or header) or allow/count/CAPTCHA (custom header only) — headers are prefixed x-amzn-waf- so your own application can react to them. Optional labels let one rule mark traffic so a later rule in the same Web ACL can act on that label. Labels are internal to WAF and never persist outside a single Web ACL.

Labels only survive if processing continues
Labels only propagate when a rule's action lets processing continue — that's count or CAPTCHA. If a rule's action stops processing — allow or block — no further rules run against that traffic, so any label added by that rule is moot for later rules in the chain.

Logging and Event-Driven Response

WAF can log to S3 (roughly a five-minute delivery delay), CloudWatch Logs, or Kinesis Data Firehose. Firehose is the path to near-real-time reaction: it can feed S3 Events, Lambda, Athena, and EventBridge, letting you build an automated feedback loop that extracts actionable intelligence from traffic and updates Web ACLs without a human in the loop — for example, pulling in a public list of known-bad IPs on an EventBridge schedule.

Pricing

Verified against the current AWS WAF pricing page — the transcript's headline figures still match: $5/month per Web ACL, $1/month per rule or rule group, and $0.60 per million requests processed. On top of that, Bot Control, CAPTCHA/Challenge, and Fraud Control (account takeover and account creation protection) each carry their own separate monthly and per-request/per-attempt fees, and any marketplace rule groups add their own subscription cost. As the course itself notes, these figures are subject to change — always confirm against the live pricing page or the AWS Pricing Calculator before relying on a specific number.

Egress-Only Internet Gateway

Lesson 02 of 05 · ~6 min

Source: Adrian Cantrill SAA-C03 · Enable Outbound IPv6 Traffic Using an Egress-Only Internet Gateway

This gateway exists to solve one specific problem: giving IPv6 instances the same "outbound-only" behavior that a NAT gateway gives IPv4 instances — because NAT itself doesn't work for IPv6.

Why NAT Doesn't Help Here

With IPv4, a private instance has no publicly routable address at all — a NAT gateway lets it initiate outbound connections and receive responses, while remaining completely unreachable from anything trying to connect in.

Every IPv6 address in AWS is publicly routable
There's no such thing as a "private" IPv6 address the way there is for IPv4. That means a plain internet gateway lets IPv6 traffic flow both ways — out and in — for every IPv6-enabled instance, unless something else restricts it. NAT can't fix this because NAT is fundamentally an IPv4-only workaround for address scarcity, a problem IPv6 doesn't have.

The Fix

An egress-only internet gateway allows IPv6 traffic to be initiated outbound and its responses to return, while blocking any connection initiated from the internet — precisely mirroring what a NAT gateway does for IPv4, but built for IPv6 addressing.

Exam tip: architecture is identical to a normal IGW
An egress-only internet gateway is highly available and auto-scaling by design, exactly like a regular internet gateway — the architecture doesn't differ. What differs is purely how you use it: create it, attach it to the VPC, then add a default IPv6 route (::/0) in the relevant route table(s) pointing at it. It's a stateful device, so return traffic for an outbound-initiated connection is automatically permitted.

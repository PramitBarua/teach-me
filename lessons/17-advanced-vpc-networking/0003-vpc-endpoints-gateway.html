VPC Endpoints: Gateway Endpoints

Lesson 03 of 05 · ~8 min

Source: Adrian Cantrill SAA-C03 · Gateway Endpoints

S3 and DynamoDB are public AWS services — reaching them normally means a public IP, a NAT gateway, or some other path through an internet gateway. A gateway endpoint removes that requirement entirely: private-only resources in a private-only VPC can reach these two services without any internet-facing infrastructure at all.

Only two services, ever
Gateway endpoints support exactly two services: S3 and DynamoDB. Nothing else uses this mechanism — everything else that needs private access uses an interface endpoint instead (next lesson).

How It Actually Works: Prefix Lists, Not Interfaces

A gateway endpoint doesn't place anything inside a subnet. Instead, associating it with subnets adds a prefix list — a logical, AWS-maintained object representing the target service's IP ranges — to those subnets' route tables, with the gateway endpoint as the target. Traffic destined for that prefix list simply routes out via the endpoint instead of an internet/NAT gateway.

Exam tip: gateway endpoints are highly available by default
A gateway endpoint is a VPC-level logical gateway object — it does not live in any specific subnet or AZ, and is highly available across every AZ the VPC uses automatically. This is the single biggest architectural difference from interface endpoints, which are genuinely AZ-scoped (next lesson).

Access Control: Endpoint Policies

An endpoint policy attached to the gateway endpoint restricts what it can be used to reach — e.g. only specific S3 buckets rather than the entire service. Combine this with an S3 bucket policy that only accepts requests arriving via that specific endpoint, and you get a fully private bucket: nothing outside the VPC (and, within the VPC, nothing outside the endpoint policy's allowlist) can touch it.

Scope Limits

  • Same-Region only — a gateway endpoint in us-east-1 cannot be used to reach an S3 bucket in ap-southeast-2.
  • Same-VPC only — a gateway endpoint is only usable from the VPC it's associated with; it isn't reachable from peered VPCs or anywhere else outside that one VPC.
Exam tip: the fully-private, high-security VPC scenario
Any question describing a heavily regulated environment needing a VPC with no internet gateway and no NAT gateway at all, that still needs to reach S3 or DynamoDB, is describing a gateway endpoint. This architecture is close to impossible to achieve any other way.

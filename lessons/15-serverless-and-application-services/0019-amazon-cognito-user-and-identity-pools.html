Amazon Cognito: User Pools and Identity Pools

Lesson 19 of 22 · ~12 min

Source: Adrian Cantrill SAA-C03 · What Is Amazon Cognito? · Amazon Cognito User Pools · Amazon Cognito Identity Pools

Cognito is one of the most heavily tested non-graphical topics in the whole exam — not because it's conceptually hard, but because its two components are named in a way that actively invites confusion. Get the naming straight and the rest falls into place.

Cognito as a whole provides authentication (verifying who someone is), authorization (managing access to services), and user management (a serverless database of users) for web and mobile applications. It does this through two genuinely separate products that happen to share a brand name: user pools and identity pools.

User Pools: Sign-In, and Nothing Else

A user pool is a directory of users. It handles sign-up, sign-in, a built-in customizable hosted UI, multi-factor authentication, compromised-credential checks, account takeover protection, and phone/email verification. It can also run Lambda triggers for custom workflows or user migration. Sign-in can come from users stored directly in the pool, or from social identities (Facebook, Google, Amazon, Apple) and SAML identity providers — all unified into one login experience.

The output of a successful sign-in is a JSON Web Token (JWT). This token proves the identity signed in successfully, and can be used to authenticate against self-managed applications and databases, or against API Gateway, which can accept JWTs directly.

The single most important fact about Cognito
A user pool JWT cannot be used to access most AWS services. User pools are a login and identity-management system — full stop. Getting actual AWS credentials is a completely different job, done by identity pools.

Identity Pools: Trading Identity for AWS Credentials

An identity pool's only job is to exchange an identity for a set of temporary AWS credentials. The identity being exchanged can be:

  • an unauthenticated (guest) identity — no sign-in at all, useful for something like storing anonymous high scores in DynamoDB;
  • an authenticated external identity — a Google, Facebook, Amazon, or SAML 2.0 token; or
  • a user pool token — yes, a user pool is just one more type of identity an identity pool can accept.

Under the hood, an identity pool has at least two configured IAM roles — one for authenticated identities, one for unauthenticated ones. When a valid identity is presented, Cognito assumes the matching role on the application's behalf, generating temporary credentials that are handed back to the app. The app's actual permissions come entirely from that role. Nothing is ever hard-coded or stored permanently.

Swapping any external identity-provider token for AWS credentials this way is called Web Identity Federation — a term you'll meet in both the exam and in the wild.

Using Both Together

Supporting five external providers directly in an identity pool means configuring five separate token types. Instead, route everyone through a user pool first: internal users and every social login all collapse into a single user pool token. The identity pool then only needs to trust one identity source — the user pool — and swaps that single token type for AWS credentials. Same outcome, far less configuration.

Why this scales past IAM users
IAM caps you at 5,000 users per account — fine for employees, unworkable for a consumer-facing app. Identity pools issue temporary credentials to a near-unlimited number of end users, which is why they're the correct answer for web-scale, customer-facing AWS access.

Retrieval Practice

Answer from memory. Explanations appear after each answer.

1. A mobile app lets users sign in with corporate SAML credentials, and afterward the app needs temporary AWS credentials to write directly to a DynamoDB table. Which Cognito component produces those credentials?

2. An architect needs users to sign up, verify their email, and sign back in through a customizable hosted UI — but the application never touches AWS services directly. Which Cognito component alone satisfies this?

3. An application supports sign-in via Google, Facebook, and Amazon accounts, routed through a single Cognito user pool, then exchanges the resulting token for AWS credentials via an identity pool. What is this general process of swapping an external identity for AWS credentials called?

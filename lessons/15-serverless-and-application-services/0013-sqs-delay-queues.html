SQS Delay Queues

Lesson 13 of 22 · ~4 min

Source: Adrian Cantrill SAA-C03 · Amazon SQS Delay Queues · Amazon SQS Message Timers

A delay queue postpones delivery of new messages to consumers. It's easy to confuse with visibility timeout — both hide a message for a period — but they solve opposite problems.

Visibility timeoutDelay queue
Message starts asVisible on the queueInvisible on the queue
Hidden whenAfter a consumer receives itImmediately, when first sent
PurposeAutomatic reprocessing on failureDeliberate delay before any consumer sees it
Range0 sec – 12 hours (default 30 sec)0 sec – 15 min (default 0)

Set DelaySeconds on the queue itself to make every incoming message start invisible for that period — this is what makes it a delay queue rather than a normal one. You can instead set a delay per message using message timers (same 0-second to 15-minute range), useful when only some messages need the delay.

FIFO restriction
Per-message timers are not supported on FIFO queues — only the queue-level DelaySeconds setting works there. If a scenario needs a per-message delay on strictly ordered messages, a delay queue can't deliver that combination.
Exam tip: don't confuse the two hide mechanisms
Visibility timeout exists for error correction — recovering messages after a failed or crashed consumer. A delay queue exists to deliberately postpone processing from the start, e.g. giving upstream steps time to finish before a message becomes actionable. Same underlying mechanic (an invisible message), different trigger and different intent.

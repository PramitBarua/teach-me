SQS Standard vs. FIFO Queues

Lesson 12 of 22 · ~5 min

Source: Adrian Cantrill SAA-C03 · Amazon SQS FIFO Queues · High Throughput for FIFO Queues

Picture a FIFO queue as a single-lane road with no overtaking, and a standard queue as a multi-lane highway. That one image explains almost every trade-off between the two.

Standard queueFIFO queue
OrderingBest effort onlyStrictly preserved (first in, first out)
DeliveryAt-least-once (duplicates possible)Exactly-once processing
ThroughputNear-infinite, scales linearly300 msg/sec, or 3,000 with batching
NamingNo restrictionQueue name must end in .fifo

Because a FIFO queue is a single lane, its throughput is capped: 300 transactions per second against the API without batching, or 3,000 when each transaction batches up to 10 messages. A standard queue has no such lane restriction — it scales out like adding lanes to the highway.

Exam tip: the .fifo suffix
A FIFO queue's name must end with .fifo — this oddly specific requirement has shown up repeatedly in real exams. If a scenario mentions a queue name without that suffix, it cannot be a FIFO queue.
Exam tip: at-least-once means design for duplicates
Standard queues only guarantee at-least-once delivery — the same message can arrive twice. Any application consuming from a standard queue must be designed to handle duplicate processing (idempotency), whereas FIFO's exactly-once processing removes that burden at the cost of throughput.

Picking Between Them

FIFO fits workflows where order is non-negotiable: sequential command processing, ordered price adjustments in a sales workflow, or anything where processing message 2 before message 1 would produce a wrong result.

Standard fits everything else where raw throughput matters more than strict order — decoupling application components, worker-pool architectures, or simply batching work for later processing.

Stale vs. current: FIFO high throughput mode
The course notes FIFO high throughput mode as a preview feature at time of recording. It has since reached general availability as "high throughput for FIFO queues," raising achievable throughput well beyond the 3,000 msg/sec batched baseline by partitioning message groups across more backend infrastructure. For the exam, know the baseline numbers (300 / 3,000) as the default FIFO ceiling, but be aware the higher-throughput mode now exists in production.

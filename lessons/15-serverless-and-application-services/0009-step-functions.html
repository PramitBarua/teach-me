AWS Step Functions

Lesson 09 of 22 · ~9 min

Source: Adrian Cantrill SAA-C03 · What Is AWS Step Functions? · Choosing a Workflow Type

Step Functions exists to solve a real Lambda limitation: functions max out at a 15-minute execution duration, and each invocation runs in a stateless, disposable environment. Chaining Lambda functions together to build a long-running, stateful process technically works, but it gets messy fast — there's no clean way to hold state, retry a specific step, or branch on a decision across invocations.

State Machines

Step Functions lets you define a state machine — a workflow with a start, an end, and states in between that do things, decide things, or wait on things, passing data along the way. State machines are defined using Amazon States Language (ASL), a JSON-based format, and each state machine runs under an IAM role it assumes to interact with other AWS services.

The State Types

StatePurpose
Succeed / FailTerminates the execution as a success or failure
WaitPauses for a duration or until a specific date/time
ChoiceBranches the workflow down different paths based on input
ParallelRuns multiple branches at the same time
MapRepeats a set of steps once per item in an input list
TaskPerforms one unit of actual work, integrating with services like Lambda, DynamoDB, SNS, SQS, ECS, Batch, Glue, or SageMaker

Flow-control states (Succeed, Fail, Wait, Choice, Parallel, Map) shape the path through the workflow; only Task states actually do something, by handing off to another AWS service.

Standard vs. Express

StandardExpress
Max durationUp to 1 yearUp to 5 minutes
Best forLong-running, auditable workflows (order processing, approvals)High-volume event processing (IoT streams, mobile backends)
Execution modelExactly-onceAt-least-once
DefaultYesNo — must be selected explicitly
Exam tip: Standard vs. Express, at a glance
If the scenario is long-running with steps that could take hours, days, or need human intervention, pick Standard. If it's high-volume, high-throughput, short-lived event processing — streaming, IoT ingestion — pick Express. Standard's exactly-once guarantee also makes it the safer default whenever a task must never run twice; Express trades that guarantee for scale and speed.

Starting an Execution

State machines can be started from API Gateway, EventBridge rules, IoT rules, directly from a Lambda function, manually, or via the SDK/CLI — almost always as backend orchestration triggered by something else in the application.

Worked Example: PetCuddletron

Bob's cat Whiskers needs cuddle reminders. A serverless front end (S3 static site → API Gateway → Lambda) lets Bob start an execution of a state machine with a delay and a notification preference. Inside the state machine:

  1. A Wait state ("timer") pauses for the requested delay.
  2. A Choice state branches on Bob's chosen notification method.
  3. One of three Task states runs: invoke an email-reminder Lambda, an SMS-reminder Lambda, or both.

Because the wait could exceed 15 minutes, plain Lambda chaining isn't an option here — this is exactly the scenario Step Functions is designed for.

# Notes

## Scenario-quiz state model (2026-08-09)
`assets/scenario-quiz.js` is the single shared engine for every `scenarios.html` file — no per-question markup or per-file JS is needed for any of this, it's picked up automatically:
- **Per-question notes**: each answer panel gets an auto-injected `.scenario-comment` textarea, persisted to `localStorage` (key `scenarioComments:<pathname>`), optional, restored on reload, shown once the answer panel is revealed.
- **Answered state**: `scenarioSelections` (a `{blockId: letter}` map) is the *only* persisted state for picks — there is no separate "revealed" storage key. A question counts as answered only once the user has both picked an option and revealed the answer (either order — picking after already-revealed commits immediately). Picks made but never revealed live only in an in-memory `pendingPicks` map and vanish on reload, by design.
- **Coloring rule**, derived live from `scenarioSelections` + the answer panel's current open/closed state, not from history: unanswered → no highlight; answered + panel closed ("Reveal answer" showing) → blue on the picked option; answered + panel open ("Hide answer" showing) → green on the correct option, red on the pick if it was wrong.
- **Reset My Answer** button (auto-injected next to the scenario count) clears only `scenarioSelections` (and in-memory pending picks) after a `confirm()`; marked-for-review flags and notes are untouched.
- Once a question is answered it's locked (further option clicks no-op) until Reset.

## Learning structure
- Source notes are in `../cantrill/` directory (one md file per topic)
- Each md file gets its own lesson directory under `lessons/`
- Lessons are numbered per directory, not globally

## User preferences
- Wants isolated topic directories so each module can be studied independently
- First module: iam-accounts-and-aws-organizations
- Scenario-quiz distractor design (2026-08-08): every scenario-based question's 4 options must include (1) one answer that's technically possible but violates a stated requirement in the scenario, (2) one answer that's plausible and closely related to the correct answer but wrong (a neighboring service/mode/feature easy to confuse with it), and (3) the correct best-choice answer. Avoid options so obviously wrong they can be eliminated without real recall — the point is to validate genuine chapter understanding, not let the user guess via elimination. Apply this to every module's scenarios.html going forward, not just the ones it was first requested for.
- Scenario-quiz no-hint titles (2026-08-08): the `.scenario-tag` line above each question (e.g. "Scenario 1 · Cross-account access") must NOT name the question's topic — the topic name is itself a hint that shortcuts recall. Tag text should just be "Scenario N". The topic label moves into the answer panel as `<p class="answer-topic">Topic: ...</p>` (styled in assets/style.css), placed first inside `.answer-panel` before `.answer-line`, so it stays hidden until the user reveals the answer. Applies to all current and future scenarios.html files, workspace-wide.
- Scenario-quiz coverage depth (2026-08-08): each module's scenarios.html must cover at least 5 questions per topic but add more when possible, where "topic" = roughly one lesson in that module's directory (e.g. module 05 has 11 lesson topics → at least 55 scenario questions; module 06 has 17 → at least 85). The questions on a given topic must each probe a genuinely different angle/scenario of that topic, not rephrasings of the same trap — e.g. for "SCPs" one question on deny-vs-allow intersection, one on OU inheritance, one on the management-account exemption, one on SCP-vs-permissions-boundary confusion, one on a specific action-level edge case. Every question still follows the distractor-design rule ([[feedback-scenario-distractor-design]]) and the no-hint-title rule above. Applies to all current and future scenarios.html files, workspace-wide.

## Flashcard feature

- Each module directory gets its own `flash-card.html` (sibling to `index.html` and the numbered lessons), for spaced-repetition review of that module's material only. Cards are hand-curated from the module's existing lesson HTML — never scraped live at runtime — pulling the highest-yield facts (definitions, exam-tip callouts, comparison-table rows, numeric limits) and writing them as short Q/A (question-based) or topic/description (topic-based) pairs, mixed together in one deck. Default density is **moderate, ~2 cards per lesson**, treated as a tunable starting point rather than a fixed rule — go lighter or heavier per lesson depending on how much genuinely high-yield material it has.
- Scoring: click to flip a card, then **Learned** (+1) or **Review** (−1), clamped to **−5..+5**, starting at **0** (never studied). Persisted client-side in `localStorage`, keyed `flashcard-score:<moduleKey>:<cardId>` — no backend, so scores live only in the browser profile that opens the file (an accepted limitation of this static-HTML workspace, not a gap to fix).
- Deck order is sequential, matching lesson order, with Prev/Next navigation — no shuffle or weakest-first sorting in the first pass, kept deliberately simple per the user's request. Could be added later as a toggle without markup changes.
- Built as shared components, same pattern as the existing quiz widget: `assets/flashcard.js` (dependency-free `initFlashcards(cards, {moduleKey})`, mirrors `quiz.js`'s IIFE style) + new `.flashcard`/`.flashcard-inner`/`.flashcard-face`/`.deck-controls`/`.score-badge` classes appended to the *existing* `assets/style.css` (reuses the shared CSS custom properties — no second stylesheet).
- The quiz-widget rule "all multiple-choice options must be the same length" does not apply to flashcard answers — flashcards are single free-form Q/A pairs, not multiple choice; answers just need to stay short (one clause to one sentence) for recall.
- Pilot module: `05-iam-accounts-and-aws-organizations` (22 cards, built and linked from its `index.html`). Rollout to the remaining 22 modules is intentionally deferred until the user has reviewed the pilot deck in the browser and confirmed the format/density before it's repeated everywhere.

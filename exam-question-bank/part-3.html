      Question 51

      A company wants to migrate its existing on-premises monolithic application to AWS. The company wants to keep as much of the front-end code and the backend code as possible. However, the company wants to break the application into smaller applications. A different team will manage each application. The company needs a highly scalable solution that minimizes operational overhead. Which solution will meet these requirements?

      • A. Host the application on AWS Lambda. Integrate the application with Amazon API Gateway.
      • B. Host the application with AWS Amplify. Connect the application to an Amazon API Gateway API that is integrated with AWS Lambda.
      • C. Host the application on Amazon EC2 instances. Set up an Application Load Balancer with EC2 instances in an Auto Scaling group as targets.
      • D. Host the application on Amazon Elastic Container Service (Amazon ECS). Set up an Application Load Balancer with Amazon ECS as the target.

      Domain: Design High-Performing Architectures

      Correct answer: D

      • A. Wrong — rewriting each piece as individual Lambda functions is a bigger re-architecture than "keep as much front-end and backend code as possible" calls for.
      • B. Wrong — Amplify is built for modern front-end apps with its own build/hosting pipeline; migrating a monolithic app's front end to Amplify and backend to Lambda still requires substantial rework rather than a lift of existing code.
      • C. Wrong — EC2 with an ALB works, but the company still has to manage and patch the underlying instances/OS for every decomposed application and team — more operational overhead than a managed container platform.
      • D. Correct — containerizing each broken-out application lets teams reuse their existing code with minimal changes, ECS is a managed, highly scalable orchestrator, and an ALB in front load-balances requests to it — least operational overhead while preserving existing code.

      Question 52

      A company is preparing to deploy a new serverless workload. A solutions architect must use the principle of least privilege to configure permissions that will be used to run an AWS Lambda function. An Amazon EventBridge (Amazon CloudWatch Events) rule will invoke the function. Which solution meets these requirements?

      • A. Add an execution role to the function with lambda:InvokeFunction as the action and * as the principal.
      • B. Add an execution role to the function with lambda:InvokeFunction as the action and Service: lambda.amazonaws.com as the principal.
      • C. Add a resource-based policy to the function with lambda:* as the action and Service: events.amazonaws.com as the principal.
      • D. Add a resource-based policy to the function with lambda:InvokeFunction as the action and Service: events.amazonaws.com as the principal.

      Domain: Design Secure Architectures

      Correct answer: D

      • A. Wrong — * as the principal lets literally anyone invoke the function, badly violating least privilege, and an execution role is also the wrong policy type for granting invoke permission.
      • B. Wrong — an execution role governs what the function itself is allowed to access (e.g., other AWS services it calls), not who is permitted to invoke it; it isn't the mechanism for granting EventBridge invoke access.
      • C. Wrong — lambda:* grants far more permissions than the single invoke action required, violating least privilege even though the principal is correctly scoped.
      • D. Correct — a resource-based policy on the function with exactly lambda:InvokeFunction as the action and events.amazonaws.com as the principal grants EventBridge precisely the permission it needs to invoke this function, and nothing more.

      Question 53

      A company uses AWS Systems Manager for routine management and patching of Amazon EC2 instances. The EC2 instances are in an IP address type target group behind an Application Load Balancer (ALB). New security protocols require the company to remove EC2 instances from service during a patch. When the company attempts to follow the security protocol during the next patch, the company receives errors during the patching window. Which combination of solutions will resolve the errors? (Choose two.)

      • A. Change the target type of the target group from IP address type to instance type.
      • B. Continue to use the existing Systems Manager document without changes because it is already optimized to handle instances that are in an IP address type target group behind an ALB.
      • C. Implement the AWSEC2-PatchLoadBalancerInstance Systems Manager Automation document to manage the patching process.
      • D. Use Systems Manager Maintenance Windows to automatically remove the instances from service to patch the instances.
      • E. Configure Systems Manager State Manager to remove the instances from service and manage the patching schedule. Use ALB health checks to re-route traffic.

      Domain: Design Resilient Architectures

      Correct answer: C, D

      • A. Wrong — the IP-based target type isn't what's causing the errors; switching target types doesn't add the required deregister-drain-patch-reattach behavior.
      • B. Wrong — the existing document is exactly what's producing errors under the new requirement; leaving it unchanged resolves nothing.
      • C. Correct — AWSEC2-PatchLoadBalancerInstance is an AWS-provided Automation runbook purpose-built for this scenario: it verifies instance health, deregisters the instance from its load balancer/target group, waits for connection draining, patches it, then re-registers it.
      • D. Correct — Systems Manager Maintenance Windows orchestrate scheduled tasks (like the runbook above) that remove instances from service before patching and add them back afterward, integrating the workflow into a managed schedule.
      • E. Wrong — State Manager continuously enforces configuration state on a schedule; it isn't designed to orchestrate a one-time deregister-patch-reattach workflow tied to ALB health checks the way Maintenance Windows + the patching runbook are.

      Question 54

      A company has implemented a self-managed DNS solution on three Amazon EC2 instances behind a Network Load Balancer (NLB) in the us-west-2 Region. Most of the company's users are located in the United States and Europe. The company wants to improve the performance and availability of the solution. The company launches and configures three EC2 instances in the eu-west-1 Region and adds the EC2 instances as targets for a new NLB. Which solution can the company use to route traffic to all the EC2 instances?

      • A. Create an Amazon Route 53 geolocation routing policy to route requests to one of the two NLBs. Create an Amazon CloudFront distribution. Use the Route 53 record as the distribution's origin.
      • B. Create a standard accelerator in AWS Global Accelerator. Create endpoint groups in us-west-2 and eu-west-1. Add the two NLBs as endpoints for the endpoint groups.
      • C. Attach Elastic IP addresses to the six EC2 instances. Create an Amazon Route 53 geolocation routing policy to route requests to one of the six EC2 instances. Create an Amazon CloudFront distribution. Use the Route 53 record as the distribution's origin.
      • D. Replace the two NLBs with two Application Load Balancers (ALBs). Create an Amazon Route 53 latency routing policy to route requests to one of the two ALBs. Create an Amazon CloudFront distribution. Use the Route 53 record as the distribution's origin.

      Domain: Design High-Performing Architectures

      Correct answer: B

      • A. Wrong — geolocation routing only sends each user to one Region's NLB rather than routing across both, and CloudFront is an HTTP(S) service that can't accelerate a raw self-managed DNS server's protocol traffic.
      • B. Correct — Global Accelerator supports non-HTTP TCP/UDP protocols (like DNS on port 53), and a standard accelerator with endpoint groups in both us-west-2 and eu-west-1 (each containing that Region's NLB) gives static anycast entry-point IPs that route each user to the nearest healthy Region — exactly matching this multi-Region, non-HTTP workload.
      • C. Wrong — individual Elastic IPs plus a geolocation record still routes to only one instance/Region at a time, and CloudFront (HTTP-only) doesn't fit DNS protocol traffic.
      • D. Wrong — Application Load Balancers operate at Layer 7 (HTTP/HTTPS) only; they cannot load-balance a self-managed DNS server's TCP/UDP traffic, and CloudFront again doesn't apply to non-HTTP DNS traffic.

      Question 55

      A company runs a production application on a fleet of Amazon EC2 instances. The application reads the data from an Amazon SQS queue and processes the messages in parallel. The message volume is unpredictable and often has intermittent traffic. This application should continually process messages without any downtime. Which solution meets these requirements MOST cost-effectively?

      • A. Use Spot Instances exclusively to handle the maximum capacity required.
      • B. Use Reserved Instances exclusively to handle the maximum capacity required.
      • C. Use Reserved Instances for the baseline capacity and use Spot Instances to handle additional capacity.
      • D. Use Reserved Instances for the baseline capacity and use On-Demand Instances to handle additional capacity.

      Domain: Design Cost-Optimized Architectures

      Correct answer: C

      • A. Wrong — using Spot exclusively for the maximum required capacity risks all capacity being reclaimed at once, conflicting with "continually process messages without any downtime."
      • B. Wrong — sizing Reserved Instances to the maximum required capacity means paying the RI rate for capacity that sits idle whenever traffic is below peak, given the described unpredictable, intermittent volume.
      • C. Correct — Reserved Instances guarantee the always-on baseline needed for continuous processing, while Spot Instances cost-effectively absorb unpredictable extra load, since parallel SQS-based processing tolerates any one Spot worker being interrupted without stopping overall processing.
      • D. Wrong — On-Demand for the variable additional capacity costs more than Spot for a workload that can tolerate interruption, leaving savings on the table.

      Question 56

      A company is migrating an application from on-premises servers to Amazon EC2 instances. As part of the migration design requirements, a solutions architect must implement infrastructure metric alarms. The company does not need to take action if CPU utilization increases to more than 50% for a short burst of time. However, if the CPU utilization increases to more than 50% and read IOPS on the disk are high at the same time, the company needs to act as soon as possible. The solutions architect also must reduce false alarms. What should the solutions architect do to meet these requirements?

      • A. Create Amazon CloudWatch composite alarms where possible.
      • B. Create Amazon CloudWatch dashboards to visualize the metrics and react to issues quickly.
      • C. Create Amazon CloudWatch Synthetics canaries to monitor the application and raise an alarm.
      • D. Create single Amazon CloudWatch metric alarms with multiple metric thresholds where possible.

      Domain: Design Resilient Architectures

      Correct answer: A

      • A. Correct — a composite alarm combines multiple underlying metric alarms (CPU > 50% AND high read IOPS) with AND/OR logic, so it only triggers when both specific conditions co-occur — reducing false alarms from CPU spikes alone while still acting immediately when both happen together.
      • B. Wrong — dashboards are a visualization tool for humans to look at; they don't automatically evaluate conditions or trigger action on their own.
      • C. Wrong — Synthetics canaries run scripted checks against endpoints (like a website); they aren't designed to correlate two different EC2 instance-level metrics like CPU and disk IOPS.
      • D. Wrong — a single metric alarm can only evaluate one metric at a time; it can't natively combine "CPU > 50%" AND "read IOPS is high" into one conditional alarm the way a composite alarm can.

      Question 57

      A solutions architect must design a highly available infrastructure for a website. The website is powered by Windows web servers that run on Amazon EC2 instances. The solutions architect must implement a solution that can mitigate a large-scale DDoS attack that originates from thousands of IP addresses. Downtime is not acceptable for the website. Which actions should the solutions architect take to protect the website from such an attack? (Choose two.)

      • A. Use AWS Shield Advanced to stop the DDoS attack.
      • B. Configure Amazon GuardDuty to automatically block the attackers.
      • C. Configure the website to use Amazon CloudFront for both static and dynamic content.
      • D. Use an AWS Lambda function to automatically add attacker IP addresses to VPC network ACLs.
      • E. Use EC2 Spot Instances in an Auto Scaling group with a target tracking scaling policy that is set to 80% CPU utilization.

      Domain: Design Secure Architectures

      Correct answer: A, C

      • A. Correct — AWS Shield Advanced provides enhanced DDoS protection purpose-built to mitigate large-scale, distributed attacks like this one, with near real-time detection and response.
      • B. Wrong — GuardDuty is a threat-detection service that generates findings; it doesn't automatically block attacker traffic on its own.
      • C. Correct — routing the site through CloudFront (even for dynamic content) absorbs and disperses volumetric traffic across AWS's globally distributed edge network, reducing the load that ever reaches the origin EC2 instances and improving resilience against a botnet-scale attack.
      • D. Wrong — manually adding thousands of individual attacker IPs to network ACLs doesn't scale (NACLs have practical rule-count limits) and can't keep pace with an attack from "thousands of IP addresses" in real time.
      • E. Wrong — Spot Instances can be reclaimed by AWS at any time; introducing Spot into a fleet that must stay available during an active attack adds an availability risk instead of mitigating the DDoS attack.

      Question 58

      A media company is evaluating the possibility of moving its systems to the AWS Cloud. The company needs at least 10 TB of storage with the maximum possible I/O performance for video processing, 300 TB of very durable storage for storing media content, and 900 TB of storage to meet requirements for archival media that is not in use anymore. Which set of services should a solutions architect recommend to meet these requirements?

      • A. Amazon EBS for maximum performance, Amazon S3 for durable data storage, and Amazon S3 Glacier for archival storage
      • B. Amazon EBS for maximum performance, Amazon EFS for durable data storage, and Amazon S3 Glacier for archival storage
      • C. Amazon EC2 instance store for maximum performance, Amazon EFS for durable data storage, and Amazon S3 for archival storage
      • D. Amazon EC2 instance store for maximum performance, Amazon S3 for durable data storage, and Amazon S3 Glacier for archival storage

      Domain: Design Cost-Optimized Architectures

      Correct answer: D

      • A. Wrong — even at its highest-performance tier, EBS doesn't match the raw I/O throughput of directly-attached NVMe instance store for a "maximum possible" performance requirement.
      • B. Wrong — EFS is a shared network file system; it doesn't deliver the maximum possible I/O performance instance store provides, so it's misapplied to the top performance tier here.
      • C. Wrong — EFS isn't the best fit for "very durable storage for storing media content" versus S3's eleven-nines durability, and plain S3 (not S3 Glacier) is the wrong tier for 900 TB of archival media that's no longer in active use.
      • D. Correct — EC2 instance store gives the maximum possible I/O performance (directly attached NVMe) for the video-processing tier, S3 gives very high durability for the 300 TB of active media content, and S3 Glacier gives the lowest-cost durable storage appropriate for 900 TB of archival media.

      Question 59

      A company has two applications: a sender application that sends messages with payloads to be processed and a processing application intended to receive the messages with payloads. The company wants to implement an AWS service to handle messages between the two applications. The sender application can send about 1,000 messages each hour. The messages may take up to 2 days to be processed: If the messages fail to process, they must be retained so that they do not impact the processing of any remaining messages. Which solution meets these requirements and is the MOST operationally efficient?

      • A. Set up an Amazon EC2 instance running a Redis database. Configure both applications to use the instance. Store, process, and delete the messages, respectively.
      • B. Use an Amazon Kinesis data stream to receive the messages from the sender application. Integrate the processing application with the Kinesis Client Library (KCL).
      • C. Integrate the sender and processor applications with an Amazon Simple Queue Service (Amazon SQS) queue. Configure a dead-letter queue to collect the messages that failed to process.
      • D. Subscribe the processing application to an Amazon Simple Notification Service (Amazon SNS) topic to receive notifications to process. Integrate the sender application to write to the SNS topic.

      Domain: Design Resilient Architectures

      Correct answer: C

      • A. Wrong — self-hosting Redis on a single EC2 instance means managing the server and durability yourself, with no built-in dead-letter/retry handling for failed messages — high operational overhead and a single point of failure.
      • B. Wrong — Kinesis Data Streams is built for high-throughput streaming/real-time analytics; a simple ~1,000-messages-per-hour point-to-point workload doesn't need Kinesis's added complexity (shards, KCL) over a simple queue.
      • C. Correct — SQS is purpose-built for this decoupled point-to-point messaging pattern, easily supports retention windows up to 2 days (well within its 14-day maximum), and a dead-letter queue automatically isolates messages that fail to process so they don't block or impact the remaining messages — all with minimal setup.
      • D. Wrong — SNS is a pub/sub notification service without a queue's built-in retention-for-processing and redrive semantics that SQS plus a DLQ provides for this "retain failed messages so they don't impact the rest" requirement.

      Question 60

      A company runs an environment where data is stored in an Amazon S3 bucket. The objects are accessed frequently throughout the day. The company has strict data encryption requirements for data that is stored in the S3 bucket. The company currently uses AWS Key Management Service (AWS KMS) for encryption. The company wants to optimize costs associated with encrypting S3 objects without making additional calls to AWS KMS. Which solution will meet these requirements?

      • A. Use server-side encryption with Amazon S3 managed keys (SSE-S3).
      • B. Use an S3 Bucket Key for server-side encryption with AWS KMS keys (SSE-KMS) on the new objects.
      • C. Use client-side encryption with AWS KMS customer managed keys.
      • D. Use server-side encryption with customer-provided keys (SSE-C) stored in AWS KMS.

      Domain: Design Cost-Optimized Architectures

      Correct answer: B

      • A. Wrong — SSE-S3 uses Amazon-managed keys and doesn't use AWS KMS at all, so it drops the company's stated use of AWS KMS entirely rather than optimizing it.
      • B. Correct — an S3 Bucket Key still uses SSE-KMS but has S3 generate a short-lived bucket-level key from the customer's KMS key, then uses that to create per-object data keys locally — cutting KMS request volume by up to 99%, directly optimizing cost without giving up KMS-backed encryption.
      • C. Wrong — client-side encryption shifts key-management and encryption work into the application itself, adding operational complexity, and doesn't inherently reduce KMS call volume the way a Bucket Key does.
      • D. Wrong — SSE-C requires the client to supply its own key on every request rather than using AWS KMS as the source of key material for the encrypt operation, and doesn't address the stated call-volume/cost goal.

      Question 61

      A company's web application is running on Amazon EC2 instances behind an Application Load Balancer. The company recently changed its policy, which now requires the application to be accessed from one specific country only. Which configuration will meet this requirement?

      • A. Configure the security group for the EC2 instances.
      • B. Configure the security group on the Application Load Balancer.
      • C. Configure AWS WAF on the Application Load Balancer in a VPC.
      • D. Configure the network ACL for the subnet that contains the EC2 instances.

      Domain: Design Secure Architectures

      Correct answer: C

      • A. Wrong — security groups filter by IP/port/protocol, not by the geographic origin of a request; they can't implement country-based restriction.
      • B. Wrong — same limitation as A: a security group has no concept of "country," only IP ranges, ports, and protocols.
      • C. Correct — AWS WAF supports geographic match (geo-match) rules that allow or block requests based on the country a request originates from, attached directly to the ALB to enforce this at the application's edge.
      • D. Wrong — network ACLs filter by IP CIDR ranges and ports only; they have no built-in geographic-restriction capability and would require manually maintaining every IP range in and out of the target country.

      Question 62

      A company needs to store data in Amazon S3 and must prevent the data from being changed. The company wants new objects that are uploaded to Amazon S3 to remain unchangeable for a nonspecific amount of time until the company decides to modify the objects. Only specific users in the company's AWS account can have the ability to delete the objects. What should a solutions architect do to meet these requirements?

      • A. Create an S3 Glacier vault. Apply a write-once, read-many (WORM) vault lock policy to the objects.
      • B. Create an S3 bucket with S3 Object Lock enabled. Enable versioning. Set a retention period of 100 years. Use governance mode as the S3 bucket's default retention mode for new objects.
      • C. Create an S3 bucket. Use AWS CloudTrail to track any S3 API events that modify the objects. Upon notification, restore the modified objects from any backup versions that the company has.
      • D. Create an S3 bucket with S3 Object Lock enabled. Enable versioning. Add a legal hold to the objects. Add the s3:PutObjectLegalHold permission to the IAM policies of users who need to delete the objects.

      Domain: Design Secure Architectures

      Correct answer: D

      • A. Wrong — Glacier vault WORM lock is a separate legacy mechanism from S3 Object Lock on standard buckets, and doesn't match "nonspecific amount of time until the company decides" — that calls for an open-ended hold, not a vault's fixed policy.
      • B. Wrong — a defined retention period (100 years) is a specific duration, contradicting "nonspecific amount of time"; a legal hold, not a retention period, is the feature designed for this open-ended, manually-lifted use case.
      • C. Wrong — tracking modification events and restoring from backups after the fact is reactive, not preventive; it doesn't actually stop the data from being changed as required.
      • D. Correct — a legal hold under S3 Object Lock keeps an object protected indefinitely (a "nonspecific amount of time") until explicitly removed, and granting the s3:PutObjectLegalHold permission (needed to lift the hold before deletion) only to specific users' IAM policies restricts who can ultimately delete the objects.

      Question 63

      A company is running a publicly accessible serverless application that uses Amazon API Gateway and AWS Lambda. The application's traffic recently spiked due to fraudulent requests from botnets. Which steps should a solutions architect take to block requests from unauthorized users? (Choose two.)

      • A. Create a usage plan with an API key that is shared with genuine users only.
      • B. Integrate logic within the Lambda function to ignore the requests from fraudulent IP addresses.
      • C. Implement an AWS WAF rule to target malicious requests and trigger actions to filter them out.
      • D. Convert the existing public API to a private API. Update the DNS records to redirect users to the new API endpoint.
      • E. Create an IAM role for each user attempting to access the API. A user will assume the role when making the API call.

      Domain: Design Secure Architectures

      Correct answer: A, C

      • A. Correct — a usage plan with an API key issued only to genuine users lets API Gateway distinguish and admit legitimate callers, throttling or rejecting requests without a valid key.
      • B. Wrong — hardcoding IP-blocking logic inside the Lambda function still lets every fraudulent request reach and invoke Lambda (incurring cost/load) before being rejected, and maintaining an IP blocklist doesn't scale against a botnet's constantly-changing IPs.
      • C. Correct — an AWS WAF rule (such as a rate-based or bot-control rule) attached to the API detects and filters out malicious/bot request patterns before they reach the backend integration.
      • D. Wrong — converting to a private API removes public accessibility entirely, which breaks the requirement that this remains "a publicly accessible serverless application" for genuine users.
      • E. Wrong — creating an individual IAM role per external user of a public API isn't a practical or scalable pattern, and doesn't specifically filter fraudulent botnet traffic.

      Question 64

      A company uses a three-tier web application to provide training to new employees. The application is accessed for only 12 hours every day. The company is using an Amazon RDS for MySQL DB instance to store information and wants to minimize costs. What should a solutions architect do to meet these requirements?

      • A. Configure an IAM policy for AWS Systems Manager Session Manager. Create an IAM role for the policy. Update the trust relationship of the role. Set up automatic start and stop for the DB instance.
      • B. Create an Amazon ElastiCache for Redis cache cluster that gives users the ability to access the data from the cache when the DB instance is stopped. Invalidate the cache after the DB instance is started.
      • C. Launch an Amazon EC2 instance. Create an IAM role that grants access to Amazon RDS. Attach the role to the EC2 instance. Configure a cron job to start and stop the EC2 instance on the desired schedule.
      • D. Create AWS Lambda functions to start and stop the DB instance. Create Amazon EventBridge (Amazon CloudWatch Events) scheduled rules to invoke the Lambda functions. Configure the Lambda functions as event targets for the rules.

      Domain: Design Cost-Optimized Architectures

      Correct answer: D

      • A. Wrong — Session Manager provides secure shell/console access to instances; it has no role in scheduling an RDS DB instance's start/stop, and RDS isn't managed via an SSM trust-relationship role this way.
      • B. Wrong — serving stale cached data while the database is stopped doesn't actually stop the database from running on the needed schedule, and adds cache-invalidation complexity that doesn't address the real cost goal.
      • C. Wrong — this automates an EC2 instance's schedule, not the RDS DB instance itself; the requirement is specifically to minimize the cost of the RDS DB instance.
      • D. Correct — Lambda functions calling the RDS start/stop API, triggered by EventBridge scheduled rules (start at the beginning of the 12-hour window, stop at the end), is a fully managed, serverless way to run the DB instance only when needed — minimizing cost with minimal operational effort.

      Question 65

      A company runs an application in a private subnet behind an Application Load Balancer (ALB) in a VPC. The VPC has a NAT gateway and an internet gateway. The application calls the Amazon S3 API to store objects. According to the company's security policy, traffic from the application must not travel across the internet. Which solution will meet these requirements MOST cost-effectively?

      • A. Configure an S3 interface endpoint. Create a security group that allows outbound traffic to Amazon S3.
      • B. Configure an S3 gateway endpoint. Update the VPC route table to use the endpoint.
      • C. Configure an S3 bucket policy to allow traffic from the Elastic IP address that is assigned to the NAT gateway.
      • D. Create a second NAT gateway in the same subnet where the legacy application is deployed. Update the VPC route table to use the second NAT gateway.

      Domain: Design Cost-Optimized Architectures

      Correct answer: B

      • A. Wrong — an interface endpoint works, but it incurs hourly and per-GB charges; a security group alone also doesn't route traffic to it — a gateway endpoint is both simpler and free for S3 access from within the VPC.
      • B. Correct — an S3 gateway endpoint is free to use, and once added as a target in the VPC's route table, routes all S3-bound traffic from the private subnet over AWS's private network instead of the internet — meeting the requirement at no additional cost.
      • C. Wrong — traffic through the NAT gateway to reach S3 still exits toward the internet-facing side of the service, and the NAT gateway incurs hourly and data-processing charges — neither meeting "must not travel across the internet" nor being the most cost-effective choice.
      • D. Wrong — adding a second NAT gateway increases cost (another hourly charge plus data processing fees) and still routes S3 traffic out through a NAT gateway rather than keeping it off the internet path entirely.

      Question 66

      A company uses a popular content management system (CMS) for its corporate website. However, the required patching and maintenance are burdensome. The company is redesigning its website and wants a new solution. The website will be updated four times a year and does not need to have any dynamic content available. The solution must provide high scalability and enhanced security. Which combination of changes will meet these requirements with the LEAST operational overhead? (Choose two.)

      • A. Configure Amazon CloudFront in front of the website to use HTTPS functionality.
      • B. Deploy an AWS WAF web ACL in front of the website to provide HTTPS functionality.
      • C. Create and deploy an AWS Lambda function to manage and serve the website content.
      • D. Create the new website and an Amazon S3 bucket. Deploy the website on the S3 bucket with static website hosting enabled.
      • E. Create the new website. Deploy the website by using an Auto Scaling group of Amazon EC2 instances behind an Application Load Balancer.

      Domain: Design High-Performing Architectures

      Correct answer: A, D

      • A. Correct — CloudFront in front of an S3-hosted static site provides HTTPS support (S3 static website hosting endpoints don't support HTTPS natively) plus global caching and an added security layer, as a fully managed service.
      • B. Wrong — AWS WAF filters malicious web traffic; it does not provide HTTPS/TLS termination functionality on its own.
      • C. Wrong — writing and deploying a custom Lambda function to serve website content reintroduces development and operational effort a purely static site (needing zero dynamic content) doesn't require.
      • D. Correct — since the site needs no dynamic content and updates only four times a year, S3 static website hosting is the simplest, most scalable, lowest-operational-overhead way to serve it — no servers, patches, or CMS maintenance at all.
      • E. Wrong — deploying an Auto Scaling group of EC2 instances behind an ALB to serve genuinely static content is significantly more operational overhead (patching, scaling policies, AMI management) than hosting the files in S3.

      Question 67

      A company wants to run applications in containers in the AWS Cloud. These applications are stateless and can tolerate disruptions within the underlying infrastructure. The company needs a solution that minimizes cost and operational overhead. What should a solutions architect do to meet these requirements?

      • A. Use Spot Instances in an Amazon EC2 Auto Scaling group to run the application containers.
      • B. Use Spot Instances in an Amazon Elastic Kubernetes Service (Amazon EKS) managed node group.
      • C. Use On-Demand Instances in an Amazon EC2 Auto Scaling group to run the application containers.
      • D. Use On-Demand Instances in an Amazon Elastic Kubernetes Service (Amazon EKS) managed node group.

      Domain: Design Cost-Optimized Architectures

      Correct answer: B

      • A. Wrong — running containers directly on plain EC2 Spot Instances in an Auto Scaling group still requires the company to manage the EC2 fleet, container placement, and orchestration itself — more operational overhead than a managed orchestrator.
      • B. Correct — EKS with a managed node group running Spot Instances gives Kubernetes-based container orchestration (with AWS managing the node group lifecycle) while Spot Instances minimize compute cost, a strong fit since the stateless, disruption-tolerant application can absorb Spot interruptions.
      • C. Wrong — On-Demand pricing costs more than Spot for a workload explicitly described as disruption-tolerant, leaving savings on the table with no added benefit.
      • D. Wrong — same cost issue as C: On-Demand isn't the most cost-effective choice when the workload can tolerate the interruptions Spot Instances introduce.

      Question 68

      A company is implementing a new business application. The application runs on two Amazon EC2 instances and uses an Amazon S3 bucket for document storage. A solutions architect needs to ensure that the EC2 instances can access the S3 bucket. What should the solutions architect do to meet this requirement?

      • A. Create an IAM role that grants access to the S3 bucket. Attach the role to the EC2 instances.
      • B. Create an IAM policy that grants access to the S3 bucket. Attach the policy to the EC2 instances.
      • C. Create an IAM group that grants access to the S3 bucket. Attach the group to the EC2 instances.
      • D. Create an IAM user that grants access to the S3 bucket. Attach the user account to the EC2 instances.

      Domain: Design Secure Architectures

      Correct answer: A

      • A. Correct — an IAM role attached to the EC2 instances lets the application use temporary, automatically-rotated credentials scoped by the role's policy to access the S3 bucket — the AWS-recommended way for EC2 workloads to access other AWS services.
      • B. Wrong — a policy on its own isn't "attached to" EC2 instances directly; policies must be attached to an IAM identity (user, group, or role), and a role is the correct identity type for EC2 instances.
      • C. Wrong — IAM groups organize IAM users and let policies be attached to multiple users at once; groups cannot be attached to EC2 instances or assumed by AWS resources.
      • D. Wrong — IAM users represent long-term credentials meant for people and cannot be "attached" to an EC2 instance; embedding a user's static access keys on an instance is also a well-known anti-pattern versus a role's temporary credentials.

      Question 69

      A company's production environment consists of Amazon EC2 On-Demand Instances that run constantly between Monday and Saturday. The instances must run for only 12 hours on Sunday and cannot tolerate interruptions. The company wants to cost-optimize the production environment. Which solution will meet these requirements MOST cost-effectively?

      • A. Purchase Scheduled Reserved Instances for the EC2 instances that run for only 12 hours on Sunday. Purchase Standard Reserved Instances for the EC2 instances that run constantly between Monday and Saturday.
      • B. Purchase Convertible Reserved Instances for the EC2 instances that run for only 12 hours on Sunday. Purchase Standard Reserved Instances for the EC2 instances that run constantly between Monday and Saturday.
      • C. Use Spot Instances for the EC2 instances that run for only 12 hours on Sunday. Purchase Standard Reserved Instances for the EC2 instances that run constantly between Monday and Saturday.
      • D. Use Spot Instances for the EC2 instances that run for only 12 hours on Sunday. Purchase Convertible Reserved Instances for the EC2 instances that run constantly between Monday and Saturday.

      Domain: Design Cost-Optimized Architectures

      Correct answer: A

      ⚠️ Current-state note: AWS has discontinued Scheduled Reserved Instances for new purchases — they no longer appear in the EC2 console or current AWS documentation. This question reflects earlier SAA-C03 exam content built around a real purchasing option that existed at the time. The underlying reasoning below (matching each workload's interruption-tolerance and schedule to the right purchase type) is still exactly how the exam tests this topic, and is still tested as of this writing — just be aware that "Scheduled RI" itself can no longer actually be purchased on AWS today.

      • A. Correct (per the original exam design) — Scheduled Reserved Instances were built for a recurring, predictable partial-day schedule like the 12-hour Sunday window, while Standard Reserved Instances suit the constantly-running, interruption-intolerant Monday-through-Saturday capacity (which also rules out Spot).
      • B. Wrong — Convertible Reserved Instances allow changing instance attributes over the term but are billed for continuous, full-time usage, not a fit for capacity needed only 12 hours on Sunday.
      • C. Wrong — Spot Instances can be interrupted at any time, directly conflicting with "cannot tolerate interruptions."
      • D. Wrong — same interruption-tolerance conflict as C for the Sunday workload, and Convertible RIs cost more than Standard RIs for Monday-Saturday when the flexibility to change instance family isn't a stated requirement.

      Question 70

      A company needs to save the results from a medical trial to an Amazon S3 repository. The repository must allow a few scientists to add new files and must restrict all other users to read-only access. No users can have the ability to modify or delete any files in the repository. The company must keep every file in the repository for a minimum of 1 year after its creation date. Which solution will meet these requirements?

      • A. Use S3 Object Lock in governance mode with a legal hold of 1 year.
      • B. Use S3 Object Lock in compliance mode with a retention period of 365 days.
      • C. Use an IAM role to restrict all users from deleting or changing objects in the S3 bucket. Use an S3 bucket policy to only allow the IAM role.
      • D. Configure the S3 bucket to invoke an AWS Lambda function every time an object is added. Configure the function to track the hash of the saved object so that modified objects can be marked accordingly.

      Domain: Design Secure Architectures

      Correct answer: B

      • A. Wrong — a legal hold has no fixed duration and isn't paired with a "retention period," and governance mode can be overridden by users granted the s3:BypassGovernanceRetention permission, so it doesn't guarantee "no users" can delete or modify objects.
      • B. Correct — S3 Object Lock in compliance mode enforces the retention period (365 days ≈ 1 year) so that absolutely no user, including the AWS account root user, can delete or overwrite protected objects until the retention period expires — exactly matching "no users can have the ability to modify or delete."
      • C. Wrong — restricting access via IAM role and bucket policy only controls who is allowed to call delete/modify APIs; it doesn't provide the immutability guarantee of Object Lock, and a sufficiently privileged administrator could still change the policy to permit deletion.
      • D. Wrong — tracking hashes and flagging modified objects after the fact is a detective control, not preventive; it doesn't stop a file from being changed or deleted at all, which the requirement explicitly calls for.

      Question 71

      A company hosts a website analytics application on a single Amazon EC2 On-Demand Instance. The analytics application is highly resilient and is designed to run in stateless mode. The company notices that the application is showing signs of performance degradation during busy times and is presenting 5xx errors. The company needs to make the application scale seamlessly. Which solution will meet these requirements MOST cost-effectively?

      • A. Create an Amazon Machine Image (AMI) of the web application. Use the AMI to launch a second EC2 On-Demand Instance. Use an Application Load Balancer to distribute the load across the two EC2 instances.
      • B. Create an Amazon Machine Image (AMI) of the web application. Use the AMI to launch a second EC2 On-Demand Instance. Use Amazon Route 53 weighted routing to distribute the load across the two EC2 instances.
      • C. Create an AWS Lambda function to stop the EC2 instance and change the instance type. Create an Amazon CloudWatch alarm to invoke the Lambda function when CPU utilization is more than 75%.
      • D. Create an Amazon Machine Image (AMI) of the web application. Apply the AMI to a launch template. Create an Auto Scaling group that includes the launch template. Configure the launch template to use a Spot Fleet. Attach an Application Load Balancer to the Auto Scaling group.

      Domain: Design Cost-Optimized Architectures

      Correct answer: D

      • A. Wrong — manually launching a fixed second On-Demand instance behind an ALB caps capacity at exactly two instances; it doesn't scale automatically ("seamlessly") with load.
      • B. Wrong — Route 53 weighted routing splits traffic by a fixed percentage between two static instances; it doesn't add or remove capacity dynamically as load changes.
      • C. Wrong — stopping the instance and changing its type via Lambda causes an outage during every resize and only provides vertical scaling, not the seamless elastic scaling a stateless, resilient application is well suited to use with Auto Scaling.
      • D. Correct — applying the AMI to a launch template inside an Auto Scaling group gives seamless, automatic horizontal scaling; since the application is explicitly stateless and highly resilient to disruption, running it on a Spot Fleet within that group minimizes cost, with an ALB distributing traffic across all scaled instances.

      Question 72

      A company is developing a file-sharing application that will use an Amazon S3 bucket for storage. The company wants to serve all the files through an Amazon CloudFront distribution. The company does not want the files to be accessible through direct navigation to the S3 URL. What should a solutions architect do to meet these requirements?

      • A. Write individual policies for each S3 bucket to grant read permission for only CloudFront access.
      • B. Create an IAM user. Grant the user read permission to objects in the S3 bucket. Assign the user to CloudFront.
      • C. Write an S3 bucket policy that assigns the CloudFront distribution ID as the Principal and assigns the target S3 bucket as the Amazon Resource Name (ARN).
      • D. Create an origin access identity (OAI). Assign the OAI to the CloudFront distribution. Configure the S3 bucket permissions so that only the OAI has read permission.

      Domain: Design Secure Architectures

      Correct answer: D

      • A. Wrong — a bucket policy granting broad "CloudFront access" doesn't by itself prevent direct navigation to the S3 URL unless it's scoped to a specific CloudFront identity/principal.
      • B. Wrong — creating an IAM user and "assigning" it to CloudFront isn't how CloudFront authenticates to a private S3 origin, and it doesn't block direct S3 URL access either.
      • C. Wrong — a raw CloudFront distribution ID isn't a valid IAM/S3 policy Principal value on its own; the actual mechanism for scoping a bucket policy to a specific distribution is via an origin access identity/control, not the bare distribution ID.
      • D. Correct — creating an OAI, assigning it to the CloudFront distribution, and restricting the S3 bucket's permissions so only that OAI can read objects ensures the bucket is reachable only through CloudFront — direct navigation to the S3 URL is denied.

      Question 73

      Organizers for a global event want to put daily reports online as static HTML pages. The pages are expected to generate millions of views from users around the world. The files are stored in an Amazon S3 bucket. A solutions architect has been asked to design an efficient and effective solution. Which action should the solutions architect take to accomplish this?

      • A. Generate presigned URLs for the files.
      • B. Use cross-Region replication to all Regions.
      • C. Use the geoproximity feature of Amazon Route 53.
      • D. Use Amazon CloudFront with the S3 bucket as its origin.

      Domain: Design High-Performing Architectures

      Correct answer: D

      • A. Wrong — presigned URLs grant temporary, individual access to specific objects; they don't help efficiently serve the same static content to millions of viewers worldwide.
      • B. Wrong — replicating the bucket to every Region is costly and operationally heavy, and still requires a mechanism to route each user to their nearest replica — it doesn't solve global delivery by itself.
      • C. Wrong — Route 53 geoproximity influences DNS routing to different endpoints; it doesn't cache or accelerate delivery of the actual file content the way a CDN does.
      • D. Correct — CloudFront in front of the S3 bucket caches the static HTML content at edge locations worldwide, efficiently serving millions of views with low latency regardless of viewer location, using S3 as a single simple origin.

      Question 74

      A company wants to migrate an on-premises data center to AWS. The data center hosts an SFTP server that stores its data on an NFS-based file system. The server holds 200 GB of data that needs to be transferred. The server must be hosted on an Amazon EC2 instance that uses an Amazon Elastic File System (Amazon EFS) file system. Which combination of steps should a solutions architect take to automate this task? (Choose two.)

      • A. Launch the EC2 instance into the same Availability Zone as the EFS file system.
      • B. Install an AWS DataSync agent in the on-premises data center.
      • C. Create a secondary Amazon Elastic Block Store (Amazon EBS) volume on the EC2 instance for the data.
      • D. Manually use an operating system copy command to push the data to the EC2 instance.
      • E. Use AWS DataSync to create a suitable location configuration for the on-premises SFTP server.

      Domain: Design Resilient Architectures

      Correct answer: B, E

      • A. Wrong — launching the EC2 instance in the same AZ as the EFS file system affects mount latency, but does nothing to automate the actual transfer of the 200 GB of data from on-premises into that EFS file system.
      • B. Correct — a DataSync agent must be installed in the on-premises environment (as a VM) so DataSync can reach and read from the on-premises NFS export that holds the SFTP server's data.
      • C. Wrong — creating a secondary EBS volume doesn't automate moving data from on-premises into AWS, and EBS volumes aren't shared network file systems like EFS, so it doesn't produce the required EFS-backed result either.
      • D. Wrong — a manual OS copy command is explicitly the opposite of "automate this task," with no built-in retry, verification, or scheduling.
      • E. Correct — DataSync connects to this server's actual data through the NFS export it's built on (DataSync's real source location types are NFS/SMB/object storage/HDFS — there isn't a distinct "SFTP" location type, but the question's point is configuring DataSync against this on-premises server's file share), letting DataSync automatically and efficiently transfer the 200 GB into the EFS destination.

      Question 75

      A company hosts a containerized web application on a fleet of on-premises servers that process incoming requests. The number of requests is growing quickly. The on-premises servers cannot handle the increased number of requests. The company wants to move the application to AWS with minimum code changes and minimum development effort. Which solution will meet these requirements with the LEAST operational overhead?

      • A. Use AWS Fargate on Amazon Elastic Container Service (Amazon ECS) to run the containerized web application with Service Auto Scaling. Use an Application Load Balancer to distribute the incoming requests.
      • B. Use two Amazon EC2 instances to host the containerized web application. Use an Application Load Balancer to distribute the incoming requests.
      • C. Use AWS Lambda with a new code that uses one of the supported languages. Create multiple Lambda functions to support the load. Use Amazon API Gateway as an entry point to the Lambda functions.
      • D. Use a high performance computing (HPC) solution such as AWS ParallelCluster to establish an HPC cluster that can process the incoming requests at the appropriate scale.

      Domain: Design High-Performing Architectures

      Correct answer: A

      • A. Correct — Fargate on ECS runs the existing containerized application with no code changes and no servers to manage, Service Auto Scaling automatically scales running tasks with demand, and an ALB distributes requests — meeting "minimum code changes," "minimum development effort," and "least operational overhead" together.
      • B. Wrong — two fixed EC2 instances still require managing the underlying servers/OS and won't automatically scale as request volume keeps growing.
      • C. Wrong — rewriting the application as new Lambda functions in a supported language is exactly the kind of significant code change and development effort the company wants to avoid, when the app is already containerized and could run as-is on a container platform.
      • D. Wrong — AWS ParallelCluster is designed for HPC/scientific computing workloads (tightly coupled parallel jobs), not for scaling a containerized web application handling growing request volume — the wrong tool for this workload entirely.
